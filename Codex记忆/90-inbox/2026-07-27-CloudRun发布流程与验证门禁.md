# CloudRun 发布流程与验证门禁

CloudRun 必须从仓库根目录发布，并在 CLI 提交成功后继续验证新路由和实际流量版本；“代码已提交”不等于“新镜像已生效”。

## 可复用流程

1. 从仓库根目录构建容器；根 `Dockerfile` 会复制 `apps/platform-api/app` 和根目录 `migrations`。
2. 前端使用 staging 模式构建，确保 `/ops-platform/` 基础路径和 CloudRun API 地址正确。
3. CloudRun CLI 返回提交成功后继续等待构建和流量切换。
4. 使用健康接口确认 HTTP 200，并用本次新增路由确认不能再返回 404；未登录路由返回 401 代表路由已存在且鉴权生效。
5. 再部署静态目录并用带缓存破坏参数的页面或资源地址检查 CDN 新版本。

## 踩坑

- 从 `apps/platform-api` 子目录发布会缺少仓库根 Docker 构建上下文和迁移目录，可能导致旧镜像继续提供服务。
- `tcb cloudrun list` 的服务状态为 `normal` 不能单独证明最新提交已切换。
- 新增数据库字段必须同时提供 MySQL 与 SQLite 迁移，并由新容器启动时执行。

## 边界

- 发布脚本和说明不得包含数据库密码、管理员密码、令牌或字段加密密钥。
- 回滚应用版本时，新增的可空数据库列可以保留，不应通过破坏性迁移删除。
