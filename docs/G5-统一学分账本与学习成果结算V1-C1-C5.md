# G5｜统一学分账本与学习成果结算 V1（C1-C5）

## 本阶段交付

- 新增 `learning_credit_entries` 追加式学分账本，包含来源、组织、学习周期、规则版本快照、幂等键、状态和冲销关联。
- 新增通用 `learning_credit_rule_versions` / `learning_credit_rules`，支持 `DAILY_ONCE`、`MONTHLY_CAP`、`CYCLE_ONCE`、`COURSE_COMPLETION`、`EVENT_ONCE`、`MANUAL_ADJUSTMENT` 六种模型。
- 班级学习绑定保存对应通用学分规则版本；课程结算同时校验该计划对应的课程积分版本必须为 `PUBLISHED`。
- 小组学习会课程新增逐人 `study_meeting_course_completions` 完成事实。学习会提交会由后端重新校验参加人员与逐人课程完成事实；名单修正新增人员默认为 `UNCONFIRMED`。
- 新增学习会单场和批量 DRY-RUN API。DRY-RUN 只计算，不写入账本、不建立批量导入记录。
- 正式结算和冲销 API 受 `LEARNING_CREDIT_SETTLEMENT_ENABLED`、部署只读门禁和权限三重控制，默认关闭。

## 规则边界

- 小组学习会基础分按 `member_id + learning_cycle_id` 幂等，周期内本组/跨组重复参加仍只计一次。
- 课程学分按 `member_id + course_key + class_learning_binding_id` 幂等，使用学习会保存的课程规则快照，不读取新的全局分值重算。
- 课程无已确认总部分值时只保留学习事实，DRY-RUN 标记为 `BLOCKED`/`NO_CREDIT`，不猜测赋分。
- 规则版本未发布时可以 DRY-RUN，不能正式 POST。

## API

- `POST /api/v1/learning-credits/dry-run/study-meetings/{session_id}`
- `POST /api/v1/learning-credits/dry-run/study-meetings?class_org_unit_id=...&learning_cycle_id=...&limit=30`
- `GET /api/v1/learning-credits/entries`
- `GET /api/v1/learning-credits/members/{member_id}/summary`
- `POST /api/v1/learning-credits/study-meetings/{session_id}/settle`（开关关闭时不可用）
- `POST /api/v1/learning-credits/entries/{entry_id}/reverse`（追加冲销，不覆盖原记录）
- `POST /api/v1/study-meetings/records/{session_id}/course-completions`

## 数据库迁移

- 前向：`migrations/sqlite/0046_learning_credit_ledger.sql`、`migrations/mysql/0046_learning_credit_ledger.sql`
- 回滚：对应 `migrations/rollback/{sqlite,mysql}/0046_learning_credit_ledger.down.sql`
- 回滚脚本发现已有账本或课程完成事实时拒绝有损降级。
