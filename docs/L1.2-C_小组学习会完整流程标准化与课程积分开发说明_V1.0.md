# L1.2-C 小组学习会完整流程标准化与课程积分

> 基线：`c4feb59` 之后的当前 `main`（含 2026 CONFIRMED 审核门禁与只读调整工作区）
> 候选版本：`2026.1`
> 状态：代码与审核工件已准备；候选流程仍需业务复核，未导入数据库、未发布生产

## 1. 目标与冻结边界

L1.2-C 为 L2 统一二维码之前的学习会流程底座。它把 2026 标准计划中的
`GROUP_MEETING` 源片段整理为“完整流程 → 有序步骤 → 课程二维码/积分节点”，同时保留
2026 CONFIRMED 版本不可覆盖的发布门禁。

已冻结的业务规则：

1. `E:\班级运营资料\6.班会+小组会学习会流程` 是完整流程的权威源；2026 目录纳入白名单，历史版、非流程辅助文件与草稿不进入运行源。
2. 解析从第一个“小组学习会”标记开始，到第一个“空巴”（兼容“空吧”）结束；空巴之后的班会二维码和内容排除。
3. 小组会基础出席分为 4 分/人/学习周期，周期内最多一次；`GROUP_MEETING` 流程步骤不携带任务级学分。
4. 课程积分只配置在课程二维码节点。无法由正式流程文字确认的二维码保持 `QR_REVIEW_REQUIRED`、`credit_points = null`，禁止猜测。
5. 第一学年 9 门课程积分以 `course-credit-rules-2026.json` 为唯一运行配置：20、20、20、20、40、40、20、30、15；其中“京瓷如何制定年度计划”为 30 分，“年度计划与月度核算管理”为 15 分。
6. 所有调整只生成 `2026.1` DRAFT 候选版本，不覆盖 `2026 CONFIRMED`，也不写数据库。

## 3. C1：完整流程解析

脚本：`scripts/parse_group_meeting_flows.py`

产物：`data/learning-plans/group-meeting-flows-2026.1.json`

解析结果：

| 项目 | 结果 |
| --- | ---: |
| 源流程数 | 78 |
| 成功识别首个空巴 | 78/78 |
| 课程二维码节点 | 32 |
| 课程待人工复核 | 15 |
| 空巴后二维码 | 0（已排除） |

每个流程保留源文件相对路径、源 SHA-256、步骤号、段落位置、二维码关系、课程映射状态和质量字段。
二维码图片不做 OCR 或猜测；只有步骤正文明确出现课程别名时才映射课程，否则保留人工复核状态。

## 4. C2：课程积分规则

产物：`data/learning-plans/course-credit-rules-2026.json`

规则文件包含：

- 9 条第一学年课程规则及别名；
- 小组会周期级 4 分规则快照；
- 未知课程的 `null / QR_REVIEW_REQUIRED` 策略；
- 规则文档 SHA-256。

解析器从该 JSON 读取别名与分值，不再以 Python 常量作为业务真相。

## 5. C3：周期—流程映射

脚本：`scripts/map_cycle_group_meeting_flows.py`

产物：`data/learning-plans/cycle-flow-mapping-2026.1.json`

映射主键是：

```text
计划版本 + 开班轨道 + 学习学年 + 学习周期
```

不以自然月作为主键。当前 144 个周期中 129 个唯一映射，5 个源文件冲突，10 个源文件缺失；冲突和缺失均保留为 `MAPPING_CONFLICT` / `MAPPING_MISSING`，在业务复核前不得自动选取。
