# V1.2-B2.1.2 学习会参加人员运营修正

## 范围与入口

开发基线为 `efb9b99`（B2.1.1 已提交，CI 33086968453 成功）。
本轮只实现已提交学习会的人员事实修正，不进入 C 审核、D 积分，不进行生产变更。

本地管理端：`http://127.0.0.1:8848/#/operations/study-meetings`；本地 API：`http://127.0.0.1:8000`。
详情 → **修正参加人员** → 勾选本组 / 添加同班其他小组学长 → 保存。
实时显示总人数、本组和跨组人数；备注选填，不输入 member_id。
已不符合选择条件的原参加人员单独提示，必须由运营核对，不静默删除。

## API 与边界

- `GET /api/v1/study-meetings/records/{session_id}/attendee-options`
- `PATCH /api/v1/study-meetings/records/{session_id}/attendees`

```json
{"member_ids":[1,2],"expected_member_ids":[1,3],"note":"可选修正备注"}
```

独立权限 `study_meetings:attendees_edit`，种子仅授予 system_admin / operations_admin。
不借用 `plans:read` 写入，不接受微信 member session 作为管理账号。
服务端再次校验组织授权、SUBMITTED 状态和正式 ACTIVE 名单；只允许同班且当前小组归属唯一的学员。
跨班、离册、过期/多重归属、重复编号、空名单、伪造 attendance_type 全部拒绝。
HOME_GROUP / CROSS_GROUP 按有效 `member_org_relations` 及组织 ID 推导。
组长/辅导员提交后没有人员修改接口。

会话行锁序列化修改，`expected_member_ids` 对比当前名单；过期修改提示“参加人员已被其他人修改，请刷新后重试”。
保留未改动参加行的原添加人及时间；只删除误选、插入补录、必要时更新本场分类。
不修改正式组织关系、合影、课程、学习周期或积分。

## 审计与 0042

`study_meeting.attendees_correct` 与修改处于同一事务：

- before/after 分别包含原本组、跨组名单及修正后名单；
- `actor_user_id`、`created_at`、可选备注（既有 `purpose` 字段）；
- 审计失败时整次修正回滚。

新增 `0042_study_meeting_attendee_correction`，提供 SQLite / MySQL 前向及回滚脚本。
旧结构的 `added_by_member_id NOT NULL` 无法真实表达运营补录，因此改为可空并增加 `added_by_user_id`。
数据库 XOR 约束保证添加人是学员或运营账号二者之一；不把运营行为伪装成组长提交。
旧行、ID、原添加人、时间和索引保留，另种子独立权限。

回滚保护：已有运营补录行时拒绝降级，禁止伪造添加人或删除业务事实以强行回滚。
无运营补录行时可恢复旧结构。MySQL DDL 非整批原子，执行失败须核对实际结构，不能盲目重跑。
本轮仅升级独立本地验收数据库；备份为 `.codex-tmp/b212-before-20260827232811.db`，0042 前后计数一致、外键检查通过。
