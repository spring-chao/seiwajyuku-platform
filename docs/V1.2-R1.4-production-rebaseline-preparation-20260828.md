生产候选必须由上述 clean main 构建，使用不可变镜像 digest。`image_tag` 可以用于检索，但最终发布和 manifest 必须记录：


## 9. 停止线与回滚

任一条件成立即停止，不自行降低门槛：

- 最新快照未完成、不可用、PITR 不可恢复或 backup ID 无法记录；
- 工作区脏、HEAD 与 origin/main/CI 不一致、migration manifest 哈希不一致；
- 镜像没有 digest，或 build-info 与 manifest 不一致；
- CloudBase 无法保留 revision 188，或流量状态不可确认；
- 健康检查、登录鉴权、V1.1.1 入口、管理端 build-info 或 5xx 指标异常；
- 发现意外迁移、权限、Flag、Cron、组织关系、身份、积分或业务数据变化；
- CloudBase 当前能力要求新增付费资源而未获得单独批准。

### 应用回滚

1. 立即停止继续升流量；
2. canary 仍在运行时，按 CLI 实际帮助执行：

   ```powershell
   tcb cloudrun traffic rollback --serviceName seiwajyuku-platform-api --json
   ```

   若当前 CLI/账号不支持该语法，使用已批准的控制台或 API 把流量明确切回 revision 188；不得猜测或盲切；
3. 将 V1.2 flags 保持关闭，停止新增入口；
4. 重新检查 `__tcb_probe__`、`health/live`、`health`、`api/v1/health` 和 `/api/v1/system/build-info`；
5. 保留新增兼容数据库结构和审计记录，不默认执行 down migration；
6. 保存异常、操作者、时间、流量、revision、digest、备份 ID 和最终健康结果。

数据库 DDL 可能隐式提交。只有在确认结构本身造成问题、没有新数据依赖、已有可恢复快照并取得单独批准时，才讨论结构回滚或 PITR；不得机械删除新增字段/表。
