## 2. 开始前检查（业务人员不自行修复）

- [ ] 发布负责人确认所有迁移已经逐项成功，生产 `schema_migrations` 连续且对象存在。
- [ ] 发布负责人确认最新快照可用、PITR 时间窗正常。
- [ ] 发布负责人确认所有 V1.2 flags 初始为关闭，且积分结算关闭。
- [ ] 发布负责人确认本卡使用的测试 member、志工任职和测试申请 ID 已登记。
- [ ] 发布负责人确认当前没有真实学员合影上传任务。

## 3. 健康与版本

由业务负责人打开 API/管理端并记录结果：

1. 访问 `/__tcb_probe__`，预期 HTTP 200、`status=ok`。
2. 访问 `/health/live`，预期 HTTP 200。
3. 访问 `/health`，预期 HTTP 200 且数据库健康。
4. 访问 `/api/v1/system/environment`，预期 `environment=production`；V1.2 开关状态由发布负责人另行截图/记录，不要求业务人员读取 secret。
5. 打开管理端 build-info，确认 commit/version 与发布记录一致。

## 4. V1.1.1 不破坏验收

使用内部标识的测试申请（不填写真实敏感资料）：

1. 未绑定小程序身份打开统一首页，预期可看到“绑定正式学员身份”和“新学长入塾申请”。
2. 进入新学长申请表，确认男女选项、政治面貌/社会角色、行业、年销售额、利润率、发票动态字段可正常显示。
3. 提交前确认隐私同意；预期后台出现一条待审核申请。
4. 管理端打开申请详情，确认新字段可读；无需将测试申请审核、收款或正式入塾。
5. 如果测试申请最终取消，记录其 ID 和取消状态；不得转换为正式 member。

## 5. V1.2 身份与岗位验收（仅在灰度开关已获批准时）

1. 测试微信登录并以“姓名 + 手机号”绑定唯一 ACTIVE member，预期返回 VERIFIED binding。
2. 绑定成功后，首页不再显示“新学长入塾申请”。
3. 已绑定但没有有效学习会 capability 的普通学员，预期只显示身份信息和“当前暂无需要操作的学习服务”。
4. 给测试 member 配置一个有效组长/辅导员任职后，预期只显示其服务小组；过期/结束任职后，学习会权限立即消失，但 binding 保留。
5. 班主任/副班主任/班长的 CLASS 范围与组长/辅导员的 GROUP 范围不得混用。

## 6. 学习会事实验收

在测试小程序中：

1. 首页 → 小组学习会登记；预期自动带出班级、小组、当前周期。
2. 一键全选本组学员，再取消一名缺席者；人数实时变化。
3. 搜索并添加一名同班跨组学员；预期显示 CROSS_GROUP，不改变其正式组织关系。
4. 选择“没有课程”提交一次；预期事实保存成功且没有积分。
5. 选择一门 CONFIGURED 和一门 PENDING 课程提交一次；预期积分只显示服务器规则，PENDING 学分为待配置/NULL，不能由组长填写。
6. 上传一张合成 JPG/PNG 合影；预期显示“合影已上传”，不出现永久公开 URL。
7. 成功页显示参加人数、课程和事实保存结果；不能只显示 `success`。

## 7. 管理端校正验收

1. 管理员打开 `/ops-platform/#/operations/study-meetings`，列表可加载。
2. 详情可查看多门课程和私有合影。
3. 运营课程修正：增加/删除课程，保存后显示审计；不入账积分。
4. 运营人员修正参加人员：删除误选、增加本组/同班跨组人员；预期本组/跨组分类正确。
5. 尝试添加跨班、非 ACTIVE、重复学员；预期全部拒绝。
6. 核对修改前后、修改人、时间、选填备注审计完整。
7. 对比 `member_org_relations`、学习周期和积分账本；预期没有任何正式组织关系/积分变化。

## 8. 存储与保留期验收

- [ ] 合成对象只能通过后端鉴权查看，不能匿名访问或猜测路径。
- [ ] `storage_key` 以 `study-meetings/` 开头，不含姓名、手机号、member_code。
- [ ] 上传替换遵循先上传新对象再切换 DB；新对象失败时旧照片仍可查看。
- [ ] 将测试记录的 `expires_at` 调整到过期（仅使用批准的隔离测试数据），API 立即拒绝查看。
- [ ] 清理 Cron/受控清理重复执行不报业务错误；对象不存在视为成功。
- [ ] 清理只改变 evidence metadata 和审计，不删除 session、attendance、course、组织关系或积分。

## 9. 停止条件

出现任一情况立即停止并通知发布负责人：

- 版本/commit 与发布记录不一致；
- 健康接口非 200；
- 绑定到错误 member、越过班级/小组范围；
- 已绑定身份仍显示新学长申请；
- 照片可公开访问、过期后仍可读取或对象路径可枚举；
- 运营修正没有审计或改变正式组织关系；
- 产生任何学员积分；
- 生产出现无法解释的 5xx、迁移错误或费用/资源异常。
