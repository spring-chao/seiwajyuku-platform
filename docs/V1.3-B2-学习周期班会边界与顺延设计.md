# V1.3-B2：学习周期班会边界与顺延设计

## 结论

36 个学习周期是 36 个连续的学习阶段，不是 36 个固定自然月。

- `cohort_month` 只表示 1、4、7、10 月开班月份模板。
- `class_learning_bindings.started_at` 表示具体班级学习计划的起点。
- 默认计划日期由起点按自然月顺延生成，仅作为运营参考。
- 实际周期时钟仍由 `class_learning_cycles` 驱动：当前开放周期只有在真实班会确认后关闭，下一周期才以实际班会时间打开。
- 小组学习会、自然月份变化、计划日期经过，不会推进学习周期。

因此，计划投影与实际投影必须分开：

```text
PLANNED
具体班级开班时间 → 默认计划班会日期 → learning_cycle_index

ACTUAL/CURRENT
class_learning_cycles.opened_at / actual_class_meeting_at
→ 当前 OPEN 周期
```

## 数据模型

现有 `class_learning_cycles` 已承载已经进入运行时的周期实例：

| 字段 | 含义 |
| --- | --- |
| `opened_at` | 实际周期开始时间；下一周期使用上一场真实班会时间 |
| `planned_class_meeting_at` | 当前周期的计划班会时间 |
| `actual_class_meeting_at` | 已确认的真实班会时间 |
| `class_meeting_status` | `PLANNED`、`POSTPONED`、`HELD` |
| `cycle_status` | `OPEN`、`CLOSED`；兼容已有 `UPCOMING` |
| `adjustment_reason` | 当前周期调整说明 |

未来周期尚未生成 `class_learning_cycles` 实例，因此新增：

`class_learning_cycle_schedule_overrides`

它以 `binding_id + learning_cycle_index` 唯一定位一个具体班级的一个周期，保存：

- 覆盖后的 `planned_class_meeting_at`；
- `adjustment_reason`；
- `ACTIVE` / `REVOKED`；
- 创建人、修改人及时间。

它只保存计划覆盖，不改变周期状态，也不直接推进学习周期。确认前序班会时，现有引擎把当前有效覆盖复制到新打开的 `class_learning_cycles` 行。

## 运行流程

1. 绑定班级时打开第 1 周期，并生成默认计划日期。
2. 运营人员可以通过周期级接口调整当前或未来某一周期的计划班会日期，并必须填写原因。
3. 到达自然月份或超过计划日期时，当前 `OPEN` 周期保持不变。
4. 确认真实班会后：
   - 当前周期写入 `actual_class_meeting_at`；
   - 当前周期变为 `CLOSED`；
   - 下一周期以该真实班会时间作为 `opened_at`；
   - 下一周期使用它自己的活动覆盖，或使用默认计划日期。
5. 已 `CLOSED` 的周期不可再调整。调整只影响当前开放周期或尚未实例化的未来周期。

接口：

- `GET /api/v1/classes/{class_org_unit_id}/learning-cycle-schedule`
- `PUT /api/v1/classes/{class_org_unit_id}/learning-cycles/{learning_cycle_index}/schedule-override`
- `DELETE /api/v1/classes/{class_org_unit_id}/learning-cycles/{learning_cycle_index}/schedule-override`

接口权限分别为 `plans:read` 与 `plans:period_write`，不改变后台全局登录保护。

## 春节顺延模拟

以 2026 年 7 月开班班级为例：

- 默认第 8 周期计划月份为 2027-02；
- 运营人员把该班第 8 周期调整为 2027-03-20，原因填写“春节期间暂停班会”；
- 第 1～7 周期班会确认后，第 8 周期打开，但仍是 `learning_cycle_index=8`；
- 2027-03-01 查询时，当前仍为第 8 周期，内容仍从第 8 周期计划读取；
- 2027-03-20 班会确认后，第 8 周期关闭，第 9 周期才打开。

同一 7 月开班模板下，其他班级没有该班级级覆盖时不受影响。不会写入月份等于 2 的特殊判断，也不会按班级名称硬编码。

## 审计口径

`4 个开班月份模板 × 36 学习周期 = 144` 仍是模板/计划审计口径，所有投影条目标记为 `projection_type=PLANNED`。

真实当前投影使用 `projection_type=ACTUAL_CURRENT`，字段包括当前开放周期、计划月份、实际状态和周期调整。静态审计脚本不连接生产数据库；未提供运行时状态时明确输出 `NOT_PROVIDED`，不把计划投影冒充成真实进度。需要时可通过 `--actual-state` 提供经过授权的 `class_learning_cycles` 当前状态快照。

本次 B2 不重写 A/B 内容映射，也不改变原有映射冲突/缺失统计；它只让审计报告明确哪些是计划投影，哪些需要运行时状态才能判断。
