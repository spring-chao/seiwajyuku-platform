# 学习计划四事实与全班级基线收口

日期：2026-09-03
状态：代码已完成，生产数据仍处于只读核验阶段

## 业务原则

班级学习计划拆成四个互相独立的事实：

1. 计划版本决定学哪一套课程、流程和积分规则；
2. 1 月、4 月、7 月、10 月开班模板决定课程轨道；
3. 真实班会边界决定当前第几学习周期；
4. `PLANNED`、`POSTPONED`、`NOT_STARTED` 等运行状态描述当前是否正常进行。

自然月份经过不会推进学习周期；延期不会创建新轮次，也不会把暂停误写成重新开始。

## 本轮实现

- `_cycle_at()` 只选择查询时间之前已经打开的运行周期；未来正式开始的绑定返回 `current_cycle=null` 和 `NOT_STARTED`。
- 学习进度、班级健康扫描和小组学习会入口均不会把未来第 1 周期当作当前周期。
- 健康扫描按 `class_org_unit_id` 对比业务基线，支持周期、模板、计划版本和状态四类预期差异，并输出实际值与拟议值。
- 基线位于 `data/learning-plans/class-learning-plan-migration-baseline-2026-09.json`，仅用于只读 DRY-RUN；未解析组织 ID 的班级明确标记为 `NEEDS_ID_LOOKUP`，不按名称匹配。
- `MANUAL_REVIEW_REQUIRED` 班级（当前包括真干三班、真干班）不会进入自动修正路径。

## 只读核验流程

先用有权限的管理员会话读取：

- `GET /api/v1/learning-plans`
- `GET /api/v1/classes/learning-plan-health`
- 各班级的 `learning-plan-history`、`learning-progress`、`learning-cycle-schedule`

将健康接口响应保存为本地 JSON 后运行：

```text
python scripts/audit_learning_plan_baseline.py --health-json <health-response.json> --output <dry-run-report.json>
```

该命令只生成差异报告，不包含生产写入路径。生产修正必须逐班复核证据、确认组织 ID，并通过既有审计和写入门禁。

## 验收重点

- 正常班：模板、版本、实际周期与业务基线一致；
- 炎武二班：第 11 周期保持不变，班会延期，小组学习会规则不被擅自暂停；
- 振华一班：正式开始前为 `NOT_STARTED`，不显示第 1 周期、不开放当前小组学习会登记；
- 真干三班：仅保留待人工确认状态，不绑定模板、不修改生产数据。
