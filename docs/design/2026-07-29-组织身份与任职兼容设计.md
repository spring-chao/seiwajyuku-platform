# 组织身份与任职兼容设计

- 日期：2026-07-29
- 状态：代码基础已实现；真实人员映射与生产启用待批准
- 依据：组织身份与产品定位决策、代码级审计

## 设计结论

现有 `org_units` 继续承载三级分中心、班级、小组和特殊班等学长组织范围。新增 `operating_institutions` 承载“盛和塾总部 → 江南塾 → 苏州分中心 → 苏州分中心运营中心”专职机构树，避免把运营中心人员归入六个三级分中心。

身份与授权链如下：

```text
person_profiles
├── account_person_links ── app_users
├── member_identities ── members
│   └── member_membership_periods
├── operations_employments ── operating_institutions
│   ├── operations_position_assignments
│   └── employee_service_responsibilities ── org_units
├── volunteer_appointments ── org_units
└── technical_admin_assignments
```

雇员组织归属来自 `operations_employments.institution_id`；对某三级分中心的访问来自 `employee_service_responsibilities`，后者只是服务责任范围。志工权限来自 `volunteer_appointments` 的任职名称、组织、范围、状态和起止时间。

## 兼容读取

`user_context()` 合并四类来源：

1. 旧 `user_roles` 与 `data_scope_grants`；
2. 有效雇佣下的有效岗位和服务责任范围；
3. 有效志工任职及其组织范围；
4. 有效技术管理员任期。

返回值增加 `subject_contexts`、`language_context` 和 `authorization_sources`，使权限来源可解释。旧角色仍可使用，避免一次性破坏现有账号；新任职到期、停用、结束或撤销后自动退出授权上下文。

新来源读取受 `IDENTITY_AUTHORIZATION_ENABLED` 灰度开关控制，默认 `false`。迁移建表本身不会启用新授权；仅测试、隔离 MySQL 验证和获批试点显式开启。

身份管理写入另受 `IDENTITY_ADMIN_WRITES_ENABLED` 控制，默认 `false`。即使新授权读取已开启，管理端仍可保持只读。管理 API、页面和审计规则见 `docs/tasks/11-受控身份与任职管理.md`。

## 旧角色兼容映射

| 旧角色 | 新模型候选 | 必须补充 | 自动迁移 |
|---|---|---|---|
| `operations_admin` | 运营中心雇佣 + 某一岗位 | 在职事实、岗位、起止时间、服务责任范围 | 否 |
| `regional_manager` | 理事或三级分中心负责人志工 | 任职名称、任职组织、范围、任期、任命依据 | 否 |
| `class_counselor` | 班主任或班委志工 | 具体任职、班级、任期、任命依据 | 否 |
| `group_leader` | 组长或组委志工 | 具体任职、小组、任期、任命依据 | 否 |
| `system_admin` | 技术管理员及可能的独立业务身份 | 技术用途、任期；业务权限另行确认 | 否 |
| `data_security_admin` | 数据安全职责 | 用途、任期、审批 | 否 |
| `read_only` | 临时观察授权 | 用途、范围、有效期 | 否 |

`scripts/preview_identity_migration.py` 只生成上述候选与异常，不读取姓名、手机号来推断身份，也没有写入模式。

## 运营中心岗位权限矩阵

符号：`R` 查看，`W` 业务维护，`A` 高风险管理。未列出的能力默认不授予。

| 岗位模板 | 组织 | MP | 学长 | 关怀 | 续费 | 签到 | 集成/审计 |
|---|---|---|---|---|---|---|---|
| 运营中心负责人 | A | A | W + 用途化企业资料 | W | W | A | A |
| 分中心运营专员 | R | W | W | W | W | - | - |
| 学习践行专员 | R | R | R | W | - | 裁定 | - |
| 发展建设专员 | R | - | W | W | W | - | - |
| 运营管理专员 | R | W/发布 | R | - | - | - | 审计 R |
| 数据中心专员 | A | 导入 | W | - | R | 同步 | 集成 A |
| 财务专员 | R | R | - | - | W | - | - |
| 行政专员 | R | - | 脱敏 R | W | - | - | - |

所有岗位均不含 `exports:sensitive`。完整敏感导出仍只属于独立数据安全职责。财务岗位不因岗位名称自动获得企业敏感资料；需要新增、经审批的财务用途权限后再评估。

兼容说明：`operations_admin` 作为“苏州塾运营管理员”岗位键保留到新任职模型中；它可以与分中心运营、数据中心、行政等岗位共同挂在同一条苏州分中心运营中心雇佣记录下，权限统一受该雇佣的有效期约束。

## 志工任职模板

- 理事；
- 三级分中心负责人；
- 三级分中心志工；
- 班主任；
- 班委；
- 组长；
- 组委；
- 专项活动志工。

所有志工模板必须绑定 `UNIT` 或 `SUBTREE` 范围、明确起止时间和非空任命依据。不存在无组织、无期限的志工任职。

## 技术管理员隔离

`technical_admin` 仅包含 IAM、组织技术配置、审计和集成管理能力，不含：

- `members:read`；
- `members:detail_view`；
- `members:enterprise_view`；
- `contact:reveal`；
- `renewals:*`；
- `exports:sensitive`。

旧 `system_admin` 暂时保留为兼容角色。真实账号试点前必须将“技术身份”和“业务岗位/任职”拆开验证，不能直接把旧角色改名。
