# 志工身份与授权有效性规则（2026-09-08）

## 结论

身份有效性采用三条彼此独立的基础规则：

- 专职人员：看是否在职。
- 志工：看学长是否在册。
- 登录账号：看是否启用。

志工并不因“在册”而自动获得任何权限。志工资格以前述在册状态为前置条件；具体能以何种志工身份服务、能够服务哪些组织，仍由当前志工岗位与服务范围决定。

## 授权判定

```text
专职权限：
账号启用
+ employment_status = ACTIVE（在职）
+ role × scope 授权状态 = ACTIVE
→ 允许

志工权限：
账号启用
+ members.status = ACTIVE（在册）
+ 当前志工岗位 = ACTIVE
+ 岗位 × 服务范围有效
→ 允许
```

志工岗位必须保存正式 `member_id`，且账号自然人、志工记录和该学长正式身份必须一致。旧记录若不能唯一补齐正式学长关联，只保留为历史档案，不能产生当前授权。

专职的 `started_on` / `ended_on`、岗位或授权的 `valid_from` / `valid_until` 可继续保留为旧档案字段，但不再决定普通专职权限。普通录入默认不填写这些日期；建立或调整在职、岗位和角色范围时，通过状态与明确的撤销操作控制权限。

## 岗位与历史

- 普通志工岗位没有业务开始日期、结束日期和自动到期。
- 建立岗位时记录系统确认时间；结束或撤销岗位时记录结束操作时间，两者仅用于档案与审计。
- 学长改为非在册时，所有志工授权立即不可用，岗位与历史记录仍保留。
- 学长恢复在册时，只有仍为 `ACTIVE` 的当前岗位才会重新生效；已结束或已撤销的岗位不会自动恢复。
- 专职离职不会改变学长在册身份；若账号启用、学长仍在册且仍有当前志工岗位，仍可作为志工服务。

## 实施边界

本规则取代 2026-07-29 兼容设计中将志工 `starts_at` / `ends_at` 作为普通业务任期和授权条件的部分。旧字段为兼容历史数据继续保留，但不再参与志工权限计算。

数据库迁移 `0052_volunteer_membership_authority` 负责新增并安全回填 `volunteer_appointments.member_id`。迁移回滚采用保守策略：存在任何正式学长关联时拒绝回滚，避免丢失授权证据。

本文只定义代码与数据模型规则，不授权生产迁移、生产数据写入或发布。
