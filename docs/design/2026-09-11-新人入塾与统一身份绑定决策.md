# 新人入塾与统一身份绑定决策

## 决策

申请入口问“你要去哪里”，身份入口只问“你是谁”。

- 新学长申请先选择具体目标塾：苏州塾、常州塾或无锡塾；江南塾仅作为上级组织，不是公开申请目标。
- 选择目标塾后进入同一套资料表，`target_shuku_org_unit_id` 保存申请意愿；审核确定的 `org_unit_id` 仍是另一项事实。
- 第 05 部分的加入说明、缴费说明和联系方式来自业务配置，不在小程序中按塾硬编码。
- 已有人员绑定统一使用姓名、手机号和微信登录凭证。系统在江南统一人员资料中按姓名与手机号哈希解析唯一 `person_id`，不让用户选择塾或身份。
- 解析结果可以同时呈现 `MEMBER`、`VOLUNTEER` 和 `OPERATIONS_EMPLOYEE`；志工和工作人员仍分别遵守既有在册、在职与 IAM2 规则。
- 工作人员身份首次绑定必须通过微信手机号所有权校验；普通学员不因工作人员门槛而被要求输入后台账号密码。
- 旧 `/member-bindings/verify` 和 `/staff-bindings/verify` 接口及工作人员绑定页保留兼容，但不再从普通首页暴露。

## 业务配置边界

`enrollment_shuku_profiles` 只存业务确认后的公开加入、缴费和联系资料。迁移不预置任何收款账号、联系人或手机号。缺少目标塾配置时，公开 metadata 返回 `BUSINESS_CONFIG_REQUIRED`，前端显示未配置提示，不展示旧的硬编码资料。

## 安全与回滚

新增迁移 `0061_enrollment_shuku_profiles` 仅创建配置表和索引；回滚在表中已有配置时拒绝执行，避免静默丢失业务资料。身份绑定只创建或更新人员级微信凭证，不创建虚假学员，不复制 IAM2 或 Volunteer 2.0 授权事实。
