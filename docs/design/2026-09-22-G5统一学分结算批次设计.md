# G5 统一学分结算批次设计

状态：设计草案，未实现、未迁移、未接生产。
适用来源：小组学习会、班级学习会、每日读书、优秀分享、历史学分以及未来新增的受控学习事实。

## 设计目标

所有学分类型共用一条编排链：

```text
事实 -> 匹配冻结规则 -> DRY-RUN -> 结算批次 -> 审批 -> POST ledger -> 必要时追加冲销
```

批次只负责集合、快照、审批、重试与对账。`learning_credit_entries` 仍是最终不可变账本；批次不能替代ledger，也不能修改已POST entry的业务内容。

## 建议表

### learning_credit_settlement_batches

| 字段 | 约束/用途 |
| --- | --- |
| id | BIGINT主键 |
| batch_no | 全局唯一、可读且不可变，例如`LC-202609-GROUP-0001` |
| batch_type | `REGULAR`、`HISTORICAL_IMPORT`、`CORRECTION`等受控枚举 |
| source_type | 与事实来源和ledger source_type对齐 |
| class_org_unit_id | 可空；有班级范围时必须是组织ID，不能只存名称 |
| period_start / period_end | 批次事实窗口；历史YEAR精度不得伪造月日 |
| status | DRAFT、DRY_RUN、PENDING_APPROVAL、APPROVED、POSTING、POSTED、PARTIAL_FAILED、CLOSED、CANCELLED |
| proposed_entry_count / proposed_points | DRY-RUN冻结汇总 |
| blocked_count | 未解决阻塞数量 |
| approved_by / approved_at | 审批人及时间；APPROVED前必须为空，之后不可静默替换 |
| posted_entry_count / posted_points | 从ledger实际结果回算，不信任请求值 |
| source_snapshot_json | 事实集合标识、范围、指纹、来源版本，不保存密钥或整份敏感原文 |
| rule_snapshot_json | 所用规则版本和指纹；APPROVED后不可漂移 |
| result_snapshot_json | blocker与汇总结果；不复制可查询的完整个人敏感资料 |
| created_by / created_at / updated_at | 操作审计字段 |

建议额外保存 `source_fingerprint`、`rule_fingerprint`、`approval_fingerprint` 三个固定长度摘要，并对 `(source_type, source_fingerprint, batch_type)` 建唯一约束，避免同一来源被重复建批。

### learning_credit_settlement_batch_items

| 字段 | 约束/用途 |
| --- | --- |
| id / batch_id | 主键及批次外键 |
| member_id | 最终匹配学员；blocked时可空 |
| source_type / source_id | 原事实稳定身份 |
| source_snapshot_json | 单条事实最小充分快照 |
| rule_key / rule_version / rule_version_id | 冻结规则身份 |
| rule_snapshot_json | POST时复制到ledger的规则快照 |
| credit_category / credit_type / points | 拟入账结果 |
| occurred_at / occurred_precision / occurred_year / occurred_month | 复用ledger的时间精度语义 |
| idempotency_key | 由原事实稳定生成；全局唯一语义与ledger一致 |
| status | PROPOSED、BLOCKED、APPROVED、POSTING、POSTED、FAILED、CANCELLED、REVERSED |
| blocking_reason / error_code | 机器可判定原因，不把原始敏感异常写入 |
| ledger_entry_id | POST成功后指向最终ledger entry；一个item最多对应一个正向entry |
| created_at / updated_at | 审计字段 |

应对 `(batch_id, idempotency_key)` 建唯一约束；POST前还必须查询`learning_credit_entries.idempotency_key`，数据库唯一约束仍是最终防线。

## 状态机

```text
DRAFT -> DRY_RUN -> PENDING_APPROVAL -> APPROVED -> POSTING
POSTING -> POSTED -> CLOSED
POSTING -> PARTIAL_FAILED -> POSTING
DRAFT/DRY_RUN/PENDING_APPROVAL -> CANCELLED
```

- `DRY_RUN`：保存结果快照，不写ledger。
- `PENDING_APPROVAL`：来源与规则指纹冻结；变更事实或规则必须退回DRAFT并生成新快照。
- `APPROVED`：只允许同一审批指纹进入POSTING。
- `PARTIAL_FAILED`：成功item保持POSTED；重试仅处理未完成item，依赖稳定幂等键防重复。
- `POSTED`：`posted_entry_count/points`必须来自ledger实查并与items对账。
- `CLOSED`：业务封账；需要纠错时新建CORRECTION批次或追加reversal，不能重开并覆盖。

## 幂等、规则与冲销不变量

1. 幂等键由原事实身份生成，不包含运行时批次ID；同一事实跨批次重跑仍命中同一个ledger key。
2. POST逐条使用现有`learning_credit_entries.idempotency_key`和唯一约束；已存在且内容一致视为幂等成功，内容不一致则批次失败关闭。
3. APPROVED后`source_fingerprint`、`rule_fingerprint`和每条`rule_snapshot_json`不可变化。
4. PARTIAL_FAILED重试不删除成功entry，不重算已POST item，只补未完成部分。
5. 错误积分只能新增负向entry并设置`reversal_of_entry_id`；不得UPDATE/DELETE原ledger事实。
6. 历史学分固定`LEGACY_SUZHOU_2026_V1`及Excel原分值；其规则快照描述迁移口径，不调用当前活动规则重新定价。
7. 批次总分、item总分和ledger实际增量三者必须对账；任何差异阻止CLOSED。

## 权限与审计

- DRY-RUN、审批、POST、关闭和冲销使用不同权限；POST和冲销至少限系统管理员或未来明确的学分结算角色。
- 每次状态迁移写审计日志，保存before/after状态、批次号、actor、reason、request_id和指纹。
- 同一批次POST使用固定操作锁；不接受调用方传入任意SQL、表名或锁名。
- 正式POST同时受`ALLOW_PRODUCTION_MUTATIONS`、`LEARNING_CREDIT_SETTLEMENT_ENABLED`、runtime provenance和批次APPROVED状态约束。

## 与现有能力的兼容性

- `settle_study_meeting()`已具备稳定幂等、规则快照、ledger写入和重复调用保护，可将“生成proposal”和“POST entry”拆入批次编排，而不改变ledger边界。
- 班级学习会、每日读书、优秀分享当前返回proposal和blocker且`formal_settlement_allowed=false`，可直接成为批次item生成器；本阶段不为它们新增独立POST。
- 历史导入已有batch/row/item/review概念，但那是来源清洗staging；未来结算批次应引用其APPROVED快照，不复用或替代历史staging表。
- 现有`post_credit_entry()`和`reverse_credit_entry()`可作为未来统一执行器的底层能力；实施前需补批次级事务、部分失败续跑、对账和权限测试。
