# R3 生产只读采集运行准备

本文件准备 `R3_DB_BASELINE_READ` 的固定访问方式，不构成批准。原 `r3_collect_readonly.py` 只读取腾讯云和三个健康/版本 GET；原 `DatabaseReadAdapter.collect()` 仍拒绝生产读取。新的 `r3_collect_db_readonly.py` 是独立、必须取得具体授权才会连接的入口。

## 批准对象与签发前材料

运行前须固定生产逻辑库、TLS 主机与端口、只读主体 `CURRENT_USER()`、实际稳定 revision、干净的控制器提交、允许来源、执行人和最长一小时窗口。数据库只读访问与 IAM/账号创建分别授权，不能因本任务目标而自动创建账号、改变权限或取用应用写账号。

签发方应复核真实用户批准后，使用预先存在、独立保管的授权 key 对 JSON 正文按 `r3_read_evidence.canonical()` 序列化并做 HMAC-SHA256，加入 `seal`。仓库不提供自动签发授权、创建 key 或配置 ACL 的命令。授权 key 与 collector key 必须不同，两个 key 均不在输出或授权文件目录；不输出 key 内容。

正文严格包含以下字段（示意值全部不可执行）：

```json
{
  "schema_version": 1,
  "purpose": "R3_DB_BASELINE_READ",
  "scope": "ap-shanghai/shengheshu-d2g2zyyl99f6c6fc2/seiwajyuku-platform-api",
  "controller_commit": "TO_BE_FIXED_AFTER_MAIN_CI",
  "approval_ref": "NOT_ISSUED",
  "approved_by": "TO_BE_FIXED",
  "realm": "live",
  "not_before": 0,
  "expires_at": 0,
  "database_name": "UNVERIFIED",
  "host": "UNVERIFIED",
  "port": 3306,
  "principal": "UNVERIFIED",
  "baseline_revision": "UNVERIFIED",
  "query_fingerprint": "TO_BE_COMPUTED_FROM_FIXED_QUERY_MAP",
  "journal_fingerprint": "TO_BE_COMPUTED_FROM_CANONICAL_JOURNAL_PATH",
  "max_batches": 1,
  "max_writes": 0
}
```

`query_fingerprint` 为 `r3_collect_db_readonly.query_fingerprint()`；它绑定 12 个固定 QueryId 的完整 SQL，SQL 修改后须重新批准。`journal_fingerprint` 为 `fingerprint(Path(journal).resolve().as_posix())`，绑定唯一持久化台账，不能换路径重新执行。台账放在授权 key 已核验的私有目录，保留失败记录；进程重启、连接失败、查询失败或结果未知均不能自动重试。

## 账号和查询范围

账号只允许 `APPROVED_COLUMNS` 列级 SELECT 与无授予能力的 USAGE；全部业务列范围在 `scripts/r3_collect_db_readonly.py` 的固定映射中。包括课程/通用规则、映射、绑定、迁移版本、APPLY 审计计数、占位项引用及账本 COUNT/SUM。不得授予库级、表级或全局 SELECT，不读取学员标识或交易明细，不允许 GRANT OPTION。查询前后分别校验 `CURRENT_USER()`、实际库名、`CURRENT_ROLE()='NONE'`、`@@session.transaction_read_only=1` 和完整可见权限范围。权限检查新增 grant scope、库/表/列和 IS_GRANTABLE 元数据，以识别“虽然只读、范围却过宽”的账号。

MySQL/代理必须事先提供只读会话；采集器不通过 SET、角色激活、权限写入或账号切换修复不符合条件的连接。连接驱动的正常字符集协商不授予额外权限。固定 QueryId 只执行 SELECT，每次最多 500 行，前后结果不一致即拒绝。

## 运行方式

先完成对应提交的 CI、隔离 MySQL 列级账号查询验证与签发材料审阅。密码仅由独立只读主体的安全进程环境提供 `R3_DB_READ_PASSWORD`，TLS CA 路径由 `R3_DB_READ_TLS_CA` 提供；开启证书和主机名校验。禁止使用应用 DATABASE_URL、自动读取保存的生产凭据、密码命令行参数或自动登录。

```text
python scripts/r3_collect_db_readonly.py --collect-approved-db-baseline
  --authorization <已独立签发的JSON>
  --authorization-key-file <预配置私有授权key>
  --verifier-key-file <独立collector key>
  --controller-commit <干净且CI通过的40位提交>
  --baseline-revision <本次核验的稳定revision>
  --journal <授权key私有目录内的固定SQLite台账>
  --output <尚不存在的独立输出文件>
```

成功仅证明 DB 基线采集，不自动宣称 Phase 3 完成或 production_ready=true。三类证据须同对象、同窗口、新鲜且独立校验；后续规则 APPLY、迁移、历史 staging、正式入账、角色和开关仍独立批准。本文不证明真实生产只读账号/通道或正式签封 key 已存在。
