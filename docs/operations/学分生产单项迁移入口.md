# 学分生产单项迁移入口

状态：供独立迁移批准与隔离验证，不构成生产写入许可。入口为 `scripts/credit_single_migration.py`，仅允许现有 0064–0067 的固定 Git blob 内容；不执行通用“迁移到最新”，不提供 down、任意 SQL、账号创建、自动签发批准或清除执行台账入口。

## 离线计划

```powershell
python scripts/credit_single_migration.py --plan --migration 0067
```

该命令只读取固定 SQL、校验 SHA-256 并拆分语句，输出文件名、hash 与脚本语句数。不加载应用数据库配置，不连接数据库、不申请读取/写入、不生成有效批准。0067 当前为四条脚本语句；正式成功时额外写一条 schema_migrations 登记。固定执行前 SELECT 与 GET_LOCK 也属于需要批准的数据库访问范围。

## 审阅和签发

完整影响与文件 hash 见 [首批执行与验收包](学分首批上线执行与验收包.md)。特别注意：0064 更新全部匹配 standard-3y/2026 的绑定，包含非活动绑定，并补课程引用；0066 改变期间结构、回填现有账本年月，不能按空表 DDL 批准。

批准记录与 [R3 读取入口](R3生产只读采集运行准备.md) 使用同一独立签发校验机制，purpose 必须为 `CREDIT_SINGLE_MYSQL_MIGRATION`。授权 key 与证据 key 分离，放在已核验私有目录；本入口不生成密钥或替人签发。签发人审阅目标 main 九项 CI artifact、迁移前备份及恢复演练报告、实时云/DB 基线，然后绑定以下全部字段；任何缺项、额外字段或布尔伪装的次数/数量均拒绝。

| 字段组 | 固定内容 |
| --- | --- |
| 身份与窗口 | schema_version=1、purpose、scope=`ap-shanghai/shengheshu-d2g2zyyl99f6c6fc2/seiwajyuku-platform-api`、realm=live、完整 controller_commit、approval_ref、approved_by、not_before/expires_at（最多一小时） |

## 执行前关闭与来源条件

入口验证云快照前后相同、稳定 revision 为 FLOW 100%、发布单关闭、管理任务结束、三项真实 HTTP 探针及 runtime commit。revision 上 G5 APPLY、settlement、bootstrap 均必须 false。独立 DB 签封绑定同服务/库，迁移连接再次核验 DATABASE/CURRENT_USER/CURRENT_ROLE，然后取得库范围的非等待 MySQL advisory lock；此锁仅协调本入口，不保护绕行的人工或通用 migrator，执行窗口仍须避免其他规则/迁移写入。

实时规则要求课程目录 25 条逐字段 canonical、通用版本唯一 PUBLISHED/六条 ACTIVE、规则 APPLY 审计一条。0064 要求 DRAFT、映射/全范围冻结为零；后续要求 PUBLISHED、映射唯一且所有目标绑定已冻结。目标必须未登记、前序迁移已登记、后序未登记，0063 基础记录存在。固定业务 SELECT 结果逐项与可信 DB 签封相同；源变动、库/主体/角色不符、数量变化或证据过期都在脚本 DDL 前停止。

入口目前不执行完整 R3 Phase 4 或生成其关闭证据，不能用该入口替代规则 APPLY、CloudRun 候选控制及其独立验收；这些仍需先完成。

## 执行命令

通过专用进程环境配置 `CREDIT_MIGRATION_PASSWORD` 和 `CREDIT_MIGRATION_TLS_CA`。不把密码写入命令、批准、日志或回执；TLS 验证 CA 与主机名，不关闭验证、不自动重连/重试。

```powershell
python scripts/credit_single_migration.py --execute-approved --migration 0067 `
  --authorization <独立签发JSON> --authorization-key-file <私有批准key> `
  --verifier-key-file <私有采集证据key> --controller-commit <获批main完整SHA> `
  --cloud-evidence <同窗口云与HTTP签封> --db-evidence <同窗口DB签封> `
  --release-manifest <该main的九项CI产物> --backup-evidence <已审阅备份恢复材料> `
  --journal <批准key私有目录内固定台账> --output <不存在的新回执文件>
```

这是参数说明，尖括号材料缺失时不能执行。执行前校验干净 checkout、批准与签封，台账在建立连接前持久化消耗额度。不同批准编号也不能重放同一目标/迁移；台账不得删除、改名或换路径绕行。已登记迁移拒绝重复执行，不将重跑视为幂等恢复。

## 结果与恢复

成功回执 `MIGRATION_RECORDED` 只表示本次脚本执行、账本条数/分值和规则等不变量核对、迁移登记提交及本地记录成功；production_ready 保持 false。0064 另核验全范围冻结和课程引用填齐。后续 schema 使用与页面验收仍依赖目标迁移相应 MySQL/运行时证据。

网络中断、语句/commit/登记超时、写后不变量失败或本地记录失败返回 `MIGRATION_OUTCOME_UNKNOWN`，次数永久消耗。MySQL DDL 可能已提交、部分表可能已存在，入口不调用自动 down，也不将 rollback 当作恢复证明。下一步只能按获批方式读迁移登记、实际 schema、账本/绑定与备份比对，形成新的人工恢复方案；不是再跑原脚本。CLI 成功写库后回执文件保存失败另报 `MIGRATION_RECEIPT_WRITE_FAILED`，不得重放写库。

私有台账与批准保留，记录服务/目标指纹、迁移、批准指纹、开始时间及 UNKNOWN/RECORDED；不存放凭据或业务明细。`--plan` 可以重复运行，执行模式没有恢复台账或强制开关。

本地 `test_credit_single_migration.py` 覆盖签名/对象/文件/窗口、基线漂移、非活动绑定影响范围、fixture 拒绝、材料变更、重启/新批准禁重放及 commit/DDL 结果未知。`test_credit_single_migration_mysql.py` 在既有 `study-meeting-mysql` 中创建新可丢弃 schema，执行 0064–0067 的真实逐项 SQL，并在 0067 第二条 DDL 前中断，核验第一张表已提交、登记缺失、账本不变、重启不能重放。

CI 云/批准/备份 attestations 为合成测试合同，只证明入口 SQL 效果与防重机制，不证明生产云状态或真实备份恢复。生产使用仍需工程工作流中明确的迁移批准。
