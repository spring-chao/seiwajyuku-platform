## 生产核验与角色

按 [R3 受限读取准备](R3生产只读采集运行准备.md) 取得独立批准，采集固定规则/绑定/账本/0064–0067 基线。SQL 指纹变化须重新签发，旧授权不覆盖新增 0067 检查。DB 签封结果不能单独证明 CloudRun、候选身份、写入批准或模块可上线。

规则 APPLY、CloudRun 配置写入、数据库迁移、IAM 授权及首批账本入账分别固定对象和批准。R3 Phase 4 的真实证据接线、有限 CloudRun 写适配器与定向 APPLY 仍未完成，不得把离线 fixture journal 当生产执行器。

人员通过「专职人员管理 → 学分结算专项能力」显式授权，填写业务原因并保留 IAM 审计。每项批准绑定 user_id、role_key、org_unit_id、UNIT/SUBTREE、有效期。权限目录与角色模板存在不代表人员获权；0067 不初始化全部能力角色，不得在生产启动时运行全量 IAM seed 补齐。

| 操作 | 必需能力 | 约束 |
| --- | --- | --- |
| 创建/维护批次 | `plans:credit_settlement_manage` | 范围覆盖目标班级 |
| 审批 | `credit_settlement_approver` | 与创建人不同，不混用其他职责的组织范围 |
| POST | `credit_settlement_poster` | 系统管理员显式分配的受限角色，仅处理已审批固定批次 |
| 处理中断 | `credit_settlement_reconciler` | 先核验 30 分钟心跳与账本，未知结果不能盲目续跑 |
| 封账 | `credit_settlement_closer` | 提案/items/ledger 条数与分值一致 |
| 纠错 | `credit_settlement_reverser` | 追加负向记录且填写原因，原事实不修改、不删除 |
| 历史审核 | `plans:historical_credit_import_manage` | 额外限定历史来源与批次 |

## 历史审核材料

首批固定实际试点班级、业务审核负责人、来源文件 hash、当前名单版本/匹配算法版本、batch_id、来源与规则指纹、期间精度、就绪/阻塞/重复条数及分值。只把审核决定与脱敏汇总放入批准包，不复制原始姓名/手机号/快照。

历史来源限定 `LEGACY_SUZHOU_2026_V1`，保持原分值与 YEAR/MONTH/EXACT_DATE 精度。明确人员和班级歧义、九月双轨/来源重叠、零分确认、异常排除及仅有年度的期间接受决定。旧隔离 READY/BLOCKED 数不代替这次清单；参与历史导入不代替学分账本。

历史 staging 登记、人工审核决定和 batch DRY-RUN 都会写数据库，必须在对应批准后执行。当前原始工作簿与新鲜生产名单未同时核验，尚未生成可正式入账清单。

## 首批 HTTP 与页面验收

以下学习会示例每步使用真实账号，保存不含 Token/快照的回执。历史来源走专用历史 DRY-RUN/审核接口，不套用学习会生成历史提案。

| 步骤 | 接口（/api/v1/learning-credits） | 必须验收 |
| --- | --- | --- |
| 提案 | `POST /settlement-batches/study-meetings/{session_id}/dry-run` | 提案数/分值/指纹冻结，ledger 无变化；创建批次属于写入 |
| 提交审批 | `POST /settlement-batches/{batch_id}/submit-approval` | PENDING_APPROVAL，ledger 无变化 |
| 独立审批 | `POST /settlement-batches/{batch_id}/approve` | 创建人拒绝、外班拒绝，合法审批为 APPROVED |
| 入账 | `POST /settlement-batches/{batch_id}/post` | 仅获批人、批次、指纹和开关均满足时执行，不自动续跑未知结果 |
| 对账/封账 | `GET /settlement-batches/{batch_id}` 与 `POST .../close` | 每个 item 对应唯一 ledger，精确条数/分值一致后 CLOSED |
| 学员本人 | `/api/v1/wechat/credit-summary`、`/credit-entries`、`/credit-entries/{entry_id}` | 待审批提案不可见，本人正式账分值正确，他人详情 404，无电话/原始快照 |

真实后台验证选班级、提案、独立审批、执行、详情与封账反馈；真实小程序验证本人汇总、分页、来源详情和期间标签。网络响应与隔离测试不代替真机验收。生产只对真实获批事实入账，不为演练写虚构积分；冲销/故障恢复先在隔离环境演练，真实纠错另行批准。

隔离 HTTP 入口：`python -m pytest apps/platform-api/tests/test_credit_launch_http_acceptance.py -q`。同一文件纳入 `study-meeting-mysql` 的可丢弃 MySQL，使用真实 HTTP 登录、人员授权、组织范围、批次服务与账本；微信提供方仅用既有 test/dev 本地模式，不能用于生产。
