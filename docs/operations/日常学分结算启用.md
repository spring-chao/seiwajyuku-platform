# 日常学分结算启用

用户于 2026-10-11 要求先启用日常结算，历史年度数据仅黄埔一班有数据，走独立上传和核验。本文件是执行说明，实际生产完成状态以本次回执为准。

## 固定准备顺序

1. 在现有管理员会话的「管理员设置 → 学分上线准备」核验并执行已确认的 25 条课程规则收口。沿用原有 G5 指纹、范围和审计校验。
2. 在同页逐项准备 0064、0065、0066、0067，依次冻结规则绑定、建立历史来源、升级期间结构和建立结算批次。仅允许版本、提交、固定脚本 SHA256、当前聚合基线指纹和业务原因，不接受 SQL、目标库、任意文件或个人权限授予。
3. 每一步执行前取得规则操作锁，并再次核验系统管理员真实身份、空账本、课程规则逐字段与确认口径一致、前序登记、当前实际结构和全部目标绑定（含非活动绑定）。STARTED 审计在首条 SQL 前持久化。
4. MySQL DDL 可隐式提交。结果未知、残缺结构、开始记录无完成登记均拒绝重放；刷新只读核验，随后根据实际状态采用独立前向修复。不会自动降级、清除台账或重跑。
5. 全部结构、绑定和课程引用完整后，按受控发布流程开启日常结算、生成批次、审批、正式入账四项配置，关闭本次准备及规则收口开关；保持启动自动迁移关闭。管理员页面显示实际存储和配置状态。

新入口为具有专项权限且真实数据库身份为 system_admin 的固定存储准备通道，与此前需独立迁移连接和签封材料的 CLI 入口并存。它不生成 CLI 授权、不伪造迁移 principal，也不绕过旧 CLI 的校验。执行须有用户对这次数据库规则准备的有效授权、正式提交 CI/MySQL 证据和迁移前备份。

## 运营使用

系统根据已提交的学习会、班级学习日、每日读书及优秀分享事实生成分值提案。运营人员在学分结算工作台选择来源、检查计算结果、提交复核并确认入账，学长查看已入账分值。开启配置不会自动重算所有历史事实，也不会跳过既有独立审批要求；期初 Excel 路径按用户已确认口径仍允许同人复核。

旧记录中不明确的课程确认、班级绑定、成员匹配、日期或重叠来源要先解决，不能为启用测试编造正式分数。已确认累计余额的截止日保护继续有效。黄埔一班历史分值及年度拆分使用真实来源单独核验，不扩大为其他班级的历史重算。

## 恢复

2026-10-11 实际准备发现：G5 收口按 JSON 内容保留 KEEP 规则，而原 0064 对 `aliases_json` 使用文本比较。三条旧规则含 JSON 分隔空格，内容相同但触发原 CHECK。固定格式修复入口只在一个既有 0064 开始记录、无持久结构/登记/映射/冻结引用、空账本、25 条语义一致规则且无后续尝试时开放；在操作锁内核验提交、原脚本哈希及含原始别名格式的指纹。只规范 JSON 编码，保留数组内容和顺序、原始开始记录及前后审计，再执行原哈希固定脚本。修复也独立持久化开始记录，结果未知拒绝再次执行。任何真实规则差异或已存在持久结构不适用此恢复入口。

配置异常时关闭正式入账和结算开关；关闭不能撤回已产生的账本。既成事实保留审计，按对账和追加冲销处理。结构准备中断后保留审计与已提交 DDL，依据实际结构前向修复，不删除事实或授权来强制降级。独立 MySQL 测试证明固定 SQL 顺序、冻结全部目标绑定、账本不变和 DDL 中断持久拒绝重放；原有迁移恢复测试继续执行。

实际格式修复已完成，但原脚本在第 2 条 `CREATE TEMPORARY TABLE` 因应用数据库账号权限返回 MySQL 1044；未产生持久结构。固定托管 MySQL 前向入口只接受这一已审计失败状态、两个原始开始记录、已完全一致的规则内容/编码、空账本及无持久结构/映射/冻结引用。额外固定脚本位于 `migrations/operations/0064_managed_mysql_forward.sql`，不进入启动迁移发现；其 SHA256 为 `9f72ff890dde3a6eac2f32f98cf2c13960b29b51b6685fc07aaf6e4bd42ef3e7`。服务在操作锁内逐字段验证全部 25 条课程规则、版本身份、6 条通用规则及类别，再按原脚本的持久结构与绑定 SQL 完成前向准备，结束后再次逐字段核验。保留独立 STARTED/完成/失败审计并登记原 0064 完成状态；不重新执行原临时表流程，不授予生产数据库账号新权限，任何残缺 DDL 或未知结果均拒绝重放。隔离 MySQL 用只有当前 schema 读写/建表/改表权限且无临时表权限的临时测试 principal 验证全链路，测试后删除该测试 principal。
