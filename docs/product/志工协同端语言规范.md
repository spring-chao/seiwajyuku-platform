# 志工协同端语言规范

- 版本：V1.0
- 日期：2026-07-29
- 状态：业务原则已确认

## 价值基线

志工首先是学长，是基于认同和利他之心承担服务的同行者，不是接受公司式派工和绩效考核的雇员。产品语言统一遵循：

> 尊重、温暖、利他、清晰。

责任不能弱化，表达应更温暖；要求不能含糊，语气应更尊重。

## 志工端建议栏目

- 我的担当
- 待协力事项
- 今日关怀
- 我的班级／小组
- 学习与活动
- 服务日历
- 同行协力
- 我的服务足迹

欢迎语建议：

> 感谢您的用心担当，让我们一起为学长的成长和幸福协力。

## 服务邀请

学长关怀建议：

> 诚邀您协力一项学长关怀事项。希望在建议时间前与学长取得联系，了解近期学习和生活情况，并记录需要进一步协助的地方。感谢您的用心担当。

签到异常建议：

> 有一条签到信息需要协助确认。这条记录暂时无法与正式学长档案匹配，诚请您根据班级实际情况协助核实。

续费关怀遵循：

```text
了解近况 → 倾听感受 → 识别困难 → 提供帮助 → 确认继续学习意愿 → 办理续费
```

## 志工自主选择

志工收到服务邀请后，应能够：

- 接受担当；
- 邀请同行伙伴协力；
- 申请调整建议完成时间；
- 说明暂时无法参与；
- 向运营中心反馈困难；
- 记录服务过程与结果。

系统不能把拒绝或调整自动解释为态度问题，也不应公开展示个人未完成数量。

## 禁用与慎用表达

志工端禁用：强制指派、绩效考核、催缴、处罚、末位排名、未达标人员、驳回失败。

慎用：使命、奉献、牺牲、必须担当、无私。这些词不作为日常按钮和系统压力提示。

## 验收要求

1. 志工端菜单、按钮、通知和空状态不出现禁用表达。
2. 同一底层事项在运营中心端和志工端正确显示不同文案。
3. 时间、责任、服务对象、进展和结果仍然清楚。
4. 志工可以接受、协力、调整或说明无法参与。
5. 不建立志工公开绩效排名。
6. 文案集中管理，页面不散落硬编码。
