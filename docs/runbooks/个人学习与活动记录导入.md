# 个人学习与活动记录

## 展示口径

小程序“我的成长”分别展示本人最近三条学习、活动明细及次数；“查看全部”进入个人记录页，按全部年份或某一年查看分类次数和分页明细。“我的学习”继续保留当前学习安排与学习会登记入口。

学习记录只包含学习会、班级学习日、小组学习会、开班、课程。报告会、游学、董事会、理事会、志工服务、新学员见面会等归活动记录。明确的志工服务记录即使标题出现“课程”“开班”，仍表示服务参与。报名、空白签到、取消的场次不作为已参加记录。

`GET /api/v1/wechat/participation-history` 接受 `kind=learning|activity`、可选四位 `year`、`page`、`page_size`（1至50）。学员由绑定会话解析；客户端不能指定另一个学员。次数按所选年份全部记录计算，分页不会改变总次数；三个事实来源（正式签到、已提交学习会、历史活动事实）先核对重复再分类分页。旧 `/learning-summary` 保留学习安排和最多20条学习记录。

## 本地历史表整理

使用 `scripts/prepare_participation_workbooks.py` 读取2025、2026活动表和人员档案。该工具只读取本地文件，不连接数据库，也不修改原表。

```powershell
python scripts/prepare_participation_workbooks.py `
  --workbook-2025 '<2025年活动统计.xlsx完整路径>' `
  --workbook-2026 '<2026年活动数据.xlsx完整路径>' `
  --roster '<8月人员.xlsx完整路径>' `
  --output-dir '<本次本地复核输出目录>'
```

输出候选CSV、问题清单和汇总JSON。输出不包含手机号、财务、公司资料和原始备注。来源文件、工作表、行号保留用于复核。月度计次矩阵不再展开为逐场明细，避免与签到表重复；只有月份的记录保留原精度，不能编造活动日期。

人员档案行号只用来定位本地资料，不能当作平台学员ID或编号。正式导入前，核对平台现有的稳定 `member_code`，按工具要求提供绑定人员档案校验值的一对一映射，再使用 `--member-map` 生成不含姓名、手机号的事实包。姓名、所属分中心、班级冲突及疑似重复仍留在问题单，不能依次取首项或凭姓名猜测。

## 受控导入与验证

事实包使用 `source_system=activity_workbooks`，复用已有 `/api/v1/legacy-operations/preview` 与 `/apply`。新增来源使用独立的分类契约，不扩张旧 `seiwajyuku_system` 包的七种来源。旧权限、二次确认、原因和审计保持生效；任何未找到的学员编号会阻止工作簿包正式导入。相同事件使用稳定来源标识，重复预览会报告已存在记录，相同包不能重复应用。

依照工程工作流，生产人员核对与批量写入需核验相应对象、接口、范围的明确授权。本地候选及代码交付不表示已经查询、写入生产。只使用有权限控制的接口核对人员，不直接连接生产数据库。

获批执行前审阅预览中的匹配、重复、未匹配数量与来源校验值；保留目标提交、事实包校验值、原数据库备份/恢复入口和预览报告。导入后按返回的 `batch_id` 核对事实数及小程序两类总次数。恢复应按批次核验依赖后制定方案，不执行无边界删除，也不更改学分、班级归属或权限。

## 验证入口

- 小程序：`node scripts/run_node_tests.mjs miniprogram`、`node scripts/check_wechat_miniprogram.mjs`。
- 后端：个人历史、旧学习汇总、工作簿导入及提取脚本行为测试。
- 隔离MySQL：CI的 `learning-credit-mysql` 已纳入个人历史和工作簿导入测试；本地SQLite不能代替该结果。
- 微信原生编译、真机界面及真实身份验收需另外记录结果，源码语法检查不能充当真机通过证明。
