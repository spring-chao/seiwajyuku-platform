# 任务 3：多角色 IAM、组织范围与审计

## 已实现

- 用户、角色、权限、多角色有效期和组织数据范围分离；
- `ALL`、`SUBTREE`、`UNIT` 三种组织范围；
- 系统管理员与数据安全管理员权限分离，系统管理员不默认拥有敏感导出权限；
- Argon2id 密码派生、短期访问令牌、刷新令牌哈希存储和令牌版本失效；
- 所有 API 使用服务端权限依赖，不依赖前端菜单隐藏；
- 登录、用户创建等关键操作写入审计日志；
- SQLite dev/test 与 MySQL staging 分别提供迁移。

## 验收

1. 系统管理员登录后可创建区域角色和班级角色；
2. 区域角色只看到授权分中心子树；
3. 未授权用户访问 IAM、审计或其他组织返回 403 或不返回数据；
4. 数据安全管理员可拥有 `exports:sensitive`，系统管理员默认没有；
5. 禁用账户或提升 `token_version` 后旧令牌失效。

## 回滚

- 回退应用提交；
- 在 staging 备份后按外键逆序删除 IAM 表；
- 不修改旧系统 `portal_users`，因此旧系统登录可继续独立运行。
