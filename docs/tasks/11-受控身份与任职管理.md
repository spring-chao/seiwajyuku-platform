# 任务卡 11：受控身份与任职管理

- 日期：2026-07-29
- 状态：代码与隔离 MySQL CI 已完成，待只读灰度批准与真实账号试点验证
- 生产状态：未启用、未迁移真实人员、未修改生产权限

## 目标

在 0011 纯新增身份模型上提供可审计的管理能力，使管理员能够在明确业务依据下：

1. 将系统账号关联到独立自然人档案；
2. 建立苏州分中心运营中心雇佣和专职岗位；
3. 单独记录对三级分中心、班级或小组的服务责任范围；
4. 建立有组织范围和任期的志工任职；
5. 建立有用途和任期的技术管理员职责；
6. 停用、结束或撤销记录，同时保留历史和审计。

## 双门禁

- `IDENTITY_AUTHORIZATION_ENABLED=false`：默认不读取新身份授权来源。
- `IDENTITY_ADMIN_WRITES_ENABLED=false`：默认禁止身份管理写入。

写入必须同时开启两项。生产环境还必须满足既有 `ALLOW_PRODUCTION_MUTATIONS=true` 明确批准；否则启动检查和服务层都会拒绝。

## API

所有接口均要求 `iam:manage`：

- `GET /api/v1/identity-admin/catalog`
- `GET /api/v1/identity-admin/accounts`
- `GET /api/v1/identity-admin/org-options`
- `POST /api/v1/identity-admin/accounts/{user_id}/initialize`
- `POST /api/v1/identity-admin/accounts/{user_id}/employments`
- `POST /api/v1/identity-admin/accounts/{user_id}/volunteer-appointments`
- `POST /api/v1/identity-admin/accounts/{user_id}/technical-assignments`
- `POST /api/v1/identity-admin/assignments/{type}/{id}/status`

写入接口必须提供确认依据和业务确认说明。系统不提供按姓名、手机号或旧角色自动匹配，也不提供物理删除接口。

## 管理端

新增“身份与任职”页面，仅 `system_admin` 和 `technical_admin` 显示：

- 展示账号是否已确认自然人关联；
- 分开展示运营中心雇佣、岗位、服务责任、志工任职和技术任期；
- 明确提示“服务责任范围不是组织归属”；
- 写入开关关闭时页面只读、按钮禁用；
- 停用、结束、撤销时要求填写原因；
- 不展示手机号、企业、财务或学长敏感资料。

## 审计动作

- `identity.person.link`
- `identity.employment.create`
- `identity.volunteer_appointment.create`
- `identity.technical_assignment.create`
- `identity.<assignment_type>.status_change`

审计保存内部 ID、岗位或任职键、组织 ID、范围、期限、确认依据和变更原因，不保存密码、完整手机号或其他业务敏感内容。

## 验收边界

- 不创建或修改真实生产人员记录；
- 不自动迁移旧角色；
- 不改变 `members`、`member_org_relations`、签到事实或现场扫码链路；
- 不开放生产灰度开关；
- 下一张任务卡再实现志工接受担当、邀请协力、申请调整和暂无法参与的服务邀请状态机。
