# 任务 13：旧盛和塾运营管理系统合并

状态：第一批数据承接能力已实现，待只读预检与受控正式迁移。

## 目标

将 `seiwajyuku_system` 中仍有长期价值的业务事实迁入统一平台；不把旧界面、旧单角色权限、名称文本组织关系、公开排行榜或未经核验的自动评分继续带入新平台。

## 功能承接清单

| 旧系统能力 | 统一平台承接方式 | 当前状态 |
| --- | --- | --- |
| 年度/月度 MP | 年度 MP 看板、月度填报、导入批次 | 已承接 |
| 学员主档 | 学员管理、组织 ID 关系、编辑/变更历史/合并 | 已承接 |
| 组织与名册 | `org_units`、`member_org_relations`、全量班级小组迁移 | 已承接 |
| 签到与活动 | 活动组/场次/记录、签到同步、复核和两种比例 | 已承接 |
| 账号与权限 | 多角色 IAM、身份/雇佣/岗位/志工任职 | 已承接；旧账号不自动迁移 |
| 续费 | 正式续费周期、责任人、跟进和导入回滚 | 已承接 |
| 七类历史活动事实 | `member_activity_facts` + 学员档案时间线 | 本任务第一批 |
| 企业画像、服务时间线 | 学员详情、企业敏感查看、关怀/走访/续费时间线 | 已有底座，继续完善 |
| 规则信号与建议 | 规则版本、证据和人工反馈 | 后续批次 |

## 第一批合并范围

只迁移以下七类结构化事实：

- 小组学习会；
- 班级学习会；
- 课程；
- 报告会；
- 游学；
- 读书打卡；
- 读书分享。

匹配只使用稳定 `member_code`。组织归属使用统一平台当前正式组织 ID，不接受旧系统的中心、班级和小组名称覆盖。

## 隐私与产品边界

- 合并包不含姓名、手机号、备注、心得、分享原文、评价、反馈、财务资料或账号权限；
- 导入器遇到上述字段直接拒绝，而不是静默忽略；
- 只保存活动日期、类型、参与状态、标题、时长和来源标识；
- 原始合并包不进入数据库，批次只保存哈希、计数和隐私契约；
- 不迁移旧综合评分、公开排行榜和以分数给学长贴标签的逻辑；
- 现场扫码、二维码、签到写入路径保持不变。

## 执行流程

1. 在隔离环境使用 `scripts/export_legacy_operations_bundle.py` 生成隐私安全 JSON 合并包；
2. 调用 `POST /api/v1/legacy-operations/preview` 完成只读匹配预检；
3. 核对可迁移数、缺失学员编号、未匹配学员和重复事实；
4. 备份统一平台数据库并在 staging 执行正式合并；
5. 抽查学员“档案时间线”，核对七类活动数量；
6. 取得业务批准后才在生产短时开启写入并应用同一 SHA-256 合并包；
7. 合并后立即恢复只读门禁。

## 回滚

- 数据批次可通过 `import_batch_id` 精确识别；
- 业务回滚应先删除该批次的 `member_activity_facts`，再把对应 `import_batches` 标记为已回滚；
- 架构回滚脚本为 `migrations/rollback/*/0018_legacy_member_activity_facts.down.sql`，只允许在已验证备份或一次性克隆库执行；
- 回滚不修改学员主档、组织关系、签到记录、续费数据或 IAM。

## 后续批次

1. 只读预检旧库真实数量并形成逐表核对报告；
2. 迁移成功后将旧系统切为只读历史查询；
3. 完成一个业务周期的并行核验后，下线旧 Streamlit 管理入口；
4. 在统一平台实现有证据、可解释、不可公开排名的个人画像信号。
