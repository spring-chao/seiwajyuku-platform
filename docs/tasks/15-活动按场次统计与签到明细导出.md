# 任务 15：活动按场次统计与签到明细导出

状态：已实现；本次补充签到质量字段、异常时间保护和按月复核范围，待发布验证。

## 背景

签到系统将同一活动组下的上午、下午、空巴等场次分别保存。原运营平台活动列表按活动组汇总，导致一个“班级学习会 - 晚上空巴”行同时显示多场次的报名人数、参会人数和参会率，无法反映单个场次的真实情况。

## 本阶段口径

- 活动列表一行对应一个 `attendance_session`，不再把同一活动组的多个场次合并成一行；
- 报名人数 = 当前场次签到报名记录数；
- 参会人数 = 当前场次 `PRESENT` 与 `MANUAL_PRESENT` 记录数，包含非塾生；
- 签到率 = 当前场次参会人数 ÷ 当前场次报名人数；
- 班级活动参会率 = 当前场次参会人数 ÷ 当前班级在册人数；
- 报告会等大型活动参会率 = 当前场次参会人数 ÷ 分中心在册人数；
- 组织关系、班级参会率和分中心参会率继续按组织 ID 查询，不回退名称文本或旧系统；
- 旧的 `/attendance/event-groups` 活动组汇总接口保留，供活动组详情和兼容调用使用。

## 交付内容

1. 新增 `GET /api/v1/attendance/activity-sessions`，返回带 `display_title` 的场次级统计；
2. 活动列表切换为场次级数据，标题按“活动 · 场次”展示；
3. 活动明细按用户从列表选中的场次加载签到记录；
4. 新增 `GET /api/v1/attendance/event-groups/{group_id}/records.xlsx`，支持传入 `session_id` 下载当前场次签到明细；不导出手机号、备注和其他敏感字段；
5. 明细窗口增加“下载签到明细 Excel”按钮；
6. 增加场次拆分、统计口径和 Excel 表头自动化测试。
7. 签到明细和 Excel 均显示迟到、早退、积分；移除没有运营价值的“来源”字段；
8. 对早于场次明确开放时间的来源签到时间，界面和 Excel 均标为“待核对”，不将其当作可信签到时间；不修改签到源记录；
9. 活动页面选择月份后，活动列表、数据复核待办汇总、待办明细和分中心汇总全部按同一活动月份筛选。

## 安全与部署边界

- 新接口只读，继续要求 `members:read`；
- 不修改签到扫码链路、`/event`、`/checkin` 或任何生产签到记录；
- 生产部署继续保持 `DEPLOYMENT_READ_ONLY=true`、`ALLOW_PRODUCTION_MUTATIONS=false`；
- Excel 仅包含活动、日期、场次、姓名、学员编号、参与类型、状态、签到时间、迟到、早退和积分；不包含来源、手机号、备注或其他敏感字段。
