# 任务 16：学员服务提示人工反馈与审计

状态：代码、GitHub CI、生产 0019 迁移、API 灰度发布和管理端静态发布已完成。生产反馈开关保持关闭；待运营人员完成真实页面只读验收，并明确真实账号试点范围、周期、业务负责人和回滚责任人后，才可申请反馈写入窗口。

## 目标

在任务 14 的只读、可解释服务提示基础上，允许有学员维护权限的运营人员对当前仍然成立的提示提交结构化反馈，并保存当时的规则版本、脱敏证据快照和审计记录。

本任务用于校正规则和业务口径，不评价学长，不形成分数或排名，也不自动创建关怀任务。

## 反馈选项

| 反馈 | 说明 |
| --- | --- |
| 确认有效 | 当前提示符合业务事实，可以继续作为运营提醒 |
| 暂不适用 | 当前规则命中，但结合已核验的业务情形暂不适用 |
| 数据已修正 | 运营人员已完成资料修正；系统仍以实时规则结果决定提示是否继续显示 |

反馈不覆盖、不删除历史记录。再次反馈会追加一条新记录，页面只展示相同规则版本下的最新一次反馈。

## 数据与权限边界

- 新表 `member_service_signal_feedback` 只保存学员 ID、组织 ID、规则代码、规则版本、反馈状态、脱敏证据 JSON、操作人和时间；
- 证据仍只允许布尔值、数量和日期，不保存手机号、姓名、备注、企业资料或任务原文；
- 提交反馈要求 `members:manage`，并再次校验学员是否在当前账号的正式组织范围内；
- 只能对当前仍然命中、且规则版本一致的提示反馈；提示已失效或版本变化时要求刷新；
- 每次反馈同步写入 `audit_logs`，审计只记录规则元数据和证据字段名，不复制敏感内容；
- 提示反馈不改变学员档案、组织关系、关怀事项、续费周期、签到事实或现场扫码链路。

## 上线门禁

- 新开关 `MEMBER_SERVICE_SIGNAL_FEEDBACK_ENABLED` 默认 `false`；
- 开关关闭时，任务 14 的只读提示继续正常工作，不查询反馈表，也不显示反馈按钮；
- 生产环境未设置 `ALLOW_PRODUCTION_MUTATIONS=true` 时，禁止开启反馈开关；
- 生产只读中间件不放行反馈接口；迁移、开关和写入窗口必须分别核验；
- 2026-08-10 已按单独批准完成生产迁移与部署；本次批准不包含真实账号试点或生产反馈写入。

## 验收场景

1. 有 `members:manage` 且在组织范围内的账号可以提交三种反馈；
2. 页面显示最新反馈状态和时间，历史记录保持追加；
3. 只读账号、范围外账号、失效提示和旧规则版本被拒绝；
4. 反馈表证据和审计日志不含手机号、备注、姓名或服务原文；
5. 开关关闭时页面保持“规则只读”，任务 14 的实时提示不受影响；
6. SQLite 前向与回滚脚本通过，MySQL CI 完成建表、备份恢复与逆序回滚验证；
7. 前端类型检查和 staging 构建通过。

## 后续阶段

1. 运营人员使用生产账号完成学员时间线“服务提示（只读）”的视觉与业务口径验收；
2. 由业务负责人选定少量真实账号、组织范围和试点周期，并明确回滚责任人；
3. 单独批准反馈写入窗口后，临时开启生产写入与反馈开关，进行短时、可回滚试点；
4. 试点结束立即关闭写入门禁并核对审计和反馈分布；
5. 只有真实账号试点稳定后，才评估“一键创建关怀任务”，且必须保留人工确认。
