# 任务 17：学员服务提示只读验收与数据质量收口

日期：2026-08-12  
状态：规划中  
优先级：P0 运营收口

## 目标

在不新增生产写入、不启用身份与任职写入、也不启用服务提示反馈开关的前提下，完成学员服务提示的真实页面验收，并将已知数据质量事项形成可分派、可核对、可回溯的处理清单。

本阶段只做“发现、核对、回到既有入口维护”的闭环：

- 学员资料问题回到“学员管理”维护；
- 关怀到期事项回到“关怀跟进”处理；
- 到期续费事项回到“续费运营”处理；
- 签到未匹配或时间异常仍在“活动与签到”的数据复核中处理；
- 不根据姓名、手机号或旧系统文本自动猜测并写入组织、身份或任职。

## 当前基线

以下为已发布规则和历史只读聚合的待核对基线，开始执行前需重新读取当前生产聚合，不能将其视作实时数量：

| 类别 | 历史基线 | 处理入口 |
| --- | ---: | --- |
| 联系方式待核对 | 44 人 | 学员管理 |
| 学习班关系待核对 | 105 人 | 学员管理 |
| 签到未匹配 | 276 条 | 活动与签到 → 数据复核 |
| 无小组关系 | 192 人 | 学员管理（仅在业务确认需要时） |

续费正式生产台账已完成真实“查看—修改—保存”验收，不重新做技术探针；本阶段仅确认服务提示能正确跳转或指向续费运营。

## 执行步骤

1. 由具备学员维护权限的运营人员抽取不超过 10 条真实学员档案，覆盖四类提示各至少 1 条；若某类当前无命中，记录为“当前无样本”。
2. 对每条样本核对提示标题、说明、证据摘要和建议动作：不得出现完整手机号、备注、企业资料、服务原文或排名性文字。
3. 核对提示与实际业务状态一致：
   - 联系方式、学习班关系：回到学员管理核对；
   - 关怀事项：回到关怀跟进核对状态与到期时间；
   - 续费节点：回到续费运营核对当前周期状态与到期月。
4. 在“活动与签到”选择当前运营月份，抽查数据复核队列的未匹配与“待核对”签到时间；确认不在此阶段以技术探针修改签到数据。
5. 建立仅含内部编号、问题类型、现状、确认来源、建议处理入口、处理责任角色和复核日期的处理清单。清单不得包含完整手机号、企业资料或原始跟进文本。
6. 由业务负责人确认每一类问题的处理口径。需要修改学员主档时，仅在学员管理逐条维护；需要调整身份、任职或权限时，转入下一阶段候选确认，不在本任务写入。
7. 复核处理后的提示是否随实时主数据自然变化；不启用反馈按钮，不保存规则反馈。

## 验收标准

- 真实页面能展示服务提示，且四类规则与业务入口一致；
- 提示证据与页面文案不泄露敏感资料，不形成个人评分或排名；
- 数据质量清单可按问题类型、处理入口和责任角色汇总；
- 任何学员资料修改均从学员管理进入，续费信息均从续费运营进入；
- 签到扫码路由 `/event`、`/checkin` 与工作日同步不变；
- 生产环境保持 `identity_admin_writes_enabled=false`、`volunteer_service_invitations_enabled=false`、`member_service_signal_feedback_enabled=false`；
- 不以修改真实记录作为技术验证手段。

## 不在范围内

- 启用服务提示人工反馈或创建反馈记录；
- 创建真实身份、雇佣、岗位、志工任职或技术职责；
- 自动补全手机号、班级、小组或组织关系；
- 批量修改签到记录、重新导入旧系统数据或变更现场签到链路。

## 完成后的下一阶段

仅当本任务完成并且业务负责人已逐项确认真实试点的人员、组织范围、任期、确认依据与回滚责任人后，才能进入“身份与任职真实账号隔离试点”。该阶段需要单独批准身份相关生产写入窗口。
