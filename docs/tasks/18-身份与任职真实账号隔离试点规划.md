# 任务 18：身份与任职真实账号隔离试点规划

日期：2026-08-12  
状态：规划中  
优先级：P1 权限与协同试点  
前置任务：任务 17 已完成服务提示只读验收与数据质量处理口径确认

## 目标

在隔离环境中，以已获业务确认的小范围真实账号完成身份、任职、组织范围和最小权限的登录验收。验证通过后，只形成是否申请生产短时配置窗口的证据；本任务本身不在生产创建或修改自然人、雇佣、岗位、志工任职、技术职责、旧角色或数据范围。

## 试点范围

每类仅选择业务事实清晰、没有权限争议的最小样本：

| 样本 | 数量 | 要验证的边界 |
| --- | ---: | --- |
| 运营中心专职 | 1 个账号 | 运营中心雇佣、一个或多个岗位、对一个三级分中心或班级的服务责任范围 |
| 三级分中心 | 1 个 | `UNIT` 与 `SUBTREE` 范围的可见性差异 |
| 班级 | 1 个 | 班级范围不扩大到其他班级或分中心 |
| 担当志工 | 1–2 个账号 | 有期限的志工任职、服务邀请接受与暂不可参与 |
| 同行志工 | 1 个账号 | 仅在有效范围内协力记录，不查看完整联系方式、不关闭事项 |
| 技术管理员 | 1 个账号 | 仅 IAM、审计与技术配置；无学员、续费、关怀、敏感导出权限 |

`admin` 仅保留平台最高管理账号标识，不作为自然人、雇佣岗位或技术职责自动迁移样本。

## 逐项业务确认清单

业务负责人必须逐项提供并确认以下信息；使用内部账号标识或脱敏别名，不在任务文档、日志或验收报告中记录密码、完整手机号或无关个人资料：

| 字段 | 要求 |
| --- | --- |
| 账号标识 | 已存在的试点账号内部标识或脱敏别名 |
| 身份类别 | 运营中心专职 / 学长志工 / 技术管理员 |
| 自然人关联依据 | 已确认的业务依据编号；不得按姓名、手机号或旧角色猜测 |
| 雇佣或志工任职依据 | 任命文件、审批单、会议决议或确认编号 |
| 岗位或任职键 | 从只读权限矩阵的有效模板中选择 |
| 任职组织与范围 | 稳定组织 ID，明确 `UNIT` 或 `SUBTREE`，并说明服务责任不等于组织归属 |
| 起止时间 | 明确起止时间；志工与技术职责不得无限期 |
| 业务负责人 | 对身份事实和范围负责的人 |
| 回滚责任人 | 试点结束、撤销或异常时负责停用和核对的人 |

任一字段缺失或存在争议时，该账号不进入试点，也不以临时扩大权限替代确认。

## 隔离环境边界

- 使用独立、可销毁的 SQLite 或隔离 MySQL 数据库；不得连接生产数据库、旧系统数据库或签到生产数据；
- 从生产复制时只允许使用经批准、最小化且去标识化的组织结构与测试数据；真实账号不得导入密码哈希；
- 所有试点账号密码由隔离环境变量提供且不记录在仓库、任务卡、日志或长期记忆；
- `IDENTITY_AUTHORIZATION_ENABLED=true`、`IDENTITY_ADMIN_WRITES_ENABLED=true`、`VOLUNTEER_SERVICE_INVITATIONS_ENABLED=true` 仅可用于隔离试点环境；
- `APP_ENV` 只能为 `dev`、`test` 或 `staging`，且 `ALLOW_PRODUCTION_MUTATIONS=false`；
- 试点结束后销毁隔离数据库或按隔离备份策略回滚，不影响生产 `user_roles`、`data_scope_grants`、学员主档、组织关系、续费或签到事实。

## 验收路径

1. 管理员在隔离环境建立已确认的自然人关联、雇佣/岗位、服务责任、志工任职和技术职责；逐项核对审计记录。
2. 专职账号登录，验证运营中心岗位不依赖三级分中心组织归属；分别检查无范围、`UNIT` 与 `SUBTREE` 的最小可见性。
3. 志工账号登录，验证仅能访问有效任职范围内的学员、关怀、续费和活动；确认邀请可接受、建议调整或暂不可参与。
4. 同行志工验证仅能协力记录，不能查看完整联系方式、企业敏感资料，亦不能结束服务事项。
5. 技术管理员验证不能进入学员运营、续费运营、关怀跟进、敏感导出和服务事项数据。
6. 将一项测试任职设为临近到期、暂停或撤销；确认 `/api/v1/me` 中角色与范围立即消失，历史与审计保留。
7. 回归年度 MP、学员管理、关怀跟进、续费运营、活动与签到；确认 `/event`、`/checkin` 与工作日零点同步未受影响。
8. 试点结束后关闭三个隔离开关、停止环境并执行数据库销毁或回滚演练。

## 验收标准

- 所有试点账号的可见范围符合已确认的任职组织、范围与任期；
- 技术管理员和同行志工的敏感数据隔离有效；
- 关联、任职创建、状态变更和邀请回应均有必要审计，审计不含密码、完整手机号或服务原文；
- 状态撤销后授权立即失效，历史记录保留；
- 无生产数据库连接、无生产身份或权限写入、无旧角色替换；
- 完成隔离环境回滚演练及既有业务回归。

## 生产进入条件

隔离试点稳定至少一个业务周期后，才可单独提出生产短时配置窗口申请。申请必须明确：准确账号范围、逐项确认依据、待创建记录、时间窗口、数据库快照、验证人、回滚责任人，以及恢复 `IDENTITY_ADMIN_WRITES_ENABLED=false` 的时点。

即使生产业务写入当前已启用，也不构成身份、任职或志工写入授权；相关生产写入须在当次任务中获得明确批准。

## 不在范围内

- 生产迁移或生产身份、岗位、志工任职、技术职责写入；
- 角色申请页面或面向全员的自助角色申请；
- 自动按姓名、手机号、旧角色或旧归属字段匹配人员；
- 扩大试点到全部账号、全部分中心或全部班级；
- 修改签到现场路由、历史签到事实或续费主数据入口。
