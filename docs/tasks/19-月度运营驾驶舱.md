# 任务 19：月度运营驾驶舱

## 产品判断

年度 MP 看板用于回答“目标、预定、实绩之间有多少差距”，不能替代日常运营驾驶舱。运营驾驶舱应同时保留两层：

1. 月度运营实况：自动汇总本月续费、新增、在册、生日、班会、课程与活动；
2. 年度 MP 追踪：继续展示年度目标、月 MP、预定、实绩和差额。

驾驶舱不新增人工填报入口。能从业务数据库计算的指标自动计算；没有可靠事件级数据源的指标显示“未接入”或“待排期”，不把缺失数据伪装成 0。

## 指标口径

| 指标 | 唯一来源 | 口径 |
| --- | --- | --- |
| 本月续费 | `renewal_status_history`、`renewal_cycles` | 本月从其他状态变为 `RENEWED` 的去重学员数；首次导入且没有真实状态变更时间的历史已续费不冒充本月实绩 |
| 本月新增 | `members.join_date` | 入塾日期落在所选月份的学员数；当前是否在册不改写历史新增事实 |
| 当前在册 | `members.status` | 当前状态为 `ACTIVE`；这是当前快照，不冒充历史月末快照 |
| 各分中心在册 | `members.org_unit_id` | 仅列正式区域分中心；直属学习班保留独立口径，不并入六个分中心，但仍计入苏州塾总在册 |
| 本月生日 | `members.birthday` | 当前在册且生日月份匹配；接口只返回姓名、分中心和月日，不返回出生年份 |
| 班会次数 | `attendance_event_groups` | 一个 `CLASS_MEETING` 活动组算一次；上午、下午、恳亲会等签到场次不重复计数；全无活动事件源时显示“未接入” |
| 班会次序 | `attendance_event_groups` | 按同一班级本年度活动日期排序，展示“本年第 N 次”；本月无活动组的班级展示“待排期” |
| 课程次数 | `attendance_event_groups` | `COURSE`、`STUDY_COURSE`、`SEMINAR` 活动组数；尚无课程事件源时显示“未接入”而非 0 |
| 其他活动 | `attendance_event_groups` | 排除班会和课程后的其他有效活动组数；全无活动事件源时显示“未接入” |

## 权限与组织边界

- 接口要求 `plans:read`，所有结果继续受 `accessible_org_ids` 组织范围限制；
- 学员可通过正式主归属、班级或小组关系进入授权范围，不使用姓名或文本班级做权限判断；
- 续费数字仅向拥有 `renewals:read` 的账号返回；无权限时返回不可用状态而不是 0；
- 不返回手机号、出生年份、企业敏感资料或关怀备注。

## 已知边界

- 当前系统没有可靠的历史月末在册快照，因此“在册”明确标注为当前快照；若以后需要追溯某月月末人数，应新增日快照或状态时态模型，不能反推当前主档；
- 旧系统迁移的个人活动事实不能证明有多少个不重复的活动，因此不用于驾驶舱活动次数；
- 课程排期必须形成统一平台活动组后才能进入驾驶舱。

## 验收

- 区域或班级账号看不到范围外学员、生日和活动；
- 同一班会包含多个签到场次时，驾驶舱仍只计一次；
- 本月无班会的正式班级显示“待排期”；
- 缺少入塾日期的在册学员进入数据质量提示，不计入新增；
- 无续费权限或课程数据源时显示不可用，不显示 0。
