# 学长同行记忆一期——生日关怀助手

## 目标

从运营驾驶舱的本月生日名单点击学长姓名，打开生日关怀助手：展示脱敏同行资料、只使用已核验的本人学习/活动事实形成共同记忆候选，并生成可人工编辑和复制的祝福草稿。

第一期不发送短信、不接入大模型、不新增数据库表、不写入生产数据。

## 已实现范围

- `GET /api/v1/members/{member_id}/birthday-greeting-context`
  - 复用学员主档与正式组织关系，返回生日月日、入塾日期、完整同行年限、分中心/班级/小组。
  - 只读取正式签到中 `PRESENT` / `MANUAL_PRESENT` 的本人记录，以及历史学习事实中 `PRESENT` / `COMPLETED` / `RECORDED` 的记录。
  - 按活动组去重，避免同一活动多个场次重复进入记忆；排除缺少日期的不可核验事实以及缺席、取消、作废记录；标题缺失时只使用已验证的活动类型通用名称。
  - 只返回特别经历、长期同行和学习活动候选，不读取手机号、企业敏感资料、续费周期、关怀备注或跟进叙事。
  - 按组织范围校验并记录审计；缺少入塾日期或活动事实时返回明确数据质量提示。
- `POST /api/v1/members/{member_id}/birthday-greeting-draft`
  - 接收人工勾选的 0～4 条已验证记忆和 `standard` / `warm` / `concise` 语气。
  - 只在内存中根据事实模板生成草稿，不持久化草稿、不发送消息；服务端再次校验记忆 ID 属于该学长的已验证上下文。
- 运营驾驶舱生日表中的姓名改为点击入口，打开“生日关怀助手”抽屉，支持勾选记忆、编辑文案、重新生成和复制。

## 事实与安全边界

- 活动类型或标题只用于选择“特别经历/长期同行”等展示分类，不能证明任职、担当或企业经营成就；没有正式任职事实时不生成担当类表述。
- `RECORDED` 仅表示历史活动事实已通过既有导入流程核验，不能扩展成电话、企业收入、续费意愿等其他事实。
- 草稿生成接口虽然使用 `POST`，但没有数据库写入；只读部署门禁将其作为受审计的内存操作放行。
- 现阶段生产环境仍需保持现有生产写入、身份写入和批量数据写入门禁关闭。
