# 学习会人工核实、预计学分与批量调组

用户于2026-10-12要求工作人员根据合影核实视频与参加人员，删减未参加者，查看每人本次预计学分并导出；在学员管理中提供班级重新开班后的批量调组入口。同日明确确认：未入账记录可核实，已入账记录保留来源并走更正流程。

## 使用

- 小组学习会详情可修正课程名单、参加名单，逐人确认“已观看／未观看／待确认”。登记状态与人工确认来源分别显示；新增参加者不会自动取得课程完成确认。
- 明细列出每人的小组会学分、课程学分、预计新增合计和未计分原因。计算复用正式结算预览，使用冻结规则及账本去重；页面和导出均不入账。
- 支持本场导出与当前日期、状态筛选导出，CSV带UTF-8 BOM，最多500场。只导出授权范围内的人员和计分明细，不导出手机号、合影或核实备注；保留导出审计并防范CSV公式注入。
- 学员管理新增“批量调整小组”：选班级、逐人安排或勾选人员统一调组、预览原／新小组、填写原因、整批保存。每次最多500名在册学员；新小组须事先创建。范围仅为本班有效小组，存在多条或不明确组织关系时先逐人处理。
- 调组沿用已有单人学员维护服务，在一个事务中更新正式组织关系、显示组名和变更历史。任何失败整批回滚，来源名单变化后须重新预览。历史学习会与学分保留原记录。

## 业务边界与发布

独立开关 `STUDY_MEETING_PRE_SETTLEMENT_REVIEW_ENABLED` 默认关闭。获批启用后，即使正式结算已开启，具备 `study_meetings:courses_edit` 或 `study_meetings:attendees_edit` 的授权人员仍可核实尚未入账且尚未进入审批的来源事实。原课程／参加人员开关仍保留原有默认边界。

已有任何对应账本记录（包括冲正记录）或结算批次进入审批、入账、部分失败、封账时，界面显示锁定原因，服务端拒绝课程、观看事实和人员修正。批次锁定读取与来源事务共同保护已冻结依据；尚处于DRY_RUN的来源可修改，其原批次必须通过既有指纹核验，来源变更后无法按旧提案入账。

不新增数据库结构，不改IAM角色授权，不关闭正式结算或启动自动迁移。生产发布只启用上述独立核实开关，保留其他运行配置和网络基线。普通导出需要普通导出和学分预览两项权限，其组织范围取交集；批量调组需要学员维护权限。

同时修复原结算预览SQL中课程总状态与逐人完成状态重名的问题：一人未观看不会让其他已确认观看者的课程预计学分归零。

## 验证

- 本地相关API与配置测试：67项通过，包含预计学分、逐人确认互不影响、删减人员、重复计分、导出范围与公式安全、已入账／审批／入账中来源锁定、批量调组范围校验、过期预览与事务回滚。
- 管理端类型检查、53项行为测试、staging构建通过；浏览器在独立测试库核验人工观看确认、预计学分联动、调组预览与保存。测试均使用合成数据。
- 两个新增接口测试文件纳入隔离MySQL CI，生产发布以前以目标提交的完整CI及实际线上核验为准。
