# 小组参会率与整场核实确认

在参加人数右侧增加“小组参会率”，仅使用本组参加人数作为分子，跨组参加人员不计入。分母为本组当前有效在册的 ACTIVE 学员人数（有效 STUDY_GROUP 关系、按学员去重），页面明确说明口径并同时展示“本组参加 / 在册人数”。当前分母为零或参加人数超过当前名单时显示“待核对”，不伪造 0% 或封顶 100%。这是当前名单口径，重组后须核对，不能作为历史在册快照。

学习会详情提供“确认核实”按钮，列表单独显示“已核实 / 待核实”，区别于“已提交”。确认覆盖当前展示的参加人员、课程、个人观看事实和合影记录，记录核实人及时间。按钮不会代替逐人观看确认，不改学分流水，也不触发结算。

复用现有学习会人员核实权限、组织范围、写入开关及入账保护。只有尚可修正的已提交学习会能够确认；已入账、审批或入账处理中继续走原更正流程。前后端均防止陈旧详情被确认，重复提交幂等。核实后人员、课程、观看事实或合影改变，恢复“待核实”；照片自然过期清理不会撤销核实记录。

确认事件及事实指纹使用现有 audit_logs 持久化，不增表、不执行生产迁移、不增加角色授权。新接口为 `POST /api/v1/study-meetings/records/{id}/review-confirmation`。

验证覆盖本组与跨组统计、在册及过期关系、零分母、确认留痕与幂等、修改失效、陈旧请求拒绝、权限范围、只读门禁和入账锁定；管理端覆盖重复提交、未保存编辑、详情切换及列表状态同步。
