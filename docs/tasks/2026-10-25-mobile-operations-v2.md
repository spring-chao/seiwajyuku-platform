# 运营专员小程序功能扩展

## 本轮范围

1. 今日行动的生日、续费入口展示可编辑并复制的微信文案；查看续费可按实际情况更新周期状态，保留状态历史及既有学员状态同步规则。
2. 按用户确认移除首页“关爱跟进”入口，保留学长详情中的关爱记录能力。
3. 增加小组学习会列表、参会率、本组/跨组/归组待核对人数、人员及课程完成明细、私有合影预览、核实后自动结算。
4. 增加活动列表、创建草稿、编辑名称/日期、确认或取消，以及现场临时报名。活动和报名直接复用独立签到引擎，临时报名不会被直接记为签到成功。
5. 将“待入数”暂按“待入塾申请”实现，支持查询、保存核对资料、通过/驳回、收款确认、正式入塾和脱敏申请摘要图片保存到相册。尚未增加上传付款凭证功能。
6. 增加月度运营驾驶舱，复用管理端数据概览的来源和缺失数据说明。
7. 修复签到现场仍显示学员改名前姓名的问题：按稳定学员 ID、编号或同一场次下已核验的报名关联显示主档最新姓名；搜索和脱敏导出同步使用最新展示姓名。原报名和实际参加人快照不被改写，不通过同名猜测关联。

8. 签到 Excel 增加三张表：签到名单（补全主档小组并增加班会小组参会率）、签到汇总（当前场次六项指标）、小组参会统计（本次班会日间场次合并去重）。百分比保存为数值并设置 Excel 百分比格式；缺少明确班级/场次关联或本班到场身份未核验时明确提示待核对。

## 复用规则

- 每次请求重新解析有效的工作人员身份及 IAM2 授权。读、审核、收款、入塾、普通导出、活动创建/修改/管理及结算的组织范围分别验证。
- 学习会参会率使用现行 `study_membership` / `study_meeting_review` 的当前有效归组口径；跨组和归组待核对人员单列。
- 核实结算调用 `confirm_and_settle_meeting_review`，沿用核实、批次、正式入账及重试校验。核实已保存而结算未完成时，分别反馈两项结果，不使用退休的直接入账路径。
- 活动操作使用 `signin_engine` 和现有 `attendance_manage.perform`，保留上游门禁和审计。远端创建/报名结果不确定时，保留待核对意图，禁止相同请求再次发起远端写入。
- 续费和申请变更校验所查看的状态/版本，拒绝覆盖他人更新。
- 所有新增页面离开时清理私有数据；身份变化后忽略迟到响应和旧确认框。合影预览兼容 HTTP 及 CloudRun 传输，临时文件在页面离开时清理。
- 无新增数据库表、迁移、默认角色权限或生产开关变更。

## 已执行验证

- 小程序测试：269 项通过；JS、JSON、正式 AppID/域名配置检查通过。
- 管理端相关签到测试：27 项通过（含生成 XLSX 后重新读回的工作表、数值和百分比格式验证）；类型检查和 staging 构建通过。
- 后端完整回归：1721 项通过、42 项跳过；覆盖姓名同步、稳定身份关联、分项授权、远端不确定结果、小组日间去重、核实结算及申请审核。
- 六个页面使用合成数据进行浏览器布局预览，390px 宽度未发现横向溢出。这不等同于微信开发者工具编译和真机验收。

## 交付核验

代码合并、目标提交 CI、生产部署和微信上传/真机验收分别记录，以实际执行结果为准。没有查询或修改本次用户提到的真实学员生产记录。
