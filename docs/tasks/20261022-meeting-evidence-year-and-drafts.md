# 小组学习会合影、年度学分与未完成提交修复

## 问题与处理

- 手机压缩不保证输出 JPEG；旧客户端把非 PNG 内容一律标为 JPEG。按真实文件头传 MIME，服务端兼容静态 WebP/BMP 并转为干净 JPEG，保留单帧、大小、像素和隐私校验。格式错误持久显示，避免统一误提示网络问题。
- 登记先建 DRAFT，再上传合影，最后提交。上传失败时保留同一草稿以重试，不代表已经提交。后台显示“待完成提交”，创建时间与实际提交时间区分。合影齐全时，原核实权限范围内可完成提交、核实并自动结算；缺合影不能绕过，给出补传提示。保留操作人审计、内容指纹、幂等和正式入账权限。
- 以往年度归属在缺少初始学习日或人工进度基线时全部留空。已有核定进度仍按十二次实际学习日规则计算；无法建立历史进度时，使用小组学习会同一班级绑定、有效周期及已发布计划的年度。周期或绑定不一致、日期跨年度或无法核验的历史总分仍待补充，不把历史累计分强行归入当前年度。修正 SPECIAL_COHORT 被误取为上级分中心的问题。
- 当前年度是否已知与完成学习日次数是否已知分别显示，避免年度已知仍显示“待配置”。历史未分配且无法证实的年度零分显示待补充。

## 验证范围

本地隔离 API：合影格式/隐私/多帧、草稿资料门禁、过期指纹、组织权限、后台完成提交后自动结算及重复确认、年度历史与反向冲销、原始绑定日期与计划年度回退。
管理端类型检查、行为测试、构建；小程序行为测试和配置检查。正式发布需目标 main CI 九项通过及 MySQL 集成结果，随后核验候选和线上版本。
