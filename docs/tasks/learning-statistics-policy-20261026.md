# 学习参与统计统一、精进组豁免与月度归组

日期：2026-10-26。组件：主平台 API、管理端、小程序及现有维护云函数；活动仓库 `.codex-worktrees/mobile-operations-v2`。分支 `codex/learning-statistics-policy-20261026`，起点 accabf300ed2571a38f9aaa62c8a63f64bacd980（GitHub API 已核验当时 main 一致）。

## 已确认需求

1. 专员首页应能发现活动管理。核对入口、版本与权限，不能靠隐藏入口或自动授予全部权限处理。
2. 活动与签到、现场管理从同一实时源导出报名签到明细，全部场次逐场保留；增加场次汇总、小组参与率及总参与率。空巴不进入上午下午班会去重总率。
3. 任意“XX班精进组”（含组织内简称“精进组”）不纳入班会、小组学习会、读书打卡、分享等要求的分子分母。人员和自愿参加、实际学分事实保留。班委组仅在小组学习会应开与参与统计中免要求，不扩大为所有班级职责豁免。
4. 每月所有应开小组都在周报明细列出，未开也列，时间和人数可空，完成情况“待完成”。精进组、班委组不计应开数。正式免开、暂停政策继续保留；没有周期配置的正常有效组按组织目录一组一次统计，矛盾或无法确定月份的正式政策明确提示原因。
5. 同班学长本月参加任何应开小组会，按本人当月统计归组去重计入本人小组；自己小组未开会仍为待完成。分中心总率沿用已完成组加权口径，不把个人参与等同小组完成。
6. 用户已明确回复“按此规则实现”：北京时间每月30日0点锁定本月统计归组；2月为最后一天0点；同班转组更新归组，跨班转入／转出保留当月原归属。锁定归组后新提交的真实参会仍可更新参与率，原始参会和学分不重写。

## 根因与实现

- 活动管理按 attendance:view 独立授权。运营岗位模板没有自动拥有整组签到权限，既有 attendance_operator 能力也未列入普通员工管理可选能力。调整为入口可发现、未授权有明确提示；员工管理可显式选择现有“活动签到运营”能力。不自动修改真实员工授权，不扩大组织范围。
- 原活动详情 Excel 查询同步后的 attendance_records，现场导出查询签到引擎实时报名。新增共享 attendance_workbooks：同一已授权实时明细、主档姓名、小组、脱敏、场次汇总、参与汇总及小组统计；实时失败或关联不一致时拒绝导出旧快照。报名实际人数与应参与口径分别展示。
- learning_requirement_policy 仅基于正式组织与归组应用统计豁免，不更改成员状态、分组或原始事实。作用于班会统计、班级运营、小组会、可确认组织范围的外部自动指标及月度基础学分率要求；聚合历史来源没有人员拆分时不伪造扣减。
- study_meeting_monthly_roster 保存独立月度归组、组目录。当前月基线和规范关系变更前快照保护跨班原归属；30日幂等冻结，跨月重新按当前组织建立新基线。读接口不创建或更新快照。新写入功能以 STUDY_MEETING_MONTHLY_ROSTER_ENABLED 开关隔离，默认关闭，沿用现有生产写入和只读门禁。
- 现有维护函数增加独立午夜触发分支，仅调用固定受保护的 roster monthly 路由，调用者不能指定日期、小组或人员。不恢复已退休的学习周期月更，不影响原2点合影清理。

## 数据库与生产边界

0073 仅新增 study_meeting_roster_months、study_meeting_roster_members、study_meeting_roster_groups 三张统计归组表及其外键、索引。无原事实、积分账本、学员主档或 IAM 数据改写。提供 MySQL、SQLite 前向 SQL 和空表安全回退；已有归组快照时回退必须拒绝，保留数据后前向修复。

正式环境执行0073、启用新月度统计写入功能、初始化本月基线以及真实员工身份授权属于工程工作流需单独核验的生产动作。当前仅开发及隔离测试，未执行这些生产变更。应在完整候选和验证证据就绪后明确目标、范围和批准引用；不能用普通发布默认授权代替。

拟议最小权限范围：仅为截图中的刘超唯一有效员工账号，在其既有运营服务范围内增加现有 attendance_operator 的8项签到运营能力；同名、未在职或范围不明确时停止，不修改其他员工，不授予学分入账或IAM管理权限。真实账号及授权差异须在获得对应授权后通过受控接口核验。
