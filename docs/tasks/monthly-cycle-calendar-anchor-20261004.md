# 学习周期月份基准修复

用户在 2026-10-04 明确要求：吴越三班 9 月登记第 3 次，10 月应为第 4 次；7 月代表开班模板。重新审查其余班级、修复同类错误并测试微信预览版。沿用本任务自主修复和后端发布授权；微信正式提审与发布仍由用户操作。

修复范围是先前 `learning.cycle.monthly_refresh` 错误生成的周期，使用现有应用服务的内部查询和审计，不使用客户端直接数据库连接或新增公众业务查询接口。先上线只读逐班诊断，私有 CLS 中只输出班级、月份与次数，不输出人员、手机、课程完成明细或凭据。新算法先停止有旧版错误记录的班级继续推进。

实际诊断清单核验后，仅把匹配清单 SHA256 的旧版自动生成周期恢复到正确月份；没有登记、完成、学分、班会事实和人工调整才允许修复。保持绑定、模板、轮次和所有行 ID，后续周期改为现有 `UPCOMING` 状态，按正确月份再启用。一个事务内锁定班级并重新核对清单，任何变化拒绝写入；逐班记录修复前后审计。实际登记、人员、课程完成和学分不改写、不删除。

月份证据优先使用人工校正所在月、实际登记/班会日期和明确标注 2026-09 的业务基准；缺少对应基准的历史导入采用记录当前次数的时间，不从开班月份重新补加。真实班会旧模式已经打开的下一周期属于下一月，防止月更重复推进。本月手动第 6 次不提前推进，第 1 个正式周期和未来启动、延期、计划结束保持原有约束。

相关测试在 SQLite 与 CI 独立 MySQL 8.4 上执行。没有结构迁移，无生产启动迁移、权限、凭据或费用变化。恢复优先按审计前向修正；出现新业务事实后不允许覆盖恢复。

该服务已有 URL_PARAMS 不持久化的发布证据，使用受控源码发布器的显式 startup-loopback 模式；稳定版本网络必须完整继承，23 条候选 HTTP 身份日志和 20/20 真实数据库探针通过后才允许正常流量。
