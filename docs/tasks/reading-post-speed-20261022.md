# 读书学分确认入账提速

用户反馈：272行有效来源、249笔计分在“正在入账”持续较久，截图仅完成56笔。此前保存来源的批量优化没有消除确认入账逐笔重算整批的开销。

## 原因与修改

原分段确认每次最多3笔；开始请求时重算一次整批预览，每笔独立事务又重算一次。请求前后还要加载来源详情。此处存在随人员数和笔数放大的重复计算。

仅对已核对Excel来源的每日读书确认路径，改为每次最多25笔、插入处理约8秒后在条目边界结束的短事务分段。每段先按学员ID顺序锁定所有涉及学员，锁定读取先于任何MySQL一致性读，再在该事务内校验冻结条目、实时整批事实/规则、已有账本与待入账总数/总分；之后逐条调用原正式入账服务，保留权限、规则版本、期初截止日和唯一幂等键校验。预览不跨事务复用。

每段所有账本和条目关联一起提交；任一条异常则整段回滚，之前成功分段保留。失败仍需明确续跑；进程中断仍走已有心跳/对账恢复门禁。暂停发生在已提交分段之间。普通审批批次、优秀分享月封顶、学习会和历史学分继续使用原逐条处理路径。

未改变计分规则、正式账本唯一键、授权或生产数据；没有新增表、迁移或资源配置。
