# 当前归组一致性修复与全局核查

用户口径：全局当前归组以班级与小组管理的组织树、有效正式班级/小组关系为唯一依据。

## 问题与处理

- 学员列表显示取优先关系，但小组筛选曾匹配任一关系；旧次要关系会让三组学员进入四组列表。
- 学习会登记、人工核实、现场签到、参会率、日常学员信息和导出曾采用不同归组查询。
- 统一日期边界、正式班级约束与主关系优先规则；同优先级冲突不按记录编号猜组，显示待核对。
- 保存小组归属会终止竞争关系并复用已有目标，保留会议与学分来源快照。批量预览纳入残留关系清理及过期预览保护。
- 当前人员分类及参会率按当前主档计算；历史登记列单独保留。登记差异不等于必然误报，可能来自后来调组。
- 班级与小组管理新增全局只读核查，服务端同时检查组织管理、学员查看及学习会查看范围。不查询手机号、关怀备注或财务信息。
- 当前名单不计入残留关系，但停用组织仍检查残留引用，不因显示修正放宽业务门禁。

## 数据边界与恢复

本次普通发布不执行数据库迁移、不启用写入开关、不批量重写生产学员归属或已结算会议。核查差异需区分真实调组、原始误报与关系冲突，按既有人员修正或学分纠错流程处理。

代码恢复使用发布前稳定API版本与管理端入口备份；已生成的历史快照、正式结算及审计不会因本次只读显示变化被修改。
