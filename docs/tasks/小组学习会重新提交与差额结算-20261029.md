# 小组学习会重新提交与差额结算

用户批准：同一小组、同一学习周期内，不受后台是否核实或已入账影响，允许重新提交；不得重复计分。小程序正式发布由用户今晚完成，之后进行正式版最后检查。

## 行为

- 每次重交保存一份新草稿。未完成照片上传、名单校验及最终提交前，上一份成功记录继续有效。
- 新版本提交成功后，上一份有效版本标记为被替代（CANCELLED并记录superseded审计）；正常列表、统计和列表导出只展示当前有效版本。历次名单、照片元数据、课程快照和账本均保留。
- 重交沿用原学习会日期，不将原有参会率或学分移动到上传更正的日期。
- 新版本需要后台重新核实。已核实的旧版本、旧指纹和旧结算预览不得用于继续入账。
- 原样重交：原有学分只保留一份；增删人员、课程或逐人完成事实：核实后追加正负差额，不覆盖原账本。
- 学分资格按原有“学员+学习周期”及“学员+课程+班级学习绑定”键去重。若本人仍参加同周期另一有效小组会（课程为同一学习绑定下的其他有效完成事实），保留应得学分；最后一份有效事实移除后扣回。所有相关小组均使用同一原始计分键核对净额，避免换组后学分无人负责回收。
- 差额记录使用SMR版本键、冻结净额与目标值，纳入结算指纹校验；继续使用原有权限、范围、开关、成员锁及幂等约束。结算中断可以续跑，已成功扣回的项目不再重复扣回。
- 后台预览明确展示负数扣回、受影响人员及项目，导出包含“已移除”人员的差额。没有新增表、生产迁移、定时任务或自动改写历史账本。

## 验证

受影响API回归涵盖后台核实前/后、已入账原样重交、删人再补回、课程移除再恢复、跨组最后一份参会事实、旧结算拒绝、差额部分失败恢复及原账本不变。新增测试放入现有MySQL学习会CI测试文件，与SQLite本地验证区分。

小程序回归涵盖成功回执丢失后的换照片或改名单重交，避免误把旧成功回执当作本次更正结果。正式发布前检查源码、API版本、CI和开发版上传回执，不把上传开发版当作正式发布或真机验收。

## 今晚正式发布后的最后检查

1. 核对微信正式版本与本次交付版本、源码提交一致。
2. 使用受权测试记录或真实需要更正的记录，检查新提交失败时旧记录仍有效；成功后后台只保留一份有效记录并显示待重新核实。
3. 原样重交后核实，核对学分净额不增加；如有真实名单更正，核对差额预览、入账结果和审计链。不得为验收伪造学员出席或随意修改真实学分。
4. 核对照片上传、成功/失败提示及30天保留配置；确认精进组新口径未回退。

发布证据保存在统一工作区 .codex-tmp 的本次交付目录。
