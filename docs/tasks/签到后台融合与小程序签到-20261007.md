# 签到后台融合与小程序签到

本任务覆盖 `spring-chao/seiwajyuku-platform` 与 `spring-chao/signin`，原需求为后台融合、小程序扫码签到及及时同步一次交付到隔离验收环境。生产数据、IAM 授权、CloudRun 流量、线上码和旧入口关闭均不在本次执行授权内。

## 权威实现和数据流

运营人员进入平台「运营管理 → 签到管理」，由平台验证现有 JWT、八项独立权限及对应组织范围，调用 signin 的受控管理接口。signin 继续运行原活动、报名、三场、窗口、团队、外班和签到确认规则；平台没有另一套签到确认规则。

学员扫描场次码后，平台将不透明 scene 解析为一个 event_id，使用现有微信身份绑定中的稳定 member_id/member_code 定位本人。正常学员只需确认，无需再次输入姓名、手机号或从同名列表中选择。特殊来宾、团队实际到场等情况保留旧 H5 流程。

平台向已核验身份签发五分钟、单活动、仅签到用途的 HMAC ticket。小程序可直接向独立 signin 引擎确认，signin 验签后委派原确认处理器。票据取得后平台暂时不可用仍可签到；首次加载或票据过期时仍需要平台，现场可使用独立 H5 兼容入口。身份停用/解绑后的短票据最多保留五分钟；不具备管理、导入或其他用途。

signin 先原子保存 event_id + registration_id 的幂等签到事实及待同步 outbox，再限时尝试平台增量同步。失败返回签到成功、记录同步待重试，定时器以退避策略继续重试。平台收到 event_id 后沿用 attendance sync、组织关联、积分和个人经历查询；只有同步 SUCCESS 且指定 registration 已保存为实际到场事实时才确认完成。原工作日 00:00 自动拉取保持兜底。

上午、下午、空巴保留三个 event_id/session_id。平台个人经历按活动组展示一次参加，原始三场事实、统计和积分仍分别计算。注册名与实际到场名始终分离；团队实际人员不会继承报名联系人的学员身份。

## 迁移清单

| 能力 | 平台入口/实现 | 保留的 signin 权威能力 |
| --- | --- | --- |
| 活动创建、名称/日期/类型/组织/时间 | 签到管理创建和编辑 | upload/create 原规则和校验 |
| 班级学习会三场 | 三场创建及活动组选场次 | create_class_meeting_sessions |
| 名单来源 | 已确认班级/小组 ID、名单对账 | 从平台可信 roster 重新读取，无法确认则拒绝 |
| 外部活动 Excel | 复用原 Excel 解析器、预览后追加 | import_preview/import_apply，校验预览和源状态 |
| 临时报名、删除报名 | 现场工作区 | registration/registration_delete |
| 开关、确认、取消 | 活动生命周期操作 | event_update/event_lifecycle_update |
| 已到、未到、迟到、请假 | 完整名单标签和筛选 | 旧统计和状态处理器，完整明细读取 |
| 人工签到 | 现场操作 | 原确认规则及活动窗口 |
| 外班、团队 | 原报名人/实际到场人分别显示 | CROSS_CLASS_MEMBER、团队名额及实际人逻辑 |
| 实时统计、Excel 导出 | 轮询刷新、脱敏导出 | stats/export |
| 场次小程序码 | 指定 event_id 生成码、重新生成 | 新的只含不透明 token 的场次路由 |

`public/index.html` 和 `public/admin.html` 标为 LEGACY 并继续可用。密码管理、整库清空/重建等旧维护能力没有放入平台白名单；不属于日常迁移操作。新后台完成真实业务验收后，旧管理入口退役需单独授权。

## 权限和审计

权限为 `attendance:view/create/update/manage/status/import/export/code`，所有新路由服务端验证。动态组合动作同时需要相应权限，并取各权限组织范围交集。最具体的小组/班级决定活动归属，父组织仅在真实祖先关系确认后作为描述元数据。不存在组织、错误父子关系、没有 scope、客户端提交 actor/授权范围均拒绝。

新增 `attendance_operator` 模板未分配给任何生产账号。既有系统管理员、运营角色不会自动得到这八项新权限；开通应通过现有 IAM 流程和另行确认的授权范围。查看或生成码不能推导写入权限。

创建、修改、取消、开关、报名增删、迟到/请假、人工签到和码轮换记录 actor/action/target/timestamp/before/after。跨服务修改先写 PENDING 意图，收到结果再记 SUCCESS/FAILED；signin 同样保存管理审计，超时不能伪称远端未执行。普通响应和审计去除手机号、电话散列、凭据和关怀备注。

## API 与配置

平台管理：`GET /api/v1/attendance/manage/events`、`POST /api/v1/attendance/manage/{operation}`、`POST /api/v1/attendance/manage/events/{event_id}/code`。operation 是代码中的固定白名单，不能传任意引擎路径。

小程序：`GET /api/v1/wechat/checkin/events`、`GET /api/v1/wechat/checkin/context`、兼容 `POST /api/v1/wechat/checkin/confirm`。匿名 context 仅显示活动信息，无报名或他人身份。

独立确认：signin `POST /native/v1/checkin/confirm {ticket}`。小程序只向受限 HTTPS 引擎地址发送 ticket，不把平台 bearer 或服务密钥发送给引擎。

及时同步接收：`POST /api/v1/attendance/sync/immediate` 使用既有 `SIGNIN_SERVICE_API_KEY`。旧 `/ops/v1/attendance/sessions` 与 `/records` 继续兼容，并增加可选 event_id 筛选。

新增配置默认关闭：`SIGNIN_MANAGEMENT_ENABLED=false`、`SIGNIN_MEMBER_CHECKIN_ENABLED=false`。`SIGNIN_PLATFORM_API_KEY` 是独立的服务间密钥，仅注入两个后端，不能放到小程序、浏览器、二维码或仓库。`SIGNIN_API_BASE_URL` 在隔离部署使用 HTTPS 引擎地址；`SIGNIN_LEGACY_URL` 是对应环境 H5 地址。signin 的同步目标和定时器配置见该仓库 staging 文档。

生产 `DEPLOYMENT_READ_ONLY`、`ALLOW_PRODUCTION_MUTATIONS` 及写入路由白名单保持原门禁。只改变功能开关不足以开启生产写入，不能用本次代码提交绕过授权。

## 数据库迁移与恢复

`0068_signin_management.sql` 在 SQLite/MySQL 仅新增空 `attendance_entry_tokens` 表，存 SHA256 token_hash、event_id、生成者和有效期，不复制姓名、手机号、报名或签到事实，也不赋予 IAM 权限。scene 是 22 字符随机 token；重新生成撤销旧 token。

正向脚本可重复执行。down 仅在未发出任何码时允许；存在任意 token 会在 drop 前拒绝，必须使用备份恢复或前向修复，不能删除真实 token 来强行降级。隔离 SQLite 测试覆盖空回滚、拒绝回滚、外键和备份恢复；CI `mysql-staging` 使用 MySQL 8.4 做重放、带码拒绝、空回滚、备份恢复及全库恢复核对。该文档描述测试入口，实际执行结果以验证报告和对应 CI 提交为准。

## 隔离验收和发布顺序

1. 在全新测试数据库应用迁移，使用合成组织、成员和只用于测试的权限账号。
2. 在独立 signin 测试环境注入服务密钥、平台测试地址和重试定时器；不改生产 envId/CloudRun。
3. 在测试平台启用两项签到开关，验证组织名单、场次、导入、现场工作区和权限边界。
4. 小程序测试包使用可手机访问的合法 HTTPS API 及独立 signin 域名，先预览编译，再生成 develop/trial 场次码；保持正式配置不变。
5. 验证扫描、现有真实微信绑定、确认、重复、三场独立、团队/外班、断平台成功及重试后个人成长。loopback/synthetic 验收不能替代手机扫码及真实微信提供方验收。
6. 两仓库提交 PR 并核验目标提交 CI。生产迁移、授权角色、功能开放和旧入口退役分别等待明确授权。

当前验证结果和未完成项目集中在 `docs/verification/签到融合-20261007.md`；不把编译、模拟微信码或仅 loopback 接口记为真实手机扫码通过。
