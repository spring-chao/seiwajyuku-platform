# 读书云端同步与自动入账

## 已确认范围

2026-11-02用户批准将现有读书采集迁移到腾讯云，并将规则变更为：保存有效学习来源后自动生成结算、自动确认入账，无需逐次人工确认。仅适用于本任务22个正式班级的读书打卡；其他学分类别不变。

学习平台通常使用账号密码且不要求验证码。该条件尚不等于云端登录已验证；验证码或风控要求不能绕过。凭据必须经安全配置提供，禁止从本机浏览器提取Cookie或隐藏令牌。

## 目标执行链

腾讯云定时触发 → 创建持久同步批次 → 按班级和日期区间入队 → 云端浏览器登录与导出 → 完整Excel核验 → 受限服务端预检与来源保存 → 生成结算 → 以实时指纹提交现有持久入账任务 → 对账并写班级收据。

采集器与现有API服务、合影维护函数分开部署。浏览器的依赖、内存和超时单独验证；调度器只派发任务。按班级小任务续跑，不要求22班在一次函数执行中全部完成。不增加无任务时每分钟轮询。

## 日期与去重

- 按Asia/Shanghai计算业务日期；部署时以实际触发记录核验北京时间09:00，不能只检查配置文字。
- 周一同步上周一至周日；跨月拆成两个精确区间。
- 每月1日只同步上月末日所在周的周一至上月末日，不复核整月。
- 每月1日若为周一，周任务跳过，由月初任务统一处理。
- 按班级、区间收据跳过已完成部分。部分成功和失败不能当成功；来源已保存但入账未完成时续跑入账，不重新下载替代对账。
- 数据事实按班级、来源身份、打卡日期、学习任务去重；原表SHA256只用于文件追溯，不能替代业务去重。

## 自动入账约束

服务端必须将机器身份限制到已核验的22班组织ID、DAILY_READING和本批次精确日期区间；不得借管理员通用身份放大范围。复用现有生产写开关、冻结期、权限、锁、实时指纹、审计与账本幂等逻辑，禁止直接插入学分账本。

身份匹配不唯一的行排除出自动入账，保留待核对。其余有效行可以自动确认，但班级仍保持PARTIAL_PENDING_IDENTITY。规则变化、异常金额或越界来源需报告待核对。部分失败只续跑未完成项目，不能重建已入账批次。

收据区分下载完成、来源保存完成、入账进行中、入账完成、身份待核对和失败。只有完整文件通过验证、所有应处理事实保存并完成应入账项目且无未处理例外，才记SUCCESS。日志、收据仅保留脱敏摘要和计数。

## 验收顺序

1. 在隔离环境验证日期边界、跨月跨年、闰年、班级映射、越权和幂等。
2. 配置安全凭据，在云端验证真实登录、重新登录、完整导出与文件关联；有验证码时保存断点并报错。
3. 使用已核验班级跑通有效来源自动保存、自动入账及账本核对，复跑不得加分。
4. 模拟下载超时、上传结果不确定、入账中断、并发触发和身份异常，验证只补未完成项。
5. 在本机关闭且Codex未运行时，通过云端定时触发记录和22班收据验收。
