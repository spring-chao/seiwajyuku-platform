# 签到名单唯一来源与工作日零点同步验证

## 实施边界

- 新运营平台 `member_org_relations` 是签到班级、小组名单的唯一主数据来源。
- 签到后台只使用班级、小组组织 ID 请求名单；名称只用于页面展示和 Excel 兼容识别，不作为名单接口查询条件。
- 运营平台不可用、来源标识异常、组织 ID 不一致、名单数量不一致或小组班级归属异常时失败关闭。
- 不读取旧运营系统名单，不使用本地缓存作为在线名单回退。
- 现有 `/event`、`/checkin` 等扫码签到 HTTP 路由及静态签到页面不变。

## 自动核验

新平台提供受服务密钥保护的聚合核验接口：

`GET /api/v1/checkin-rosters/validate`

接口不返回姓名、手机号、成员编号或组织 ID，仅返回：

- 班级、小组、特殊班数量；
- 各关系类型在册人数汇总；
- 小组与班级关系不一致数量；
- 指向无效组织的关系数量；
- 主数据来源、查询模式和失败关闭模式。

每次从签到后台导入名单时还会核对：

- 响应来源必须是 `PLATFORM_ORG_RELATIONS`；
- 查询模式必须是 `ORG_UNIT_ID`；
- 返回范围必须等于请求的班级或小组组织 ID；
- 响应汇总人数必须等于实际返回人数；
- 每一行人员关系必须属于所选组织；
- 小组必须属于所选班级。

## 定时同步

签到云函数定时触发器：

- 名称：`attendanceSyncWeekdays0000`
- Cron：`0 0 0 ? * MON-FRI *`
- 时间：工作日 00:00

触发后先执行名单聚合核验；通过后调用新平台：

`POST /api/v1/attendance/sync/scheduled`

新平台再从签到后端的增量接口拉取活动与签到记录。整个过程使用服务密钥，不依赖人员账号，不改变现场扫码链路。

## 回退原则

- 名单接口异常：停止本次名单读取或导入，显示明确错误。
- 自动核验异常：停止本次定时同步并保留云函数错误日志。
- 不允许自动切回旧运营系统、名称文本查询或历史缓存。
- 修正组织关系或恢复接口后，可重新执行相同操作；不会因失败自动写入错误名单。
