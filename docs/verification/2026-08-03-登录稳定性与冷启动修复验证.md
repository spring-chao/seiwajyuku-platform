# 登录稳定性与冷启动修复验证

日期：2026-08-03

## 问题结论

登录页反复出现“网络错误”并不只是单一冷启动问题，而是三个因素叠加：

1. 云托管最小实例数原为 0，首次请求可能等待实例启动；
2. 生产 API 的跨域白名单未包含本地管理入口，浏览器可能只完成预检而不发送登录请求；
3. 生产只读保护误拦截了登录和令牌刷新请求，导致接口返回 403，前端又将这类失败统一显示为网络错误。

## 已实施调整

- 云托管最小实例数调整为 1，最大实例数保持 5；
- 保留现有 VPC、数据库连接和生产写入保护配置；
- 允许正式站点、`http://127.0.0.1:8848` 和 `http://localhost:8848` 调用生产 API；
- 只读模式仅额外放行 `/api/v1/auth/login` 与 `/api/v1/auth/refresh`，其他管理写入继续关闭；
- 登录与读取当前账号合并为一次可重试流程：网络错误、超时和服务端暂时错误自动重试一次；
- 单次登录请求超时由默认 10 秒提高到 20 秒；认证失败等明确的客户端错误不重试。

## 上线与验证

- 后端版本：`seiwajyuku-platform-api-060`，100% 流量；
- 后端最小实例数：1；
- 两个本地管理入口的跨域预检均返回 200；
- 使用无效测试账号从两个本地入口发起真实登录请求，均返回 401，并带有对应跨域响应头；
- 401 证明请求已到达认证逻辑，不再被跨域或只读中间件误拦截；
- 前端已重新构建并发布到 `/ops-platform`，线上文件确认包含自动重试标记；
- 后端相关自动测试 14 项通过，前端类型检查与生产构建通过。

## 保持不变的安全边界

- 未放开通用生产写入；
- 未改变人员、班级、小组或签到名单；
- 未改变 `/event` 和 `/checkin` 扫码链路；
- 未在本文记录任何密码、令牌或服务密钥。

## 人工验收

浏览器强制刷新登录页后，只登录一次。预期直接成功；若首次后端请求短暂波动，页面会在后台自动重试，不再要求用户重复点击三次。
