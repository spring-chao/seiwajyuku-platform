# 活动与签到表格口径与布局修复

## 变更目的

根据运营平台实际使用口径，调整活动列表和活动明细中的人数列，并改善表格的对齐与可读性。

## 统一数据口径

| 页面字段 | 数据口径 |
| --- | --- |
| 报名人数 | `record_count`，活动产生的签到报名记录数；原“应到人数”更名而不改变该统计来源 |
| 参会人数 | `present_count`，正常签到人数（`PRESENT` 与 `MANUAL_PRESENT`），包含非塾生和人工确认记录 |
| 应参会人数 | 班级活动取班级在册人数，报告会等大型活动取分中心在册人数 |
| 签到率 | 参会人数 ÷ 报名人数，保留签到后端的原始口径 |
| 参会率 | 班级活动按参会人数 ÷ 本班应参会人数；报告会等大型活动按参会人数 ÷ 分中心应参会人数 |

`签到率` 与 `参会率` 使用不同分母：签到率反映报名记录的到场情况，参会率反映班级或分中心应参会人数的到场情况。两者的参会人数均为正常签到总数，包括非塾生和人工确认。

## 界面调整

- 活动列表和活动明细均按“报名人数 → 应参会人数 → 参会人数 → 签到率 → 参会率”展示。
- 活动明细概览与场次表移除旧的“签到记录/已签到记录”重复列，避免同一指标重复展示。
- 移除“数据源”列，减少非业务字段造成的横向拥挤。
- 表头加深、单元格统一内边距、长文本自动换行，并增加悬停反馈，使列内容对齐且易读。
- 保留“查看明细”入口及班级/分中心参会率筛选。
- 报告会明细增加按分中心内班级查看已匹配学员参会率的只读表格；主活动参会率仍按活动正常签到总人数计算。

## 验证结果

- 后端测试：`85 passed`。
- 管理端：`pnpm typecheck` 通过。
- 管理端：`pnpm build:staging` 通过。
- 自动化测试加入非塾生 `PRESENT` 记录，确认原始参会人数及活动参会率均会计入非塾生。
- 报告会班级参会率明细自动化测试通过：测试班级在册 2 人、已签到学员 1 人。
