# 活动与签到页面空白修复验证

更新时间：2026-08-04

## 现象

活动与签到页面在加载复核汇总时显示活动、签到和复核数量均为 0。签到事件接口和同步状态接口本身仍可读取。

## 根因

复核汇总新增的 MySQL 查询包含 `LIKE '%目前不读书%'`。平台数据库适配层将 `?` 转换为 PyMySQL 的 `%s` 占位符，但未转义 SQL 中的字面量 `%`，PyMySQL 将其误认为格式占位符并抛出 `TypeError: not enough arguments for format string`，接口返回 HTTP 500。前端原先使用 `Promise.all`，任一辅助接口失败会使整页停留在空的初始状态。

## 修复与验证

- 数据库适配层在 MySQL 模式下保护参数占位符并转义字面量 `%`；SQLite 行为保持不变。
- 新增 MySQL/SQLite SQL 转换回归测试。
- 后端测试：83 项通过。
- GitHub CI：提交 `aeaa6ce` 通过。
- CloudRun 发布后，健康检查和生产只读环境接口均为 HTTP 200。
- 使用现有登录会话刷新活动页并选择 2026 年 7 月，页面恢复显示 7 个活动场组、384 条签到记录、1 次已签到人次；活动状态显示为中文“正常”。
- 生产日志确认 `event-groups`、`sync/status`、`reconciliation-summary` 均返回 HTTP 200，未再出现异常堆栈。

## 影响边界

本次仅修复读取路径和测试，不执行任何生产写入，不修改签到系统 `/event`、`/checkin` 链路，不改变组织关系或权限数据。
