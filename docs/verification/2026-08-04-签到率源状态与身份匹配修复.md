# 签到率源状态与身份匹配修复验证

## 问题

签到系统的昆山分中心半年度学习报告会显示 106/115 = 92.2%，而运营平台显示 0%。

## 根因

- 签到源记录本身已经返回 `attendance_status=PRESENT`。
- 运营平台同步时，若 `member_code` 无法匹配 `members`，旧逻辑会把记录状态覆盖为 `UNMATCHED`。
- 运营平台签到率只统计 `PRESENT` 和 `MANUAL_PRESENT`，因此未匹配记录被错误排除。
- 未匹配身份应影响班级/分中心参会率和积分，但不应抹掉签到源的原始签到事实。

## 修复

- 新增签到状态标准化，兼容 `checked_in=true`、`CHECKED_IN`、`已签到`、`late` 等来源表达。
- 未匹配学员保留源状态（例如 `PRESENT`），仅将 `score_eligible` 置为 false。
- 未匹配仍通过 `member_id IS NULL` 进入数据复核队列，继续失败关闭，不参与班级/分中心参会率和积分。
- 现有 `/event`、`/checkin` 扫码链路未修改。
