# 双分中心隔离身份合成试点核验（2026-08-14）

## 结论

已完成昆山、吴江两个分中心的合成身份与组织范围试点。该试点只使用临时 SQLite 数据库和合成账号，不创建、导入或修改生产组织、自然人、账号、雇佣、岗位或权限。

## 已确认的合成试点参数

| 项目 | 值 |
| --- | --- |
| 隔离账号 | `pilot-ops-center-director` |
| 岗位键 | `ops_center_director` |
| 昆山组织 ID | `pilot-kunshan-center`，`SUBTREE` |
| 吴江组织 ID | `pilot-wujiang-center`，`SUBTREE` |
| 越权对照组织 | `pilot-outside-center`，不授予范围 |
| 试点窗口 | 2026-08-14 起，30 天；脚本按运行时刻生成结束时间 |
| 业务负责人 | `ops_center_director`（脱敏岗位别名） |
| 回滚责任人 | 平台 `admin` 账号 |
| 回滚方式 | 销毁可丢弃的隔离 SQLite 数据库 |

`ops_center_director` 在此是岗位键，而不是对真实人员的自动匹配；任何真实账号进入隔离试点前，仍需单独提供自然人关联与任职依据。

## 验证结果

- 隔离试点脚本、身份管理、身份授权和志工邀请回归：`25 passed`；
- 负责人拥有昆山、吴江两棵组织子树及各自合成班级的可见范围；
- 负责人可看到两个已授权分中心的合成学员，不能看到 `pilot-outside-center` 的合成学员；
- 双分中心雇佣创建必须产生身份审计记录；
- 脚本仅允许 `dev`、`test` 或 `staging`，且仅可连接文件名包含 `pilot` 的 SQLite 数据库；生产写入开关必须为关闭状态；
- 自动测试用临时目录在退出后自动销毁数据库，完成回滚演练。

## 边界

本次是技术与组织范围合成验证，不替代一个月的真实账号业务试点。真实账号试点仍需逐项确认账号标识、身份类别、自然人关联依据、任职依据、稳定生产组织 ID、范围和起止时间，并在隔离环境稳定一个业务周期后再单独申请生产短时配置窗口。
