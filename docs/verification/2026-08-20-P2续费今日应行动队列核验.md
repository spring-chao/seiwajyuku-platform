# P2 续费“今日应行动”队列核验（2026-08-20）

## 验收结论

P2 V1 已完成：新增只读 `GET /api/v1/renewals/actions/today`，并在续费运营页增加“今日应行动”队列。队列只使用五条可解释规则和确定性排序，不修改 P0 阶段引擎、不重构 P1 action-card、不增加数据库迁移。

本任务文档明确要求“不部署生产”，因此本次只完成代码、测试、构建和页面静态验收；没有执行 CloudBase API/Hosting 生产发布。

## 本次变更

- 后端新增 `renewals:read` 保护的今日队列接口，支持 `year`、`org_unit_id`、`stage`、`reason` 筛选，并按 `accessible_org_ids` 做组织范围校验；越权组织返回 403。
- 候选阶段仅包含 `OBSERVE_3`、`RENEW_2`、`FOLLOW_1`、`DUE_NOW`、`RECOVERY`；`CLOSED` 和默认 `PREPARE` 不进入队列。
- 进入规则为：约定跟进逾期、约定今天联系、最近一次沟通需要协助、当前自然月阶段未触达、当前阶段已沟通但未留下下一步。
- 每个 item 返回 `primary_reason` 与完整 `reasons`（含 code、中文说明和逾期天数），不使用概率分数；同一人可同时出现多个原因。
- 列表返回学长、组织、班级/小组、续费月份、阶段、责任人、最近关爱、意愿、协助标记、下一步及下次联系时间；不返回完整手机号、企业敏感信息、action-card 文案，下一步文本继续做手机号/金额脱敏。
- 续费运营页在周期台账前展示汇总卡片与行动队列表格；“今日行动”直接调用既有 `openCycleDetail`，复用 P1 工作台，不新增第二套详情页。
- 跟进记录保存后会重新读取今日队列，使队列与最新下一步保持一致。
