## 聚合架构

- `member_care_management.py` 是只读聚合层，不创建 `unified_tasks` 表，也不修改 `renewal_cycles`、`renewal_followups`、`followup_tasks`、`operation_items`。
- 今日关爱基础直接调用 P3 `build_member_care_actions()`；续费阶段和今日原因继续调用 P2 `list_today_actions()`、`determine_renewal_stage()`，没有复制观3/续2/追1规则。
- 普通关怀与企业走访继续调用 `list_tasks()`，因此沿用 `followup_visibility`、`accessible_org_ids`、保密级别和参与权限。
- 生日逾期来自 P3 `BIRTHDAY_CARE` action；管理层额外异常来自既有续费周期和跟进任务事实。

## 指标口径

### 顶部摘要

| 指标 | 口径 |
| --- | --- |
| `today_care_people_count` | 当前账号可见 P3 `people[]` 的人数，每位学长只计一次 |
| `today_care_action_count` | 当前账号可见 P3 actions 总数，可与人数不同 |
| `overdue_people_count` | 存在 `CARE_OVERDUE` 的去重学长人数 |
| `oldest_overdue_days` | 可见逾期 action 中最大的逾期天数，不设置 7/14/30 天阈值 |
| `renewal_support_needed_count` | P2 `SUPPORT_NEEDED` 异常数 |
| `renewal_recovery_open_count` | `determine_renewal_stage() == RECOVERY` 且周期未闭环的数量 |
| `renewal_unassigned_count` | 观3、续2、追1、到期、挽回阶段且 `assigned_user_id` 为空的数量 |
| `followup_no_schedule_count` | OPEN/IN_PROGRESS 且 `next_followup_at`、`due_at` 均为空的任务数 |

`CARE_OVERDUE` 继续拆分为 `RENEWAL`、`FOLLOWUP`、`ENTERPRISE_VISIT`、`BIRTHDAY`；生日、普通关怀、企业走访和续费逾期均以明确日期已经过去为事实，不使用人为天数门槛。

## 六类管理异常

| 异常 | 前端表达 | 导航 |
| --- | --- | --- |
| `CARE_OVERDUE` | 关爱逾期 | 复用续费、跟进/走访或生日流程 |
| `RENEWAL_RECOVERY_OPEN` | 续费挽回未闭环 | 现有续费页 |
| `RENEWAL_SUPPORT_NEEDED` | 续费需要协助 | 现有续费页 |
| `RENEWAL_STAGE_UNTOUCHED` | 当前阶段尚未留下关爱记录 | 现有续费页 |
| `RENEWAL_UNASSIGNED` | 续费责任人待分配 | 现有续费页 |
| `FOLLOWUP_NO_SCHEDULE` | 关怀任务缺少下一时间 | 现有关怀/企业走访页 |

组织默认按“有逾期 → 最早逾期天数 DESC → 需要协助 → 挽回未闭环 → 组织名称”排序。这是异常处理顺序，不是绩效排名。

## 权限覆盖矩阵

接口返回：

```json
{
  "source_coverage": {
    "renewal": {"accessible": true},
    "followup": {"accessible": false},
    "birthday": {"accessible": true}
  }
}
```

没有来源权限的统计字段返回 `null`，前端显示“未授权”，不会伪装成 0。账号没有任何来源权限时接口返回 403。组织筛选继续执行 `accessible_org_ids`，越权组织返回 403。

## 隐私与去重验证

- 响应只返回组织、学长、异常来源、事实依据、责任人和导航所需最小字段。
- 不返回完整手机号、企业财务数据、`service_purpose` 原文、沟通摘要、主观判断或敏感关怀笔记。
- 同一学长同时有续费、生日、普通关怀或多个逾期 action 时，`today_care_people_count` 与 `overdue_people_count` 均按人去重；`today_care_action_count` 和异常列表保留事实项数量。
