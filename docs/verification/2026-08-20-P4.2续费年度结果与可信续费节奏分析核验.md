# P4.2 续费年度结果与可信续费节奏分析 V1 核验

## 范围

- 只读接口：`GET /api/v1/renewals/analytics/annual?year=YYYY&org_unit_id=...`
- 页面：运营驾驶舱的“年度续费洞察”
- 本次没有新增表、字段或生产数据写入，因此没有数据库迁移。
- 阶段规则继续由续费日历引擎决定，分析服务复用 `determine_calendar_stage()`，不复制阶段算法。

## completion evidence 判定矩阵

| evidence | 判定事实 | 进入续费节奏 |
| --- | --- | --- |
| `LIVE_STATUS_TRANSITION` | 当前为 `RENEWED`；`completed_at` 存在；存在 `to_status=RENEWED`、非空 `from_status` 的状态历史；历史 `created_at` 与完成时间相差不超过5秒；不是导入或历史自动补录 | 是 |
| `IMPORT_SNAPSHOT` | 周期带有正式续费导入批次 `source_batch_id` | 否，结果可计入年度结果 |
| `HISTORICAL_AUTO_RECONCILIATION` | 状态历史包含历史月份维护/自动标记为已续费的可识别原因 | 否，结果可计入年度结果 |
| `UNKNOWN` | 无法证明完成时间来源 | 否，结果可计入年度结果 |

`completed_at` 单独存在不构成可信完成时间证据；分析服务不补写时间、不修改历史、不根据到期月份猜测日期。

## 年度结果口径

- `total_cycles`：所选年度、当前账号可见组织范围内的续费周期数。
- `renewed_count`：当前状态为 `RENEWED`。
- `not_renewing_count`：当前状态为 `NOT_RENEWING`。
- `exited_count`：当前状态为 `EXITED`。
- `deferred_count`：当前状态为 `DEFERRED`。
- `open_count`：除 `RENEWED`、`NOT_RENEWING`、`EXITED` 外的当前状态。
- `outcome_status_counts`：当前状态的完整分布；不依赖完成时间可信度。

## 可信续费节奏口径

仅对 `LIVE_STATUS_TRANSITION` 的 `RENEWED` 周期，以可信 `completed_at` 当天调用日历阶段 helper：

| 阶段 | 展示 |
| --- | --- |
| `PREPARE` | 观3之前 |
| `OBSERVE_3` | 观3 |
| `RENEW_2` | 续2 |
| `FOLLOW_1` | 追1 |
| `DUE_NOW` | 到期月 |
| `RECOVERY` | 到期后 |

`before_due_count = PREPARE + OBSERVE_3 + RENEW_2 + FOLLOW_1`，`due_month_count = DUE_NOW`，`after_due_count = RECOVERY`。
比例名称固定为“可信完成样本中，到期前完成比例”，分母为可信完成样本数；没有可信样本时返回 `null`，不显示伪造的 0%。
