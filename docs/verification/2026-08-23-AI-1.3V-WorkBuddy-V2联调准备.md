# AI-1.3V WorkBuddy V2 联调准备与门禁

## 当前结论

V0 启动边界和 V1 标准 MCP Streamable HTTP 已完成并发布；V2 真实 WorkBuddy Connector 尚未执行。当前仓库和可用账号环境中没有公开可访问、与生产数据隔离的长期 staging 服务，因此不得把生产 API 临时打开作为替代验收。

本次新增 `scripts/verify_agent_mcp_streamable.py`，用于在真实 Connector 前后重复执行协议验收。脚本强制以下边界：

- `target_environment` 必须是 `staging`；
- 远程主机名必须明确包含 `staging` 或 `preview`，并使用 HTTPS；
- 远程主机必须与 `AGENT_PROBE_EXPECTED_HOST` 完全一致，防止凭据被误发到其他地址；
- 路径必须是 `/mcp/seiwajuku`；
- 凭据只从环境变量读取，不接受命令行明文参数；
- 输出只包含协议、工具名、结果结构和数量，不输出令牌、客户端密钥、姓名或业务明细；
- 验证 `initialize`、`Mcp-Session-Id`、`MCP-Protocol-Version`、`notifications/initialized`、GET 事件流、`tools/list`、六个只读工具和 `get_my_today_actions`；
- 发现写工具、敏感工具、非只读 annotation 或工具集合漂移时立即失败。

## 官方 Connector 约束

WorkBuddy Enterprise 的 Connector 管理文档确认：自定义 MCP Server 使用 `streamable_http`，可配置认证凭据、自定义请求头和工具过滤；连接器使用管理员配置的统一凭据代理成员访问。因此统一凭据只能证明“调用方是 WorkBuddy Connector”，不能证明“当前操作者是某一名运营人员”。

## V2 隔离 staging 前置条件

1. 创建名称明确含 `staging` 的公开 HTTPS 服务，使用独立数据库或仅含合成数据的隔离库；不得连接、复制或读取生产数据库。
2. `APP_ENV=staging`、`ALLOW_PRODUCTION_MUTATIONS=false`、`RUN_BOOTSTRAP_ON_STARTUP=false`；迁移和 IAM seed 作为独立可核验任务执行。
3. 仅 staging 设置 `AGENT_API_ENABLED=true`，生成专用 Agent client secret，并保持六个只读工具 allowlist。
4. 创建两个合成运营账号、两个不同组织范围和互不重叠的合成学员；不使用真实姓名、手机号或关怀记录。
5. 生成短期 staging operator token，仅用于 V2；凭据不得写入仓库、命令行、截图或验收文档。
6. 在 WorkBuddy 企业管理台创建 `seiwajyuku-ops-staging` Connector，MCP URL 指向 staging `/mcp/seiwajuku`；在保存凭据和启用连接器前再次取得限定确认。

## 验收命令

在已安装 `apps/platform-api/requirements.txt` 的终端中，通过进程环境注入值：

```powershell
$env:AGENT_PROBE_ENVIRONMENT = 'staging'
$env:AGENT_PROBE_URL = 'https://<agent-staging-host>/mcp/seiwajuku'
$env:AGENT_PROBE_EXPECTED_HOST = '<agent-staging-host>'
$env:AGENT_OPERATOR_TOKEN = '<short-lived-staging-token>'
$env:AGENT_CLIENT_ID = 'workbuddy-staging'
$env:AGENT_CLIENT_SECRET = '<staging-only-secret>'
$env:AGENT_PROBE_CHANNEL = 'api'
python scripts/verify_agent_mcp_streamable.py
```

验收完成后立即从当前终端清除以上敏感环境变量。报告只保存脚本输出和对应 `request_id`，后端再按该 ID 核对审计；不得复制响应中的业务数据。

## V2/V3 完成标准

V2 需要真实 WorkBuddy Test Run 依次完成 `initialize`、`tools/list`、`get_my_today_actions` 和至少一次合成学员查询，并与同一 `request_id` 的后端审计对应。

V3 不能复用统一静态 operator token 冒充双人身份。必须由两名实际运营身份获得各自可信委托，证明 actor、组织范围、MCP session、对话上下文和返回数据均不串人。若 WorkBuddy 无法提供可信人员身份，继续进入 AI-1.4 的一次性绑定或 Identity Gateway 设计，不得开放写工具。
