# 新学长扫码入塾申请开发核验

更新时间：2026-08-24

## 本次交付范围

- 新增全局入塾申请二维码管理；二维码不绑定分中心、班级或小组，服务端只保存令牌摘要。
- 新增无需登录和后台布局的移动端公开页 `/enroll/:token`。
- 公开提交只创建 `member_enrollment_applications`，不会直接创建 `members`。
- 新增申请列表、详情、资料复核、审核通过、收款确认、驳回和正式入塾后台流程。
- 正式入塾必须同时满足审核通过、已收款、有效正式分中心、有效姓名和手机号、无重复正式档案等服务端门槛。
- 正式入塾复用现有学员创建核心，在同一事务中创建主档、`PRIMARY_REGION` 关系、续费历史逻辑和审计记录，并幂等回写申请。
- 新增五项 IAM 权限：`enrollment:read`、`enrollment:review`、`enrollment:payment_confirm`、`enrollment:enroll`、`enrollment:manage_link`。
- 新增 SQLite/MySQL 双端 `0028_member_enrollment_applications` 前向迁移及回滚脚本。

## 用户补充口径

原开发文档中“公开表单不得采集年销售额、利润率”的限制已被本任务中的用户明确修订。

当前实现允许公开表单填写年销售额和利润率，但仍按企业敏感资料处理：

- 申请库与正式学员主档均使用加密字段保存；
- 普通申请列表不返回精确值；
- 详情仅向具有 `members:enterprise_view` 权限的账号返回精确值，并记录敏感访问审计；
- 正式入塾直接转移受保护密文，不需要向审核人员暴露明文；
- 日志和审计不记录精确财务值。

## 安全边界

- 公开请求体使用字段白名单并禁止 `org_unit_id`、班级、小组、学员编号、学员状态和系统权限字段。
- 手机号使用加密值、匹配摘要、后四位和脱敏展示值；普通接口不返回完整手机号。
- 同一手机号有效申请使用唯一防重字段，重复提交与已存在正式档案均返回同一公开成功文案。
- 已有正式档案只在受权后台显示风险标记；正式入塾服务端继续失败关闭。
- 公开提交按二维码与客户端地址的 keyed digest 持久限流，不保存客户端地址原文。
- V1 仅开放 `PAID` 收款确认；减免与特批状态保留在结构中但服务端拒绝启用。
- `/api/v1/public/enrollment/{token}` 的 POST 没有加入生产只读白名单；只读部署会继续阻断公开写入。

## 验证结果

- 后端全量回归：`226 passed`；其中入塾申请定向用例覆盖公开字段白名单、重复提交、重复正式档案、组织范围、企业财务权限、限流、二维码轮换、审核/收款门槛、正式建档和幂等。
- 前端 `pnpm typecheck`：通过。
- 新增/修改前端文件 ESLint：通过，零警告。
- Vite 生产构建与 CI 同款 `pnpm build:staging`：均通过。Windows 下仓库原 `pnpm build` 脚本使用 POSIX 环境变量写法而无法直接执行，改用等价的 PowerShell 环境变量加 `pnpm exec vite build` 完成生产构建。
- 本地浏览器联调：
  - 手机视口下公开页无需登录即可打开，包含年销售额和利润率字段；
  - 合成申请提交后显示通用成功状态；
  - 后台列表只显示脱敏手机号；
  - 企业敏感财务资料按权限显示；
  - 二维码轮换后旧链接立即失效，新二维码在浏览器本地生成；
  - 审核、正式分中心、收款和正式入塾按门槛逐步解锁；
  - 最终建档成功，页面控制台无错误或警告。
