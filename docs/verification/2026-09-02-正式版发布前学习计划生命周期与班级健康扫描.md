## 1. 本轮范围

本轮只处理正式版发布说明中的 P0-1、P0-2，以及小组学习会链路所需的前置能力：

- 班级学习计划首次绑定、当前设置修正、从指定周期接续、重新开始；
- 轮次历史、结束原因、前序 binding 和审计记录保留；
- 学习计划版本 `DRAFT / PUBLISHED / RETIRED` 的业务语义；
- 全正式班级只读健康扫描和后台逐班管理入口；
- 接续轮次的计划日程、四期开班模板和小组学习会配置校验；
- 微信小程序本期小组学习会、本期必学、无二维码视频和无视频周期的现有验收链路。

没有执行与本次发布无关的积分、消息、AI 或大范围 UI 扩展，也没有按班级名称自动合并、停用或回填数据。

## 2. 已完成的代码能力

### 学习计划生命周期

- 正常班会确认只推进当前 binding 的周期，不会按年度自动换计划；
- `RESTART` 会结束旧 binding，新建第 1 周期的新轮次；
- `RESUME` 会结束旧 binding，从明确指定的周期建立新轮次；
- 当前纠错要求原因并写审计，不把历史周期改写成新的轮次；
- 新轮次只允许选择 `PUBLISHED` 计划；
- `RETIRED` 计划仍可被既有 ACTIVE 轮次读取，当前轮次可保留原计划做纠错；
- 生产并发写入按班级组织行串行化，避免空历史班级被并发首次绑定成多个 ACTIVE binding。

### 健康扫描

接口：`GET /api/v1/classes/learning-plan-health`

扫描输出包含：

- 未绑定、多个 ACTIVE binding、计划状态异常；
- 模板异常、缺少当前周期、`plan_cycle` 错位；
- 小组学习会配置缺失；
- 无有效小组、小组无有效学员、班级关系不一致；
- 志工能力或组织范围未核验；
- 同名班级的组织 ID 冲突提示。

扫描是只读的，所有修正必须在后台选择具体组织 ID、填写原因后逐项执行。

后台入口：`活动与学习 → 班级学习计划`。历史查询接口为：
`GET /api/v1/classes/{class_org_unit_id}/learning-plan-history`。
