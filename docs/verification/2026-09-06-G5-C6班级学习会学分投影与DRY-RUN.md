# G5 C6｜班级学习会学分投影与 DRY-RUN 验证

日期：2026-09-06
基线：`4ab8c8606082b8dd1372c2cbf2dec854271601f5`
范围：只实现班级学习会从签到评分到统一学分账本的只读投影；不正式入账、不部署、不执行生产迁移。

## 结果

C6 代码和隔离测试通过。`attendance_score_records.final_points` 是班会积分的唯一来源；DRY-RUN 不调用签到重算、不修改签到事实、不写入 `learning_credit_entries`，也不写审计记录。

每位学员以一场班会为一个投影单元，幂等键为：

```text
CLASS_MEETING:{member_id}:{event_group_id}
```

支持 `READY`、`BLOCKED`、`NO_CREDIT`、`SKIPPED_DUPLICATE` 四种结果，并返回上午、下午、空巴、扣分、裁定、最终分、规则绑定和评分事实快照。已有账本记录只标记 `SKIPPED_DUPLICATE`；不会因为 DRY-RUN 重复产生第二笔账。

## 入口

```text
POST /api/v1/learning-credits/dry-run/class-meetings/{event_group_id}
POST /api/v1/learning-credits/dry-run/class-meetings
```

批量入口支持 `class_org_unit_id`、`event_date_from`、`event_date_to` 和 `limit`。两个入口均要求 `plans:credit_settlement_preview`，服务层再次校验组织范围。

## 数据完整性边界

- 班会必须是 `CLASS_MEETING`，具有班级组织范围、学习计划绑定、已发布且启用的 `CLASS_MEETING_SCORE / EVENT_ONCE` 规则。
- 仅接受后端已匹配、可计分的 `MEMBER` 签到事实。
- 每一名学员必须在班会现有每个场次各有一条最终评分记录；缺失评分、重复签到事实、身份不一致、评分过期或班级关系缺失均失败关闭。
- 缺失场次不会被默认为 0 分；全部最终分为 0 时标记 `NO_CREDIT`，不制造 0 分账本记录。
- 评分在正式入账前发生变化时，DRY-RUN 读取最新最终评分。正式入账后的修正沿用账本的冲销加新入账模型，不覆盖原记录。

## 本地数据盘点

仅检查明确的本地开发库，未连接或读取生产数据库。`apps/platform-api/data/seiwajyuku_dev.db` 有班会原始签到事实，但最终评分记录数为 0；其他本地开发验证库没有可用班会事实。因此当前没有“数据完整班级”可以做真实历史学分对账，不能人为补写评分或完成状态来制造样本。首批真实班会产生后，仍须在正式 POST 前完成人工 DRY-RUN 对账。
