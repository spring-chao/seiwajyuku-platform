## 1. 现有只读 API 的边界

已核对的现有接口不能单独构成该历史快照：

- `GET /api/v1/members?org_unit_id=...` 返回当前列表摘要，只按成员主归属过滤，不提供所需的历史 `STUDY_CLASS` / `STUDY_GROUP` 有效期和关系 ID。
- `GET /api/v1/checkin-rosters/members` 面向签到机对机名单；它只给当前名单，并会记录名单访问审计，还可能返回本阶段不需要的电话字段，因此不用于本次快照。
- `GET /api/v1/iam/org-units/tree` 只返回当前启用组织树，缺少组织有效期，不能解释 2026-08-31 至 2026-09-04 的历史结构。
- `GET /api/v1/classes/{class_id}/learning-plan-history` 可辅助读取 binding 摘要，但不返回逐条历史成员关系或完整 cycle 明细。

因此需要数据所有者执行一次受控的、最小范围的只读数据库快照；不新增生产写接口，也不以当前名单替代历史关系。

## 2. 本次代码收口：从候选匹配起按事实日期判断

此前最终资格判断已经按 `occurred_on` 检查班级和小组关系，但导入初期的小组映射、候选成员和人工确认候选仍可能读取当前关系。现已修正为：

```text
来源发生日期
→ 组织节点 active_from / active_until
→ STUDY_CLASS / STUDY_GROUP valid_from / valid_until
→ 身份候选与人工确认范围
→ 再生成 DAILY_READING 来源事实
```

具体保证：

- 已在事实日期后才入班或入组的人员，不能成为候选，也不能被人工确认绑定到该历史来源身份。
- 今天已停用、但在事实日期有效的小组，仍可作为历史小组映射；不会因为当前 `is_active=0` 被静默丢弃。
- 每一个来源身份的全部实际日期必须各自存在唯一有效的班级关系；有来源小组时还必须各自存在唯一有效的小组关系。
- 班级/小组组织节点的自身有效期也会参与校验。
- `NO_GROUP` 观察保持个人积分、班级率分母和分子均为 `false`。身份无法确认时保留 `MEMBER_MAPPING_REQUIRED` 审计状态，但不阻断已确认正常组或精进组的 DRY-RUN。

## 3. 授权只读快照提取方案

### 3.1 授权和执行条件

由当前平台数据所有者或受授权 DBA 在生产兼容 MySQL 数据源执行。执行账号只授予本次表集合的 `SELECT` 权限，不授予 `INSERT`、`UPDATE`、`DELETE`、DDL、`FILE` 或管理权限；不得把连接串、密码或令牌写入仓库、报告或聊天。

快照须在一个一致性只读事务中生成：

```sql
SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;
SET SESSION TRANSACTION READ ONLY;
START TRANSACTION WITH CONSISTENT SNAPSHOT;
```

导出完成后：

```sql
ROLLBACK;
```

该事务只允许执行下文列明的 `SELECT`。不得查询 `learning_credit_entries`、不相关班级、全量通讯录、明文手机号、电话哈希或关怀备注。

### 3.2 先做目标班级唯一性预检

执行者先以参数化方式查询候选，不自动按名称选择 ID：

```sql
SELECT id, name, unit_type, parent_id, active_from, active_until, is_active
FROM org_units
WHERE name = :class_name
  AND unit_type = 'CLASS'
  AND (active_from IS NULL OR active_from <= :window_end)
  AND (active_until IS NULL OR active_until >= :window_start)
ORDER BY id;
```

参数固定为：

```text
:class_name   = 吴越三班
:window_start = 2026-08-31
:window_end   = 2026-09-04
```

候选不是唯一、父级不正确或历史有效期不覆盖窗口时停止，记为 `BLOCKED / PLATFORM_MASTER_DATA_MISSING`，不在快照或生产中补造组织。

### 3.3 最小数据集合

在已人工确认的 `:class_org_unit_id` 下导出以下明确字段。每个关系查询必须以历史窗口重叠条件过滤：

```sql
(valid_from IS NULL OR valid_from <= :window_end)
AND (valid_until IS NULL OR valid_until >= :window_start)
```

### 3.4 查询范围约束

成员和关系导出应采用等价于下列条件的参数化查询，而不是 `SELECT *`：

```sql
SELECT DISTINCT
  m.id, m.name, m.member_code, m.status
FROM members AS m
JOIN member_org_relations AS r ON r.member_id = m.id
LEFT JOIN org_units AS g ON g.id = r.org_unit_id
WHERE r.relation_type IN ('STUDY_CLASS', 'STUDY_GROUP')
  AND (
    r.org_unit_id = :class_org_unit_id
    OR (g.parent_id = :class_org_unit_id AND g.unit_type = 'GROUP')
  )
  AND (r.valid_from IS NULL OR r.valid_from <= :window_end)
  AND (r.valid_until IS NULL OR r.valid_until >= :window_start)
ORDER BY m.id;
```

若总部 `账户` 字段在同名/同组候选中确实需要消歧，才对上述已范围限定的候选成员追加查询 `m.id, m.phone_masked, m.phone_last4`；快照、对账表和报告均不得展开完整号码。导出的 relation 查询使用相同范围，并保留每条原始有效期，不能压缩为“当前归属”。

主档检查必须确认：

1. 吴越三班唯一存在；1～5 组均为其直属 `GROUP`，精进组能唯一映射为“吴越三班精进组”。
2. 正常组 39 人和精进组 2 人在每个来源日期均有唯一有效的班级/小组关系。
3. 空小组 5 人继续保留观察。其个人学分和班级率资格均为 false；身份未解仅作为单独审计项。
4. 存在唯一 binding/cycle 能解释每个来源日期，并且冻结规则版本和 2026 `CHINA_MAINLAND` 日历可解析。

通过主档检查后，班级率人工基准为：

```text
2026-08-31  39 / 39 = 100%
2026-09-01  39 / 39 = 100%
2026-09-02  39 / 39 = 100%
2026-09-03  39 / 39 = 100%
2026-09-04  39 / 39 = 100%
```

精进组不进入班级率分子或分母。空小组不进入个人积分或班级率。系统若与该基准不同，必须逐人列出关系、身份、日历或规则原因，不修改人工基准迎合结果。

最终 `REAL_FACT_RECONCILIATION=PASS` 的必要条件：所有可参与个人积分或班级率的人员安全识别；小组和学习轮次覆盖完整；五天班级率一致；DRY-RUN 无未解释差异；`learning_credit_entries` 前后数量相同。

在此之前不启动 C7.2。
