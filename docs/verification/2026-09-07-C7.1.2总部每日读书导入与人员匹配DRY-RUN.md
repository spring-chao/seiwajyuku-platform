## 2. 已交付的数据链路

新增 `0050_c7_hq_reading_import`（SQLite/MySQL 及 rollback），保存：

- 导入批次：目标班级、原始文件名、SHA-256、导入人/时间、行数、日期范围和状态；同一班级同一文件哈希唯一。
- 来源身份绑定：`HQ` 来源身份键与永久 `member_id` 的确认绑定，以及首次确认、最近看到的姓名/脱敏账号/小组。
- 逐行观察：来源行、发生日期、来源小组、映射小组、`CLASS_REGULAR` / `CLASS_ADVANCED` / `NO_GROUP` / `UNKNOWN`、录音状态、匹配状态和独立的个人/班级统计资格标志。

服务和 API 保持以下边界：

- 必须先提交目标班级；服务端不根据文件内容猜班级，也不在目标班级外匹配学员。
- 小组只在目标班级的真实组织树中映射；缺失小组不会自动创建。
- 姓名只能形成候选；只有明确身份确认、合法小组和 `录音=提前完成/按时完成/过期完成` 才生成每日读书源事实。
- `精进组`仍计个人每日读书资格，但排除班级完成率分母/分子；空小组保留原始观察但不计个人分、不计班级率；未知小组阻断。
- 工作人员身份与学习资格分开判断；工作人员学习资格不明确时为 `REVIEW_REQUIRED`。
- 已确认来源身份不会被后续文件自动换绑；平台组织关系不因导入而改变，关系不一致返回 `GROUP_MISMATCH`。
- 每日读书源事实不接受 `points`、`score` 或 `credit_points`；分值由既有 C7 `DAILY_ONCE` 规则和发生日期对应的学习轮次/冻结规则/中国大陆业务日历计算。
- 优秀分享只能通过 `EXCELLENT_SHARE_MANUAL_VERIFIED` 受控入口保存“学员、班级、发生日期、说明、依据”；月度 `+1` 和最高 5 分仍由 C7 DRY-RUN 计算。

新增入口：

```text
POST /api/v1/learning-credits/hq-reading/import
POST /api/v1/learning-credits/hq-reading/{batch_id}/confirm-identities
POST /api/v1/learning-credits/hq-reading/{batch_id}/dry-run
POST /api/v1/learning-credits/excellent-shares/manual-verified
```

导入/身份确认使用 `plans:hq_reading_import_manage`；DRY-RUN 使用 `plans:credit_settlement_preview`，并在部署只读模式下保留唯一的总部导入 DRY-RUN 路径。

专项覆盖内容包括：

1. 目标班级范围隔离和跨班同名不误匹配。
2. 同班重名时按小组和脱敏账号缩小候选；无账号不直接按姓名入账。
3. 普通组、精进组、空小组、未知组和目标不存在小组。
4. 工作人员未明确学习资格时 `REVIEW_REQUIRED`。
5. `提前完成`、`按时完成`、`过期完成`、`未提交`、`-`、空值的录音规则；备注字段不能替代 `录音`。
6. 未提交观察后续变成完成时更新观察并生成源事实。
7. 同一学员同一日期的多个来源事实由 C7 合并为一个 `DAILY_READING:{member_id}:{date}` 提案。
8. 同一文件哈希幂等、重叠日期文件不新增观察/事实；来源内容冲突保留并阻断。
9. 平台换组只返回 `GROUP_MISMATCH`，不改组织关系；已绑定 `member_id` 不被清空或切换。
10. 人工优秀分享由服务端执行月封顶，第 6 次保留事实但返回 `MONTHLY_CAP_REACHED`。
11. 完成率汇总工作簿拒绝导入；完整手机号拒绝进入批次。
12. HQ 来源事实不能通过通用事实接口绕过受控导入；导入、身份确认均在单事务中避免半本账。
13. 已生成源事实的后续重叠导入仍保留原学习轮次绑定。
14. SQLite 0050 正向迁移和空数据安全 rollback 在一次性数据库中通过。

隔离测试只使用临时组织、临时学员和合成明细，不代表真实运营对账结果。
