# C7 每日读书与优秀分享 DRY-RUN 验证

基线：G5.3.2 `0f8d213043c035affc48df8fa3db416b7cf01b22` 之后的工作区

## 结论

C7 已完成第一阶段代码实现和本地隔离数据库验证，可以继续保持正式结算关闭，等待业务首批真实事实复核。

本阶段没有执行生产迁移、没有部署生产、没有写入生产数据库，也没有打开 `LEARNING_CREDIT_SETTLEMENT_ENABLED`。C7 没有正式入账接口；两个结算入口均为 DRY-RUN。

## 业务口径

- 每日读书只通过 `CHINA_MAINLAND` 年度业务日历判断工作日，时区固定为 `Asia/Shanghai`。
- `NORMAL_WORKDAY` 和 `ADJUSTED_WORKDAY` 可产生规则规定的每日读书分；`WEEKEND` 和 `HOLIDAY` 为 `NO_CREDIT`。
- 未配置事实发生年份的已发布日历，结果为 `BLOCKED / BUSINESS_CALENDAR_MISSING`，不回退到 `weekday() < 5`。
- 日历按年度、版本号保存；已发布版本不可修改，发布新版本会退役同年度旧版本。
- 优秀分享按事实发生日期的上海时区自然月计算，每人每月最多5分。第6次及以后事实继续保存，结果为 `NO_CREDIT / MONTHLY_CAP_REACHED`。
- 每日读书幂等键为 `DAILY_READING:{member_id}:{YYYY-MM-DD}`；优秀分享幂等键为 `EXCELLENT_SHARE:{member_id}:{fact_id}`。
- 学分规则从事实日期所属学习轮次的冻结 `credit_rule_version_id` 解析；历史轮次不使用当前 active binding 代替。没有唯一轮次、班级关系或规则映射时阻塞，不猜分。

## 实现内容

- `0049_c7_learning_activity_and_business_calendar.sql`：年度日历版本、日历日期、每日读书/优秀分享原始事实表及最小权限。
- 对应 SQLite/MySQL rollback：存在 C7 事实或 C7 账本流水时拒绝有损回滚。
- `learning_activity_credits.py`：事实写入、日历配置、历史轮次解析、`DAILY_ONCE` 和 `MONTHLY_CAP` DRY-RUN。
- `learning_credits.py` 仍是统一账本入口；C7 预览只读取账本检查重复和月度有效余额，不插入 proposal/staging/ledger 行。
- API：
  - `POST /api/v1/learning-credits/activity-facts`
  - `GET /api/v1/learning-credits/business-calendars/{year}`；保存使用 `POST /api/v1/learning-credits/business-calendars`
  - `POST /api/v1/learning-credits/dry-run/daily-reading`
  - `POST /api/v1/learning-credits/dry-run/excellent-shares`

事实写入接口没有 `points` 字段；服务端也拒绝在元数据中携带 `points`、`credit_points` 或 `score`，分值只能来自冻结规则。

## 隔离数据库测试结果

命令：

```text
python -m pytest tests/test_learning_activity_credits.py -q
8 passed
```

覆盖内容：

1. 普通周一、普通周日、工作日节假日、调休周六、调休周日。
2. 年度日历缺失时明确阻塞，且不使用周一至周五回退。
3. 同一学员同一天多个事实合并为一个每日读书幂等键。
4. 连续10次每日读书 DRY-RUN 结果一致、账本数量不变。
5. 2026 与2027日历版本按发生年份独立解析。
6. 同月8次优秀分享前5次 `READY +1`，第6～8次 `NO_CREDIT / MONTHLY_CAP_REACHED`，8条事实均保留。
7. 历史学习轮次按发生日期选择冻结 binding；轮次重叠时 `BINDING_AMBIGUOUS`。
8. `plans:read` 用户不能调用 DRY-RUN；事实 API 不接受客户端学分。

每个 DRY-RUN 都断言 `write_proof.ledger_entries_delta == 0`，并断言全局账本记录数前后一致。

整套平台 API 测试结果为 `503 passed / 4 failed`。4 个失败均为 C7 之前已存在的基线问题：3 个 C6 旧日期/夹具相关失败，以及续费测试夹具重复年度周期唯一约束失败；C7 专项测试和迁移前后检查均通过。

## 放行边界

当前只放行 C7 代码和隔离数据库验证。生产仍需先导入并发布对应年度中国大陆法定节假日及调休日历，再用首批真实事实执行人工对账；在该对账完成前保持：

```text
LEARNING_CREDIT_SETTLEMENT_ENABLED=false
```

本报告不等同于正式学分结算已开启，也不等同于真实生产业务对账已完成。
