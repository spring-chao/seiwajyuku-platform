## 结论

`CORRECTION` 现在保持原 `class_learning_bindings` 和 `learning_round`，不会因为修正计划版本而创建新学习轮次。

当目标 `plan_version_id` 发生变化时，必须存在 `ACTIVE` 且两类规则版本均可用的显式映射；修正会在同一 transaction 内同步更新：

```text
plan_version_id
cohort_month
current cycle.plan_cycle_id / learning_cycle_index
credit_rule_version_id
course_credit_rule_version_id
```

目标计划没有映射时返回 `RULE_MAPPING_MISSING`，不会写入 NULL 规则引用后继续。修正后的 binding `transition_type` 为 `CORRECTION`。

## 正式流水门禁

只要该 learning round 已存在 `POSTED` 或 `REVERSED` 学分流水，就禁止跨计划版本 CORRECTION，并提示先走专门的学分重算/冲销修正流程。该判断以账本历史事实为准，不依赖当前 feature flag 是否暂时关闭。

同一计划内只修正 cohort/cycle 时保留原冻结规则 ID；正常第 1 年到第 2/3 年的自然进阶仍不创建新 binding。
