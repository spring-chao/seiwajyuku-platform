# G5.3.2｜新学习轮次规则映射强制门禁

日期：2026-09-07
基线：`a66accb3e92216096cad5b38dc6fc32cf1b2e013`
范围：为 `INITIAL`、`RESTART`、`RESUME` 新学习轮次增加显式学分规则映射门禁；不部署、不执行生产迁移、不正式入账、不进入 C7。

## 结论

`_create_learning_binding()` 现在在创建 binding 前调用显式计划到学分规则映射解析。没有 `ACTIVE` 映射，或映射所指向的两类学分规则版本不可用时，统一返回：

```text
RULE_MAPPING_MISSING:该学习计划尚未配置可用的学分规则映射，不能开启新的学习轮次
```

因此新建的 `INITIAL`、`RESTART`、`RESUME` binding 不再允许将以下字段留为 NULL：

```text
credit_rule_version_id
course_credit_rule_version_id
```

规则解析失败发生在 binding INSERT 前；`RESTART`、`RESUME` 即使已进入同一 transaction 的旧 active binding 结束步骤，也会因异常整体回滚。旧的历史 NULL binding 不删除、不猜测规则，仍可被读取并交给 `CORRECTION` 修正流程。

## 测试调整

G5.3.1 的历史错误绑定测试不再通过正式 `restart_class_learning_plan()` 创建未映射新轮次，改为测试夹具直接插入 legacy/unmapped binding。这样测试同时验证了：

- 正式生命周期入口不能产生未映射新轮次；
- 历史 NULL binding 仍可跨计划 CORRECTION 到有映射计划；
- CORRECTION 不改变原 binding ID 和 `learning_round`。

学习轮次通用测试计划均补充显式测试映射，避免测试夹具继续模拟一个不应被正式生命周期入口接受的新计划。

新增/覆盖的门禁场景：

- 未映射计划 `INITIAL` 拒绝；
- 未映射计划 `RESTART` 拒绝；
- 未映射计划 `RESUME` 拒绝；
- 拒绝后原 active binding 状态、ID、轮次和记录数不变；
- 有映射计划仍可正常创建并冻结两类规则 ID；
- 历史 NULL binding 可通过 CORRECTION 修正；
- 无映射目标计划的 CORRECTION 仍拒绝；
- 已有正式 `POSTED/REVERSED` 流水的跨计划 CORRECTION 仍拒绝。
