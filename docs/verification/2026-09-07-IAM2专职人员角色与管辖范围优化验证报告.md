# IAM 2.0｜专职人员角色与管辖范围优化验证报告

- 验证日期：2026-09-07
- 验证范围：专职人员一体化管理、显式角色—管辖范围授权、历史兼容解析及迁移预览
- 生产动作：未执行生产数据库读取、写入、迁移或部署

## 任务结论

本次实现将普通运营场景中的账号、专职人员、任职岗位、角色和管辖范围收敛到“专职人员管理”页面。岗位继续保留为任职与历史记录；系统权限改由 `employee_authorization_grants` 中的单条“角色 + 组织 + UNIT/SUBTREE + 有效期 + 状态”授权决定，避免角色集合与范围集合产生笛卡尔组合。

旧任职记录在没有任何显式授权记录时继续按原岗位与服务责任范围兼容解析；一旦存在显式授权记录（即使该记录后续过期、暂停或撤销），不会静默回退到岗位权限。兼容迁移页面仅生成无写入预览，不会自动迁移人员。

| 范畴 | 结果 |
| --- | --- |

| 人员操作 | 新建、变更预览、保存、停用、重置密码、角色权限只读预览、兼容迁移预览均有服务端门禁或审计。停用和账号变更会增加令牌版本并废止现有刷新会话。 |

| 数据库 | SQLite/MySQL 均提供 `0051_iam2_staff_authorization` 正向及回滚脚本。回滚脚本在存在 IAM2 授权、人员资料或新增任职字段数据时拒绝继续，避免丢失数据。 |

## 已验证的关键边界

- 多角色、多组织场景下：`employee_member_management` 的 SUBTREE 授权只覆盖其自身组织树，不能借用 `employee_learning_management` 的另一组织范围。
- UNIT 与 SUBTREE 均已覆盖；重复“角色 + 组织 + 范围”组合会在预览中去重。
- 已过期显式授权不会恢复旧岗位模板权限。
- 新建自动密码只返回一次，不写入审计；列表不返回明文手机号。
- 保存前可查看前后差异；新增敏感权限要求授权依据和业务原因。
- 停用账号后旧访问令牌失效、刷新会话被撤销；任职和授权历史未删除。
- 平台系统管理员以外的 IAM 操作员无法通过旧接口授予系统或受限角色。
