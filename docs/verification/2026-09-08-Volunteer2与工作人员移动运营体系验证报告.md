# Volunteer2 与工作人员移动运营体系验证报告

- 验证日期：2026-09-08
- 范围：第二期志工服务组织、工作人员移动运营、微信身份绑定与 IAM2 精确授权
- 结论：通过代码与自动化回归验证；本次未执行生产部署、生产迁移或生产数据写入。

## 已验证的业务规则

1. 专职权限以“账号启用 + 在职 + IAM2 当前角色 × 组织范围授权”判定；工作人员移动端在每次操作时解析现有后台账户、在职关系和 IAM2 授权，不保存移动端角色或范围副本。
2. 志工必须关联正式学长；志工资格以前置的学长在册状态判定。学长非在册时，全部志工授权立即失效，但任职历史保留。
3. 志工岗位采用当前有效的服务组织单元、岗位和服务范围，不使用普通业务开始日期、结束日期或自动到期。已结束或撤销的岗位在学长恢复在册后不会自动恢复。
4. 同一学长可保留多个 V2 当前志工岗位；V2 岗位不会写入旧版“单一当前岗位”字段，也不会把志工岗位误映射为后台广泛权限。
5. 专职离职不改变学长身份。只要学长仍在册且有当前有效志工岗位，志工服务能力仍按岗位和范围计算。
6. 微信绑定升级为人员绑定：学长可走原有正式学长绑定；工作人员可在验证既有后台账户、人员关联、在职关系和 IAM2 授权后绑定，无需伪造学长档案。一个人可同时呈现学长、志工、工作人员身份。

## 交付内容

- 新增志工服务组织单元（VSU），拆分上级服务组织路径、塾归属和正式服务对象；不通过组织名称推断三大委或服务范围。
- 新增 V2 志工岗位目录、岗位任命、状态结束或撤销、推荐规则和人工接受流程。推荐只生成待确认建议，不自动创建目标任命。
- 为 SQLite 和 MySQL 增加 0053 前向迁移及回滚脚本。回滚在发现 V2 服务组织、规则、链接、V2 任命或人员微信绑定等不可无损数据时会阻止执行，避免静默丢失数据。
- 新增无写入的迁移预检接口，用于列出旧志工记录与唯一候选服务组织或岗位；实际迁移需逐项人工确认。
- 后台新增志工服务组织与任命管理页，支持按姓名、体系、线条、塾归属、服务组织、岗位、服务对象和状态筛选。
- 小程序新增工作人员绑定及移动运营工作台、今日待办、学员查询、跟进和学习会记录入口。

## 授权与数据边界

- 工作人员移动运营仅复用现有 IAM2：employee_authorization_grants、roles、role_permissions 与组织范围的实时结果。
- 员工离职会立即失去工作人员移动操作能力；账户停用同样阻断访问。
- 学长非在册会立即失去志工服务能力；恢复在册只恢复仍为当前有效的岗位。
- V2 志工岗位仅用于移动端服务能力和范围，不默认授予后台系统管理权限。
- 写操作仍受既有身份写入开关约束；功能开关默认关闭，未改变生产 IAM 写入门禁。
