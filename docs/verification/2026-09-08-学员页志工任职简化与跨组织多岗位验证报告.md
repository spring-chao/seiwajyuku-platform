# 学员页志工任职简化与跨组织多岗位验证报告

- 执行日期：2026-09-08 至 2026-09-09
- 范围：学员编辑页、Volunteer 2.0 任职 API、志工能力汇总、历史任职、管理端回归
- 发布边界：仅完成代码与验证；未部署生产，未执行生产数据库迁移或数据迁移

## 结论

日常单个学长的志工任职已回到“学员管理 → 编辑学员”。当前任职以轻量标签展示，可以在同一页面连续添加多条班组委或条线管理任职，也可以一次确认结束其中一条；历史任职折叠保留。原独立志工任职管理页继续用于全局筛选、批量、服务组织和高级管理。

本次没有新建任职表，继续复用 `volunteer_appointments`、`volunteer_position_catalog`、`volunteer_service_units`、`volunteer_position_capabilities`、正式组织关系和原有能力汇总。

## 业务规则验证

- “班组委 / 条线管理”仅是本次新增任职的分类，不是人员身份二选一。
- 班主任、副班主任、班长按班级过滤；辅导员、组长先选服务班级，再按正式父子关系过滤该班小组。
- 二级塾、分中心、班级三大委岗位按岗位配置的正式层级过滤服务组织；前端不根据名称猜测组织。
- 学长当前学习班级/小组只用于智能默认，不限制服务组织；改变学习班级不会改写已有 Volunteer 2.0 服务范围。
- 多条 V2 任职在兼容学员档案接口中不再被标为“主要岗位待确认”。旧式、未迁移的多条兼容任职仍按原规则进入人工复核。
- 结束一条任职只结束该记录，其余任职及能力继续有效；历史保留结束时间和状态。
- 非在册时全部当前志工能力立即失效；恢复在册后，仅仍为 ACTIVE 的岗位重新生效，已结束岗位不会复活。

## 三条跨组织任职专项

自动化构造了一个学习归属在炎武二班的在册学长，并同时建立：

1. 昆山分中心验收样本 · 发展建设委副董事长；
2. 炎武一班验收样本 · 班主任；
3. 炎武一班验收样本 · 感恩组验收样本 · 辅导员。

验证结果：三条记录均为独立 ACTIVE appointment；服务对象分别是分中心、另一班级、另一班级下小组；小程序服务模型按三条任职聚合能力，不要求主要岗位。结束班主任后仍保留另外两条，辅导员能力继续存在；恢复在册时该已结束班主任没有复活。

## 管理端交互验证

- 当前任职使用可换行的标签区域；只有具备学员管理权限的操作人可以结束任职。
- 新增区保持“志工类型 + 岗位 + 服务组织 + 添加”的一行主交互，组级岗位增加“服务班级”选择。
- 普通界面只展示志工类型、岗位、服务班级、服务小组、服务组织、当前任职、历史任职、添加任职等业务词。
- 独立志工页顶部已明确其批量、服务组织和高级管理定位。
