# 志工在册状态与岗位授权修订验证报告（2026-09-08）

## 验收结论

已将身份有效性收口为以下独立门禁：

```text
登录账号：app_users.is_active = true
专职人员：operations_employments.employment_status = ACTIVE
志工：members.status = ACTIVE + volunteer_appointments.status = ACTIVE
专职、志工权限：均继续按角色 × 组织范围精确计算
```

志工必须直接关联正式 `member_id`。普通志工岗位不再接收业务开始/结束日期，也不因预设日期自动失效；创建时间与结束操作时间仅作为档案和审计记录。

## 已实现内容

- 新增 `0052_volunteer_membership_authority`（SQLite/MySQL）迁移：为 `volunteer_appointments` 增加 `member_id`，仅对唯一可确认的旧身份关联安全回填；无法确认的旧记录保留历史但不能成为当前授权。
- 志工授权、微信身份能力、学员当前志工服务及学习会健康检查均改为直接读取“在册学长 + ACTIVE 岗位”，不再读取志工 `starts_at` / `ends_at` 作为权限条件。
- 结束或撤销志工岗位时记录 `ended_at` 审计时间；学长非在册立即失去志工权限，恢复在册时仅未结束的 `ACTIVE` 岗位重新生效。
- 专职授权统一改为“账号启用 + 雇佣 `ACTIVE` + 角色范围 `ACTIVE`”；任职/授权日期可保留历史，但不再自动授予或收回普通专职权限。
- 专职人员管理、身份高级入口和学员志工入口均移除普通业务任期输入，改为显式在职/离职或岗位结束操作。
- 本地身份试点种子改为显式 `ACTIVE` 专职状态，且新建普通专职记录不写业务任期日期。
- 前端标准构建脚本改为跨平台 Node 调用，`pnpm build` 可直接在当前 Windows 环境执行。

规则说明见：[志工身份与授权有效性规则](../design/2026-09-08-志工身份与授权有效性规则.md)。
