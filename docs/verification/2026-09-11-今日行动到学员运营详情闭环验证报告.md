## 3. 实现内容

### 后端

`build_member_care_actions()` 现在同时返回：

- `people`：按学员聚合的待处理行动；
- `source_coverage`：续费、关爱、生日来源各自的可用性，来源异常不会伪装成 0；
- `completed_today`：从原有跟进、走访、续费和生日完成记录读取的今日完成投影；
- `summary.completed_people_count` / `summary.completed_action_count`：完成人数和动作数。

完成投影只保留运营展示所需的最小字段，不暴露跟进中的客观事实、主观判断或敏感服务内容。生日的运营事项完成与学员级完成表会按学员和生日年度去重。

当天已记录跟进/走访且没有明确下一次时间的开放事项，不再继续出现在待处理列表；原任务仍留在跟进 domain 中，历史和审计不变。当天明确关闭的任务也能进入“今日已完成”投影。

### 管理端

- dashboard 的关爱卡片升级为“今日行动”，增加“待处理 / 今日已完成”视图；
- 待处理仍按原有来源、紧急度和学员聚合展示；
- 已完成视图显示学员、归属、完成动作和时间，并可回到同一学员运营详情；
- `MemberDetailDrawer` 增加“关键事实”区，续费、学习、关爱、志工均从现有时间线/任职接口读取；
- 生日继续直接完成并刷新；续费、跟进/走访继续通过各自 canonical 页面完成，返回 dashboard 时由 `onActivated` 重新加载。

CI 管道增加 `today-action-loop.test.mjs`，检查今日行动的待处理/完成视图、完成投影、详情聚合和动作导航仍然存在。

## 5. 业务验收清单

生产业务验收仍需由运营账号实际执行，当前不将自动化结果等同于生产验收：

1. 续费、日常关怀/走访、生日三来源能在“今日行动”正确聚合；来源异常时显示“暂不可用”，不显示为 0。
2. 点击“去处理”进入学员运营详情，能看到现有续费、学习、关爱、志工事实。
3. 生日完成、续费跟进、日常关怀/走访记录完成后返回 dashboard，行动自动刷新并进入“今日已完成”。
4. 续费阶段继续符合“观3、续2、追1”，不把所有人显示成催缴。
5. 江南/苏州/常州/无锡组织范围继续由 IAM2 控制，不能越权查看其他组织。
6. 无锡组织筛选保留“指导一团、指导二团、直属无锡塾的精进班”，精进班不被强制挂入指导团。
