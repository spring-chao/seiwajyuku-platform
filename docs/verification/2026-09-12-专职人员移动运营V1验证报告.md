# 专职人员移动运营 V1 验证报告

日期：2026-09-12
范围：微信小程序专职人员移动运营 V1；未发布生产。

## 交付结论

V1 已形成手机端高频运营闭环：

`今日行动 → 学长查询/详情 → 记录一次关爱 → 今日行动刷新`

首页仅保留“今日行动、学长查询、关爱跟进、续费关注”四个入口。没有新增移动端任务表、人员表、角色表、组织范围表、关爱事实表或续费事实表。

## 复用的事实与权限能力

| 场景 | 复用能力 |
| --- | --- |
| 今日行动 | `build_member_care_actions` 的续费、关怀、生日三来源及今日已完成投影 |
| 学长查询与详情 | 学员主档、组织关系、学习/关爱时间线、Volunteer 2.0 当前任职 |
| 关爱记录 | `followup_tasks`、`followup_records`、现有审计和今日行动刷新规则 |
| 续费关注 | `renewal_cycles`、`renewal_followups`、既有“观3 / 续2 / 追1”阶段引擎 |
| 身份与范围 | person session、有效专职雇佣、`employee_authorization_grants`、IAM2 permission × scope |

## 新增移动聚合接口

- `GET /api/v1/wechat/operations/members/{member_id}`
- `POST /api/v1/wechat/operations/members/{member_id}/care-records`
- `POST /api/v1/wechat/operations/members/{member_id}/renewal-care-records`
- `POST /api/v1/wechat/operations/members/{member_id}/birthday-care`
- `POST /api/v1/wechat/operations/members/{member_id}/contact-access`
- `GET /api/v1/wechat/operations/renewal-watch`

已有工作台、今日行动、学长查询 API 均保持兼容，并扩展为本轮的移动读模型。

## 安全与 IAM2 结果

- 每个移动运营请求都重新从 person session 解析有效账号、在职状态、有效 IAM2 grant 和对应组织范围。
- BFF 按单个 permission 过滤 grant 后再调用既有领域服务，避免将不同角色的组织范围错误交叉组合。
- 学长搜索支持姓名和手机号后 4 位；结果与详情默认不返回完整手机号。
- 完整手机号只通过单人、按次的 `contact-access` 获取：必须同时具备现有 `contact:reveal` 与 `followups:manage`，校验当前组织范围、联系用途、有效任务归属，并写入既有审计与联系方式访问日志。
- 页面离开或卸载时清除仅存在于当前页面内存的完整手机号。
- 工作人员账号停用、离职或最后一条 IAM2 grant 被撤销后，移动运营 API 立即返回拒绝；自然人微信绑定不被删除。
