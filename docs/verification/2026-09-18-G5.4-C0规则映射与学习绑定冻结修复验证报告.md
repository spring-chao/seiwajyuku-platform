## 1. 根因结论

根因已由迁移链、规则定义、测试和生产只读状态共同确认。

`0048_learning_plan_credit_rule_mapping.sql` 使用 `INSERT OR IGNORE` / `INSERT IGNORE` 创建课程规则版本：

```text
STANDARD_3Y_2026 / 2026.1 / PUBLISHED
```

生产在执行 0048 前已经存在同一 `plan_key + version_label` 的课程规则版本，因此唯一约束使插入被忽略；该语句不会把既有 `DRAFT` 更新为 `PUBLISHED`。随后 mapping 的 INSERT 又要求课程规则版本为 `PUBLISHED`，所以 mapping 保持 0 条，已有学习绑定无法冻结两类规则引用。

生产只读结果：

| 对象 | 结果 |
| --- | --- |
| 课程规则版本 | id=3，`STANDARD_3Y_2026 / 2026.1`，`DRAFT` |
| 课程规则行数 | 14 |
| 已配置课程行数 | 9 |
| 课程分值合计 | 225 |
| `standard-3y / 2026` mapping | 0 |
| ACTIVE binding 的两类规则引用 | 19 条均为空 |

仓库冻结定义 `data/learning-plans/course-credit-rules-2026.json` 是 25 条、全部 `CONFIRMED`。生产现有内容不仅不完整，且至少有分值差异：`Y1-KYOCERA-ANNUAL-PLAN` 为生产 30、仓库 40；`Y1-ANNUAL-MONTHLY-MGMT` 为生产 15、仓库 11。因此不能把本次问题当成单纯的状态提升，也不能在生产直接发布当前 14 条内容。

## 2. C0 修复迁移

新增成对迁移：

- `migrations/mysql/0064_fix_credit_rule_mapping_and_binding_freeze.sql`

迁移行为：

1. 仅识别 `STANDARD_3Y_2026 / 2026.1 / based_on=2026` 这一目标身份。
2. 只在全新空课程规则目录中初始化冻结的 25 条定义；对部分存在的目录不猜测、不补齐。
3. 检查目标课程规则身份、25 条数量、名称、年度、分值和 `CONFIGURED` 状态。

5. 已存在但不准确的 mapping 直接 fail closed；不覆盖已有非空 binding 引用。
6. 课程版本通过全部门禁后才提升为 `PUBLISHED`，并创建唯一 `ACTIVE` mapping。
7. binding 两类规则引用只通过 `COALESCE` 补 NULL；已有冻结引用不被覆盖。
8. `study_meeting_courses.credit_rule_version_id` 只在能够沿 course → session → cycle → binding 唯一解析且当前值为 NULL 时补齐；不能解析的保持 NULL。
9. 迁移主体使用事务边界，避免前置检查失败后留下部分初始化。

## 3. 回滚保护

rollback 只允许未被使用的 C0 状态回退：

- 空数据、未被 binding、课程事实、活动事实或账本引用时，可以清理 C0 状态表和本次新增 mapping；
- 已存在 frozen binding、课程事实、活动事实或账本引用时，通过 `CHECK(n=0)` 拒绝回滚；
- 不清空已有冻结引用，不把已使用的 `PUBLISHED` 强行降回 `DRAFT`；
- 若迁移前已经存在 mapping，rollback 保留原 mapping 元数据。
