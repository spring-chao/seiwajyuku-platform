## 1. C1 数据底座

新增成对迁移：

- `migrations/sqlite/0065_learning_credit_history_import.sql`
- `migrations/mysql/0065_learning_credit_history_import.sql`
- 对应 SQLite/MySQL rollback 文件

三层数据结构为：

1. `learning_credit_import_batches`：文件指纹、来源规则身份、批次状态和解析摘要；`(file_sha256, import_type)` 唯一，重复上传幂等。
2. `learning_credit_import_rows`：一行对应 Excel 一个学员来源行，保留工作表、行号、姓名、班级、小组、原始总分、计算总分、校验状态和匹配状态。
3. `learning_credit_import_items`：每个非零来源学分单元格一条 item，保留 `source_sheet`、`source_row_number`、原始列名、列号、月份、标准化历史类型、分值和来源规则身份。

历史规则身份固定为：

```text
LEGACY_SUZHOU_2026_V1
```

它表示人工历史来源分值，不调用 `DAILY_ONCE`、`MONTHLY_CAP`、`CYCLE_ONCE` 或其他当前规则重新计算 1—8 月历史分。

## 4. 身份匹配和 DRY-RUN

本轮只定义 `MemberMatchingService` 接口，没有实现自动确认。没有权威的 member、组织关系和历史学习轮次快照时：

```text
match_status = NOT_RUN
matched_member_id = NULL
match_reason = PLATFORM_MEMBER_SNAPSHOT_REQUIRED
```

全量真实工作簿在隔离库完成登记后，DRY-RUN 结果为：

```text
batch_status                  = NEEDS_REVIEW
proposed_item_count           = 0
proposed_points               = 0
blocked_reason                = PLATFORM_MEMBER_SNAPSHOT_REQUIRED
learning_credit_entries_delta = 0
ledger_write                  = false
learning_credit_entries count = 0
```

重复登记相同文件和导入类型返回同一批次，不形成第二套待入账数据。当前 API 只提供登记、解析结果、异常、行明细和 DRY-RUN；没有 `POST_TO_LEDGER` 接口。
