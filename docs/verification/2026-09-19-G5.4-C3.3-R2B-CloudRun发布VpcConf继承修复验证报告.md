## 1. 结论

R2A 已将根因确定为 `REVISION_VPC_CONFIG_NOT_INHERITED`，详见 [G5.4-C3.3-R2A 新 Revision 私网网络根因只读审计](2026-09-19-G5.4-C3.3-R2A新Revision私网网络根因只读审计.md)。R2B 已把修复收敛为一个适用于所有后续 API revision 的受控发布器：

```text
DescribeCloudRunServerDetail
  -> 唯一 100% stable revision
DescribeVersionDetail(stable)
  -> 版本级 VpcConf（权威基线）
UpdateCloudRunServer
  -> DeployInfo + DiffConfigItem(Key=VpcConf)
DescribeVersionDetail(candidate)
  -> 四字段完全一致断言
ReleaseGray(URL_PARAMS one-time token)
  -> build-info + liveness + DB health 20/20
  -> 通过后才允许普通灰度/全量
```

本阶段没有运行脚本的 `--execute`，没有调用任何生产写接口。

## 2. 旧路径与新路径

旧路径把裸 `tcb cloudrun deploy` 当成现有服务的完整生产发布入口。R2A 证明该 CLI 路径不会可靠地读取并复制稳定版本 `253` 的版本级 `VpcConf`；当服务级 `ServerConfig.VpcConf` 为空时，新版本可正常构建但失去生产 MySQL 私网连通性。

新正式入口为：

```text
scripts/deploy_cloudrun_api.py
```

脚本固定 `ENV_ID` 与 `seiwajyuku-platform-api`，不接受任意环境、服务名、TencentCloud action 或 VPC/subnet 参数。普通调用者只能选择受控的源码包、不可变镜像或稳定镜像配置发布；网络字段由稳定 revision 继承层独占管理。真实网络迁移不在本工具范围内，必须另建 `NETWORK_CHANGE` 授权流程。任何 `--execute` 还必须加载该提交在 `main` 完成 9 项 CI 后生成的 release provenance manifest，校验 `ci_conclusion=success` 与 commit 完全一致。

裸 `tcb cloudrun deploy` 已在现行发布文档中标记为不能单独构成生产发布或完成证明；历史可行性文档保留原命令并明确其已被替代。

## 3. 为什么使用 UpdateCloudRunServer

正式路径选择 `UpdateCloudRunServer`，不选择 `SubmitServerConfigChangeDiff`：

- 两者都支持 `Items: DiffConfigItem[]`，因此都能表达 `Key="VpcConf"`。
- `UpdateCloudRunServer` 同时具有显式 `DeployInfo`，可统一承载 package、image 和配置发布，并返回任务信息。
- `SubmitServerConfigChangeDiff` 的官方语义是“更新配置并使用最新镜像发布”，没有同等的显式发布制品输入，不适合作为源码/镜像/配置三类发布的唯一入口。

发布器通过 `tencentcloud-sdk-python-tcbr` 的 `VpcConf`、`DiffConfigItem`、`DeployParam` 和 `UpdateCloudRunServerRequest` 类型构造请求，不使用 shell 拼 JSON 或手工签名 HTTP 请求。源码包上传使用官方 TCB SDK 取得受控上传地址，临时 Git archive 仅包含目标提交，并注入不含秘密的构建印章。

## 4. stable revision 与版本级网络基线

发现规则：

1. `DescribeCloudRunServerDetail.BaseInfo.Status` 必须为 `normal`。
2. 部署记录不得有 `IsReleasing=true` 或 `Status=deploying`。
3. `OnlineVersionInfos` 中必须只有一个正流量版本，且其 `FlowRatio=100`。
4. 分流、无 100% 版本、服务异常或活动发布均返回 `STABLE_REVISION_NOT_UNIQUE`。
5. 随后只调用 `DescribeVersionDetail(stable)` 读取 `VpcConf`；不会回退到服务级配置。
6. 稳定版本缺少 `VpcId` 或 `SubnetId` 返回 `VPC_BASELINE_MISSING`。
7. 如批准包提供只读数据库 VPC 证据，`--expected-database-vpc-id` 不一致返回 `VPC_DATABASE_MISMATCH`。

`VpcId`、`VpcCIDR`、`SubnetId`、`SubnetCIDR` 以固定字段顺序做 SHA-256 fingerprint。生产 VPC/subnet 值没有写入发布逻辑；真实值只存在于 R2A 报告与脱敏回归 fixture。

## 5. 显式继承与 candidate 断言

每个代码或环境变量发布请求均至少包含：

```text
DiffConfigItem:
  Key = VpcConf
  VpcConf = stable DescribeVersionDetail.VpcConf
```

环境变量变化以稳定版本的 `EnvParams` 为底合并，再作为单独的 `EnvParam` diff item 提交；即使仅改变一个门禁，也仍携带稳定 VPC。无环境变化的普通代码发布同样携带 VPC item。

候选以 `DeployParam.ReleaseType=GRAY` 创建，不会由发布请求直接全量。候选变为 `normal` 后重新调用 `DescribeVersionDetail(candidate)`，逐字段严格比较四个 VPC 字段。空值、部分缺失、错误 subnet 或任一 CIDR 变化均返回 `CANDIDATE_VPC_MISMATCH`，此时 `ReleaseGray` 调用数为零。

## 6. 确定性 candidate 路由与健康门禁

版本级 VPC 断言通过后，发布器生成仅存于进程内的一次性 token，并用官方 `ReleaseGray` 类型构造：

```text
TrafficType = URL_PARAMS
stable.IsDefaultPriority = true
candidate.UrlParam = {Key: sj_canary, Value: <one-time-token>}
```

所有候选请求都携带该参数；默认请求仍进入 stable。定向验证顺序为：

1. `/api/v1/system/build-info`：`commit_sha` 必须等于批准提交；
2. `/health/live`：HTTP 200 且 `status=ok`；
3. `/api/v1/health`：真实执行 `SELECT 1`，必须 20/20 HTTP 200 且 `status=ok`；
4. 再读一次 build-info，防止验证过程中身份变化。

数据库健康任一次失败返回 `CANDIDATE_DATABASE_NOT_READY`，取消定向路由并恢复 stable 100%；不能以默认域名的随机 5% 响应替代该证据。token 不进入 Git、环境变量、数据库或长期日志，安全输出也不显示 token。

## 7. 状态机与失败关闭

```text
DISCOVER_STABLE
READ_STABLE_VERSION
BUILD_PLAN
CREATE_CANDIDATE
VERIFY_CANDIDATE_CONFIG
TARGETED_HEALTH
READY_FOR_RELEASE
GRAY
FULL
VERIFIED
```

`--promotion ready` 在门禁通过后恢复 stable 默认路由并停在 `READY_FOR_RELEASE`；`gray` 和 `full` 只在额外批准范围内继续。前置失败进入 `BLOCKED`，候选创建后的失败进入 `FAILED`。网络断言失败前不会设置任何 candidate 路由；定向健康或全量验证失败会尽力恢复 stable 100%。

## 8. dry-run 与敏感信息保护

`--dry-run` 只执行服务、部署记录、稳定版本和稳定 build-info 的只读查询，输出：

- stable revision 与版本级 VPC/fingerprint；
- desired commit 与发布类型；
- 环境变量变更键及 `changed`／`unchanged`；
- candidate 请求将携带的 VPC；
- candidate 创建、定向路由和健康策略。

dry-run 不申请包上传地址、不上传源码、不调用 `UpdateCloudRunServer` 或 `ReleaseGray`。`DATABASE_URL`、密码、JWT、加密密钥、token 与 API key 等值不会进入安全 plan、日志或报告；仅 allow-list 中的非敏感布尔门禁可显示 `true`／`false`。
