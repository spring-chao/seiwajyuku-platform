# G5.4-C3.3-R2B 生产候选 Revision 连通性验证批准包

编制日期：2026-09-19
拟申请阶段：`G5.4-C3.3-R2C`
状态：**待单独批准；本文件本身不授权执行**

## 1. 唯一目标

R2C 只允许用 R2B 受控 wrapper 创建一个 **G5 flag=false 的纯网络验证 candidate**，证明新 revision 能正确继承当前稳定 revision 的版本级 VPC，并通过定向的数据库健康检查。

它不是规则 APPLY，不是迁移，不是生产网络迁移，也不是普通流量发布。通过或失败后均保持当前稳定 revision 为默认 100% 流量，并在 `READY_FOR_RELEASE` 停止。

## 2. 执行前必须重新只读核验

生产状态会变化，R2A 的 `253` 只作为历史安全基线，执行时不得写死。R2C 开始前必须重新确认：

1. R2B 最终 `main` 提交的 CI 为 9/9 PASS，含 `build-provenance`；
2. `DescribeCloudRunServerDetail` 只有一个 100% stable，服务正常、无活动发布；
3. `DescribeVersionDetail(stable)` 的 `VpcId`、`VpcCIDR`、`SubnetId`、`SubnetCIDR` 完整；
4. 只读数据库资源证据的 VPC 与 stable VPC 一致；
5. stable 默认健康与 build-info 正常；
6. G5、settlement、bootstrap 的当前稳定值已经只读确认；
7. wrapper `--dry-run` 显示 candidate 请求 VPC 与 stable 四字段完全一致，revision/network/config/database writes 均为 0。

任一条件不满足即 `BLOCKED`，不得为了继续测试改 VPC、subnet、安全组、MySQL 或服务级网络配置。

## 3. 拟批准的唯一写动作

在另行明确批准 R2C 后，允许：

- 固定环境与固定服务 `seiwajyuku-platform-api`；
- 复用当前 stable image，创建 **一个** `ReleaseType=GRAY` candidate；
- `UpdateCloudRunServer.Items` 显式携带从 stable version 读取的同一 `VpcConf`；
- 显式保持以下非敏感运行门禁：

  ```text
  G5_4_PRODUCTION_RULE_APPLY_ENABLED = false
  LEARNING_CREDIT_SETTLEMENT_ENABLED = false
  RUN_BOOTSTRAP_ON_STARTUP            = false
  ```

- candidate `normal` 后，只读回读版本详情并逐字段断言 VPC；
- 仅设置一次性 `URL_PARAMS` candidate 定向路由；
- 定向核验 build-info、`/health/live`、`/api/v1/health` 20/20；
- 成功或失败后取消定向路由，恢复 stable 100% 默认流量；
- 保留 candidate 及最小审计证据，不删除稳定版本或共享资源。

候选实际编号由腾讯云生成；本批准包不预写 `257`，也不允许因编号不同重复创建。

## 5. 预期命令形态

以下只描述形态，不得在 R2B 执行；提交、stable commit、build id、批准编号和只读数据库 VPC 均须在 R2C 当场取得：

```powershell
python scripts/deploy_cloudrun_api.py `
  --commit <当前stable运行提交> `
  --reuse-stable-image `
  --env-file <仅含三个false门禁的临时JSON> `
  --expected-database-vpc-id <只读查询值> `
  --execute `
  --release-manifest <stable提交的9项CI产物/release-manifest.json> `
  --approval-ref G5.4-C3.3-R2C-<批准编号> `
  --promotion ready
```

临时 env 文件不得提交 Git；输出只能记录键、变更状态与三个非敏感布尔值。

## 7. 停止与恢复条件

以下任一情况立即停止，不创建第二个 candidate：

- `STABLE_REVISION_NOT_UNIQUE`；
- `VPC_BASELINE_MISSING` 或 `VPC_DATABASE_MISMATCH`；
- candidate 构建/启动失败；
- `CANDIDATE_VPC_MISMATCH`；
- build-info 不等于批准提交；
- liveness 非 200；
- 数据库健康不足 20/20；
- 发现任一门禁不是 false；
- 发生未批准的普通流量、配置、网络或数据库变化。

如已经设置定向路由，只恢复 stable 100% 默认路由；不改 VPC/subnet/安全组/MySQL，不 APPLY，不执行 `0064`，并输出失败关闭报告。R2C 完成后必须停止，后续动作重新申请。
