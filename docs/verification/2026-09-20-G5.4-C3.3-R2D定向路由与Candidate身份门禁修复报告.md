## 1. R2C 假阳性根因

R2C 中 `ReleaseGray` 返回成功，发布器立即发出 23 个探针并把 HTTP 结果记为 `20/20`。事后 CLS 只读日志证明 23 条请求的 container/pod 标签全部属于 stable 253，candidate 257 命中为 0。因此：

```text
VpcConf 修复                         = PASS
ReleaseGray 成功响应                 = 不能证明路由生效
TARGETED_CANDIDATE_IDENTITY          = FAIL
NEW_REVISION_DB_CONNECTIVITY         = NOT_PROVEN
```

相同 runtime commit 不能识别 253 和 257；`253=100% / 257=0%` 也不表示发布单已经结束。

## 2. R2D 代码修复

`scripts/deploy_cloudrun_api.py` 现按以下顺序工作：

```text
ReleaseGray
  -> DescribeReleaseOrder + DescribeCloudRunServerDetail 轮询
  -> TARGETED_ROUTE_ACTIVE
  -> DescribeCloudRunPodList candidate >= 1 可运行实例
  -> 2 build-info + 1 liveness + 20 database health
  -> SearchClsLog 等待完整 23 条并确认 candidate=23、stable=0、unknown=0
  -> CANDIDATE_IDENTITY_VERIFIED
  -> READY_FOR_RELEASE
  -> 恢复 stable 100% / candidate 0%
  -> TRAFFIC_RESTORED
```

路由激活门禁同时要求：`TrafficType=URL_PARAMS`、CurrentVersion/ReleaseVersion 对应 stable/candidate、stable 默认优先、candidate 非默认优先，以及 `sj_canary` token 在 UrlParam 或 TrafficTypeValues 中一致。路由未激活时不发送任何候选探针，超时返回 `CANDIDATE_ROUTE_NOT_ACTIVE`。

发布器新增 `DescribeReleaseOrder`、`DescribeCloudRunPodList`、`SearchClsLog` 的只读 SDK 适配。活动 `IsReleasing=true` 在稳定版本发现阶段返回 `ACTIVE_RELEASE_ORDER_EXISTS`，阻止创建新 candidate。恢复流量后另行验证 `TrafficType=FLOW`、stable 100%、candidate 0%；不调用 `OperateServerManage`，不猜测 `cancel`、`go_back` 或 `done` 的语义。
