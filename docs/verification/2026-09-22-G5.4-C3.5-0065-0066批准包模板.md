## 两个硬检查点

### Checkpoint A：0065

仅执行`0065_learning_credit_history_import.sql`，确认batch/row/item三类表、约束、索引和受控权限存在，全部staging表为空，ledger不变。未通过不得执行0066。

### Checkpoint B：0066

仅在A通过后执行`0066_historical_credit_time_precision_review.sql`，确认：

```text
learning_credit_entries supports EXACT_DATE / MONTH / YEAR
learning_credit_import_rows has credit/match review fields
learning_credit_import_items has occurred precision and period review fields
class mapping and decision tables exist
staging row count = 0
ledger = 0 / 0.00
settlement = false
```

迁移执行不等于历史数据POST。0065/0066都没有向`learning_credit_entries`插入业务记录的授权。

## 回滚与失败关闭

在所有staging表为空、无非EXACT_DATE账本事实时，可按0066→0065顺序验证down脚本；一旦存在导入item、mapping、decision或非EXACT_DATE ledger，down应拒绝，恢复必须走备份或批准的前向修复。不得删除真实staging证据来制造“可回滚”。

0065或0066任一步失败即停止；不得跳过失败迁移继续后续步骤。

## 明确不授权

历史Excel上传、批次登记、匹配、审核、DRY-RUN、ledger POST；R3或0064；settlement开启；任何CloudRun控制面写操作。
