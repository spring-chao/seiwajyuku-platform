## 迁移与rollback审计

| 迁移 | 代码能力 | ledger影响 | rollback边界 |
| --- | --- | --- | --- |
| 0046 | 通用规则版本、规则、统一ledger、binding规则引用、课程完成事实和权限 | 只建结构/种子，不自动POST | ledger或课程完成事实存在即拒绝down |
| 0047 | 登记班级学习会投影规则 | 不创建entry | 已有班会ledger entry即拒绝down |
| 0048 | plan到generic/course规则版本的显式mapping及binding引用 | 不创建entry | binding/course事实使用显式引用即拒绝down |
| 0049 | 工作日日历和每日读书/优秀分享事实结构 | 不创建entry | activity事实或相关ledger entry存在即拒绝down |
| 0064 | canonical课程规则发布、mapping、binding/课程事实冻结 | ledger delta必须为0 | 冻结引用或事实存在即拒绝down，成功生产迁移主要依赖备份恢复/前向修复 |
| 0065 | 历史workbook/row/item staging及权限 | 不含POST语句 | staging证据或历史ledger存在即拒绝down |
| 0066 | ledger时间精度、历史匹配/积分/期间审核结构 | 只补既有entry精度字段，不插入entry | 非EXACT_DATE ledger或任何staging/review证据存在即拒绝down |

MySQL与SQLite均有对应前向脚本和loss-averse down脚本。回滚脚本的“可执行”仅指空事实状态；它不是删除真实事实以回到旧schema的许可。

## 三个正式入账缺口复核

1. 小组学习会：`learning_credits.py`已实现`settle_study_meeting()`，使用ledger幂等键、冻结规则校验和正式结算开关；重复调用不重复入账。
2. 班级学习会：`class_meeting_credits.py`只暴露DRY-RUN，返回`formal_settlement_allowed=false`；API没有正式settle endpoint。
3. 每日读书/优秀分享：`learning_activity_credits.py`只生成DRY-RUN proposal，二者均返回`formal_settlement_allowed=false`；API没有正式settle endpoint。

因此后两类及班级学习会不得各自新增专用POST。正式约束已写入[统一结算批次设计](../design/2026-09-22-G5统一学分结算批次设计.md)：事实→冻结规则→DRY-RUN→统一批次→审批→POST ledger→追加冲销。

## 账本边界、幂等与冲销

- `learning_credit_entries.idempotency_key`有唯一约束；小组学习会、班会、每日读书和优秀分享均已基于稳定事实身份生成key。
- `post_credit_entry()`在写前读取同key，数据库唯一约束仍是最终防线。
- ledger保存rule version及`rule_snapshot_json`；冻结校验阻止未绑定规则进入正式POST。
- 冲销新增负向entry并设置`reversal_of_entry_id`，原entry标记REVERSED；不会以UPDATE覆盖原分值或DELETE原ledger。
- 统一结算批次未来只做编排、快照、审批、续跑和对账，不取代上述边界。

## 统一结算批次设计摘要

建议新增`learning_credit_settlement_batches`和`learning_credit_settlement_batch_items`，状态为：

```text
DRAFT -> DRY_RUN -> PENDING_APPROVAL -> APPROVED -> POSTING
POSTING -> POSTED -> CLOSED
POSTING -> PARTIAL_FAILED -> POSTING
DRAFT/DRY_RUN/PENDING_APPROVAL -> CANCELLED
```

批次保存来源、规则和结果快照；item保存成员、事实、规则、分值、blocker、稳定幂等键及ledger_entry_id。APPROVED后来源/规则指纹不可漂移；PARTIAL_FAILED只续跑未完成item；错误分只能追加reversal。详细设计见独立设计文档，本轮没有实现数据库结构或写路径。
