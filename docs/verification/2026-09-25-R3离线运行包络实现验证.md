# R3离线运行包络实现与验证

授权范围：非生产代码补齐与测试，不包含部署、环境修改或APPLY。

## 实现

新增scripts/r3_execution_envelope.py，与普通发布器隔离，不改变既有生产业务门禁。提供有类型的离线生命周期：

NEW → CREATE_PENDING → CANDIDATE → ROUTE_PENDING → READY（独立C检查点）→ APPLY_PENDING → APPLIED → RESTORE_PENDING → MANUAL_CLOSE_REQUIRED → CLOSED。

- 固定false稳定版，不允许将临时true版本作为默认或失败恢复目标。
- 创建、定向、APPLY、恢复分别最多预留一次动作；pending表示请求结果不明，禁止直接重试。
- 所有六项运行门禁必须显式存在且匹配；校验runtime commit、镜像digest、VPC、其他配置不变、双指纹、actor条件。
- 正式APPLY前独立检查授权及路由新鲜性；2次build-info、1次live、20次DB health和CLS 23/0/0是READY条件。
- 流量恢复、发布单关闭、实例退出及不可路由分别检查；不生成或猜测OperateType，不执行删除或实例启停。
- 保留true离线版本时明确输出retained_true_config=true / all_stored_flags_false=false / reactivation_authorized=false，不混淆“在线门禁关闭”和“全部历史配置false”。
- 若APPLY结果不明，关闭后仍保留UNKNOWN，不伪造成功。
