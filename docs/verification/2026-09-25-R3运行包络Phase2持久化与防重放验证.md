## 实现

### 持久化、锁与一次性预算

SQLite 保存 envelope/approval 身份、独立 APPLY approval、stable/runtime/image/VPC 与业务指纹、当前状态、candidate、路由风险、APPLY outcome、四个动作预算及创建/更新时间。

每次状态推进使用 `BEGIN IMMEDIATE`，把 `*_PENDING`、动作 reservation 和 journal payload/checksum 放在同一个事务内提交；提交成功后才返回本进程的 Fake dispatch 许可。四个动作 create/target/apply/restore 各最多一次。

`(service, operation)` 活动包络唯一索引阻止两个进程为同一服务同时创建活动 R3 包络。reservation 的 `(envelope_id, action)` 主键和事务内重读阻止重复预留；dispatch 先持久化已消费标记，再模拟成功、超时或未知结果。

重启不会恢复内存 dispatch 许可。即使 journal 显示 `dispatched=0`，也不能推断外部动作未发送并重发。人工/fixture 证据可记录成功、NOT_OCCURRED 或 UNKNOWN；未发生和未知都不退还预算。APPLY UNKNOWN 允许进入恢复和关闭，但不变成 APPLIED。

锁与去重保证限定为**同一个规范化、本地、受访问控制的 journal 文件**。不同路径、复制/回滚/删除数据库不在全局锁保证内；不能以新建 journal 绕过动作额度。checksum 检测意外损坏，不是防恶意篡改签名。空文件、缺表、版本不符、数据库损坏和锁错误均失败关闭；不自动重建丢失状态。

### 证据与独立 APPLY

提供 Service、Revision、Traffic、Release、ManageTask、Runtime、DatabaseBaseline、ApplyOutcome，以及 Approval、Actor、Backup、Provenance、PendingOutcome、Close 等 typed Evidence。

每条包含 source、observed_at、expires_at、subject、raw_fingerprint 和规范化 payload。仅接受 `fixture:r3-phase2`，核验对象身份、SHA256、新鲜度及布尔/计数类型；最大 TTL 为 300 秒。此 source 是合成夹具标签，不代表真实认证或可信外部签名。生产适配器必须后续独立评审，不能把 fixture 证据伪装为生产证据。

公共 Phase 2 `advance` 接口只收 typed evidence tuple，不收裸门禁布尔参数。Phase 1 内部纯状态机接口保持兼容，由 Phase 2 在证据校验后调用。

READY 不自动进入 APPLY。APPLY 必须有不同于 envelope approval 的独立授权 ID、有效 Actor 身份/权限、新鲜路由和 runtime 证据，以及完全一致的 production/canonical fingerprints；随后原子记录 APPLY_PENDING 和该授权 ID。

### 恢复与关闭

READY、APPLY_PENDING、APPLIED 及 ROUTE_PENDING 均可消耗一次恢复预算。恢复证据必须是 FLOW、批准 stable 100%、candidate 0%、无 URL_PARAMS，且 stable 安全开关为 false。

关闭独立于流量恢复。CloseEvidence 必须证明 candidate 身份一致、发布单关闭、任务停止、candidate 实例为 0 且不可路由、stable false gates。证据不全停在 MANUAL_CLOSE_REQUIRED。未实现或猜测 `OperateServerManage`。

关闭结果允许 `retained_true_config=true`，同时明确 `reactivation_authorized=false`、`production_ready=false`；不能据此宣称所有历史版本的存储开关均为 false。创建结果未知且 candidate 身份尚未证实时不允许虚假 CLOSED。

## 离线入口

CLI 仅提供 `--plan`、`--show-state`、`--resume-offline`。后两者仅检查既有 journal，不 dispatch、不创建遗失 journal。未提供 reset 或任何生产执行选项。

```powershell
python scripts/r3_envelope_journal.py --plan <synthetic-baseline.json> --journal <canonical-local-journal.sqlite> --envelope-id <id> --approval-id <fixture-approval> --service fixture-service
python scripts/r3_envelope_journal.py --show-state --journal <canonical-local-journal.sqlite> --envelope-id <id> --approval-id <fixture-approval>
python scripts/r3_envelope_journal.py --resume-offline --journal <canonical-local-journal.sqlite> --envelope-id <id> --approval-id <fixture-approval>
```

plan 输入为 Phase 1 Baseline 的合成 JSON。所有示例都是本地演练，不是生产批准包。
