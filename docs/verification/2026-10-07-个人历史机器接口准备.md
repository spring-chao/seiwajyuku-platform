# 个人历史机器接口准备

本次仅准备代码与隔离测试。没有启用批准范围、变更生产配置、调用生产接口、提交或发布。

## 默认状态与权限范围

新增路径为 /api/v1/integrations/participation-history/preview 和 /apply，使用现有 INTEGRATION_API_KEY 的 X-API-Key 服务身份。生产环境拒绝空配置与默认开发密钥；不新建密钥、用户或 IAM 角色。

服务端 APPROVED_IMPORT_SCOPES 当前为空，preview 与 apply 均默认拒绝。用户请求正文不能自行声明批准。后续提案只能绑定一个已冻结的包 SHA256、准确 verified_fact_count 与 UTC 截止时间；任何字节、条数或期限不符都拒绝。

现有快照接口身份不自动授权新增历史事实写入能力。启用本批范围须按[工程工作流授权表](../engineering-workflow.md#授权表)单独核验有边界的明确批准；当前代码准备不代表获准启用。

## 接受与拒绝的内容

只接受 activity_workbooks、明确匿名隐私契约及六个事实字段：source_table、external_id、member_code、occurred_on、participation_status、title。分类仅限学习会、班级学习日、小组学习会、开班、课程、其他活动；只接受 PRESENT、2025／2026 年合法且已经发生的日期、系统已存在的稳定学员编号。未知编号即使对应已有事件键也拒绝。

上传限制 20MB。其他旧运营来源、未签到事实、姓名、手机号及组织／账户／学分／规则字段不能通过该入口导入。原人工作业路由继续使用 Bearer 与 integrations:manage，原因最少八个字符及二次确认条件保持不变。机器 apply 同样要求原因及二次确认，并保留生产写入和只读部署门禁。

## 事务与一次执行

批次、事实与审计共用现有 legacy 合并事务。服务批次 created_by 与审计 actor_user_id 为 NULL；审计动作和载荷明确记录 SERVICE／INTEGRATION_API_KEY，不借用人工身份。

服务路径串行核对相同冻结包：SQLite 使用 BEGIN IMMEDIATE；MySQL 先锁定本包同一个现有学员行，再对批次执行当前锁定读取。等待锁之后重新核验期限。任何失败回滚批次、事实和审计。

该 SHA 已有 APPLIED 批次后拒绝再次 apply，即本批成功后不再具有写入能力；同 SHA 的 preview 后验仍可读取至批准期限。幂等检查与去重保持原有批次及事实键规则。
