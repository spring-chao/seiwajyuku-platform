# 入塾走访图片服务权限

用户于 2026-10-09 明确要求取消最高权限账号及服务专员保存走访图片时的额外权限门槛。本次将完整走访 PNG 导出归入既有 `enrollment:review` 入塾资料处理能力；系统管理员、运营管理员及负责入塾的专员无需额外获得 `members:enterprise_view` 或 `exports:sensitive`。

前端使用入塾处理权限显示可操作的“保存为图片”，移除三项权限组合提示。导出接口及服务端都检查入塾处理权限，沿用申请组织范围校验、走访用途及审计；授权后返回完整联系方式、企业财务和开票资料，图片不打码。没有入塾处理权限或申请超出其组织范围仍拒绝。普通详情接口沿用原字段可见性，不改全平台 IAM 角色权限，也不批量授予账号新的角色。

相关 API 30 项测试通过，覆盖系统管理员、运营专员、只有入塾查看/处理两项权限的合成角色、完整原值、组织隔离、未登录/非入塾账号拒绝、用途确认和无原始资料的审计。管理端类型检查和 23 项测试通过。浏览器用本地系统管理员和合成申请资料验证图片按钮可用及完整 PNG 下载，证据保存在工作区 `outputs/enrollment-visit-access-20261009`。

本次是用户明确授权的入塾图片功能范围调整，不执行生产数据库迁移、直接业务资料修改或 IAM 写入。生产代码发布继续要求该提交完整 CI、干净来源、受控 API 候选验证与线上版本核对，结果单独记录。
