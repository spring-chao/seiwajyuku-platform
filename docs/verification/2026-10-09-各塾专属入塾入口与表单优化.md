# 各塾专属入塾入口与表单优化

## 结果与范围

按照用户确认的设计，各塾专属码直接进入锁定目标的登记表，展示共用品牌标识和对应塾名称。移除专属表单的重复标题、填写时长及选择申请塾卡片；通用入口继续提供申请塾选择。

资料用途移至第05节重要说明；该塾联系人及服务地址置于守则简介后、详情入口前。电话由用户点击复制，仅调用 setClipboardData，不读取剪切板。联系人、费用、收款信息与完整规则继续取自对应组织配置；缺少配置时不回退到其他塾。第06节隐私确认保留。提交按钮与卡片对齐，使用酒红色、适度圆角及按下状态，未勾选两项确认时禁用，并保留服务端业务校验。

## 入口管理

- 新建不同塾入口互不停用；相同目标重复创建返回原入口，必须主动轮换才改变入口令牌。
- 管理端提供全部启用入口的选择、正式码生成与下载、单独轮换与停用。沿用 enrollment:manage_link 权限，不授予新权限。
- 正式码显式使用 release 和 check_path=true。管理端可在新浏览器会话重新下载，不需恢复原始令牌或轮换入口。
- 新码使用128位、带用途前缀的 HMAC 公共入口能力，绑定入口ID和已有令牌摘要。无需明文令牌存储；轮换或停用使旧码失效，其他塾不受影响。现有原始令牌二维码继续兼容。
- 通用首页只绑定通用入口，不随最新创建的城市专属入口切换目标；若未配置通用入口，首页不擅自选择某个城市。
- 品牌名称仅用于展示，提交归属继续使用组织ID，服务端拒绝更换专属码目标。

## 数据与恢复

无新增迁移，无生产业务数据、联系方式配置、身份权限、写入开关或密钥变更。利用既有可空 active_slot：通用入口保留唯一槽位1，专属入口使用NULL。创建入口通过已有上级组织行锁串行化；SQLite隔离测试使用即时写事务。旧版本专属入口占用槽位1时，仅释放技术槽位，不停用旧码。

管理码的签名依赖既有 JWT 服务密钥；以后密钥轮换时应重新分发这类二维码。回退旧应用会不识别新管理码；原始令牌码继续有效。若已创建多个启用入口，不应退回原全局轮换逻辑，应采用前向修复。
