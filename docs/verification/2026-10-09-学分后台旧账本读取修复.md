# 学分后台旧账本读取修复

用户反馈生产学分结算工作台弹出 `Network Error`，同时显示结算批次结构尚未就绪。两个提示属于不同查询；缺少批次表本身已有只读降级，不应通过开启结算或直接执行迁移消除提示。

源码确认管理端明细查询直接使用 0066 引入的期间字段，而小程序已有升级前精确日期账本的兼容处理。隔离旧结构中，管理端原查询因此失败。本次从原 `occurred_at` 只读投影精确日期的年、月，保持权限、组织范围、筛选及冲销关联；不写入或迁移账本。完整新结构沿用原查询；部分期间结构升级返回受控 503，避免猜测日期。

管理端错误提示标明失败区域和 HTTP 状态，网络不可达与结构未就绪分别解释。请求失败时表格明确显示读取失败，不显示为正常空记录。总览仍只在查询成功后展示数字。

本地验证：API 相关回归 26 passed / 1 skipped（MySQL 专项等待隔离 CI），首批真实角色 HTTP 验收 2 passed；管理端 19 tests passed，类型检查及 staging 构建通过。新增 MySQL 夹具以独立随机表名验证原结构 SQL，保持 CI 原表；实际远端结果以提交 CI 为准。

本次没有执行生产迁移、规则写入或调整学分门禁。浏览器连接未能取得生产失败请求日志；隔离复现不能代替线上根因确认。代码交付、生产发布和页面验收分别记录。
