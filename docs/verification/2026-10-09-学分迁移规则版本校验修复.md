# 学分迁移规则版本校验修复

0064 的课程和通用规则校验原先先按规则键关联所有规则，再关联目标版本。其他版本复用相同键时，其版本关联结果为空，触发 CHECK 拒绝，导致正确的目标策略也无法升级。隔离 SQLite 已复现此失败。

两个方言改为先解析 `STANDARD_3Y_2026 / 2026.1`，再按版本 ID 和规则键关联。目标版本数量、25 门课程、6 条通用规则、内容一致性和映射检查仍保留。旧规则不修改，不产生学分入账。新增回归覆盖旧版同键、目标课程错误、通用分值错误及目标规则缺失；MySQL CI 使用独立临时 schema 验证实际 SQL，包含升级后的旧规则不变、账本不变和失败拒绝。

这是尚未执行迁移的脚本修正；已登记 0064 的数据库仍按迁移登记跳过，不删除登记、不重跑。生产状态需通过获准的只读查询核实。本次代码交付不执行生产迁移，也不启动 bootstrap。

单项迁移入口同步绑定新的 MySQL 文件 SHA256：`92cfe506dfbd9f1c776b910823e0135017c1af0df3a05472c85d52f3a91519e7`。旧摘要的授权不能执行新文件。任何先前失败或结果不确定的运行先检查持久 DDL 和状态，不重置执行日记；修复后执行仍需要新的准确范围及备份恢复证据。

恢复方式：在执行前可撤回本代码变更；已经执行的数据库不得回跑旧脚本或破坏性降级。生产写入前准备对应备份及恢复演练，并使用现有单项入口的中断不重放约束。本地 SQLite 不替代 MySQL 或生产验收。
