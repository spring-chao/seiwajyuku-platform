# 学员编辑页志工岗位目录加载补充修复

用户反馈显示三条当前任职，但岗位选项加载失败。先前修复了共同加载失败时误清空任职展示；岗位选择的完整目录读取仍可能失败，不能把该项写成已经验收完成。

本次只读诊断在近期日志中发现 member-editor-catalog 返回 200；未获得截图对应请求的完整耗时或浏览器错误对象，因此不认定数据库损坏，也不将超时写成已证明的唯一原因。代码确定管理端请求限时 10 秒，完整目录会逐个展开服务组织，再逐岗位重复查询/校验。学员编辑页实际只消费 positions，服务组织从正式组织列表选择，新增任职由现有 API 校验并关联正式服务对象。

学员编辑页改用既有 /api/v1/volunteer-position-catalog 轻量接口，只读取岗位和能力定义，保留可选、非活动岗位筛选；完整工作台目录接口仍保留。未修改后台接口、权限、任职写入或生产数据。分区加载器将错误对象传给失败处理，页面分别显示超时、网络、登录、权限或 HTTP 状态，不显示后台 SQL、请求配置等内部信息。现有任职独立加载、失败保留和旧请求隔离继续有效。

本地管理端类型检查及 23 项测试通过。合成环境将旧完整目录设为 503，轻量接口仍返回 200，约 0.109 秒，17 个岗位定义中包含可选班主任；确认编辑页不再依赖完整目录。staging 构建及正式部署结果以本轮输出回执为准，不把生产岗位页面未核验记为通过。
