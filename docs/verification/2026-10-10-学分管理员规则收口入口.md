# 学分管理员规则收口入口

## 问题与结果

用户已经登录现有后台管理员，并要求继续修复数据库与课程规则。既有 G5.4 服务具有事务、指纹、占位项引用和身份校验，但后台没有调用入口；浏览器登录不能让外部脚本取得后台用户身份。本次新增「管理员设置 → 学分上线准备」，使用正常前端认证客户端调用既有固定 APPLY，不复制令牌、不伪造账号、不提供任意 SQL 或替代 API 主机。

新 GET `.../g5-4-course-rule-reconciliation/preflight` 在写入开关关闭时仍可读取，且要求既有专项权限、system_admin 角色和数据库中有效管理员。服务仅 SELECT，不加 FOR UPDATE，不写审计或业务表，退出时 rollback/close。展示规则语义字段、差异数量、迁移登记、绑定及账本汇总；不返回规则创建人、更新人或原始审计图像。

可执行时预览提供固定 APPLY 的完整指纹基线；已有 APPLY 服务继续在操作锁内重新验证运行提交、规则指纹、通用规则、迁移、19 个班级、账本及占位项引用。页面不会开启功能开关或执行迁移。支持受控发布的 `sj_canary` 参数及额外的 `expected_commit` 不一致拒绝；参数不是候选身份的证明，调用前仍需正式发布证据。

浏览器在发送前保存提交状态，存储失败则拒绝发送。请求失败、超时和页面重载均不会自动再次提交；成功后重新只读核验。此状态仅防止界面误重放，服务器事务及幂等逻辑仍是数据安全边界。
