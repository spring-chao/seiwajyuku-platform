# 小组学习会观看课程提交修复

## 核实结论

在 `origin/main` 的 `b81a58a` 复现代码断点：小程序确认页将观看选择写入本地 `learning_content_results`，但创建学习会仅提交小组、日期、人员。API 默认 `has_course=false`，因此课程明细为空。结果页又使用本地选择覆盖服务端返回值，造成前后端看似不一致。

截图所涉第4、6学习周期的流程配置包含明确课程映射。该结论来自源码与隔离接口验证；本任务未直接连接生产数据库、查询真实学长资料或创建真实学习会。

## 修复范围

- 小程序提交当前学习周期 ID 和各项学习内容的明确选择，并将其纳入重试指纹；跨周期不恢复旧选择。
- 服务端只从当前绑定周期的有效流程解析课程，校验周期、内容集合、重复项与布尔值；客户端不能提交学分。已完成且有课程映射的内容进入现有课程明细与参加人员完成事实。
- 保留未观看、未选择和无视频周期可正常登记的现有规则，不自行增加必学完成门禁。无课程映射的学习内容保存选择审计，但不虚构课程或学分。
- 创建审计保留选择，接口从服务端审计快照返回已保存的选择，结果页不再以本地状态制造保存成功表象。
- 同一创建人、日期、周期、名单的未提交草稿可同步改变后的观看选择，保留照片与既有课程定价快照；使用会话锁，与提交和人工修正串行。已提交记录仍禁止重复创建。
- 管理端空课程文案改为“未登记观看课程”，避免缺少数据被表述为确实未观看。

无数据库结构变化，无生产历史记录回填，无权限、学分标准或正式结算门禁变更。旧客户端没有上传的观看选择不能从周期配置推断为真实完成；历史记录须由有权限人员核实后使用既有课程修正功能处理。
