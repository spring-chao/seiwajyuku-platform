# 活动合并展示与昆山报告会参与记录修复

## 行为

- 管理端活动列表按已有活动ID汇总上午、下午、空巴扫码场次；查看明细默认显示全部场次，可切换到单一场次。保留原扫码事实、场次积分、明细导出及整活动删除的既有门禁。
- 移除数据复核待办区域、明细对话框和该页相关请求。新增分中心、班级、活动类型及日期区间筛选；分中心按组织ID及父级关系识别，不用班级名称猜测。日期过滤仍由原有服务端组织范围约束。
- 合计明确标为报名/已签到“人次”，不将多次扫码合计当成独立人数计算参会率。每场次人数与参会率仍在明细展示。
- 小程序个人参与记录按活动基础名称及日期去重，适用于班会、报告会和其他活动；去除尾部场次标记，数量、分页、分类汇总同步去重，保留实际签到源优先级。

## 昆山报告会

2026-07-19报告会有115条报名、106条已签到，签到记录未关联平台学员ID，导致个人参与记录按学员ID查询时遗漏。最小只读核实及姓名/手机号内存比对已获用户分别授权。姓名和手机号未写入聊天、日志、文件或代码。

严格“在册、姓名及手机号同时匹配且唯一”匹配78条已签到记录，其中同一学员重复报名2条，形成76条每人一次的参与事实；28条未匹配记录保持待核对。用户明确批准此76条一次性补录及仅本批次新增事实的限定恢复。

- 冻结包SHA-256：`3e576124196aa2cc08a643b9cf5879a98af431475718f25ddcbbebebd66e826b`。
- 既有机器导入接口只增加此SHA、76条及北京时间2026-10-23 23:59:59截止时间的范围；不修改通用权限或生产写入开关。
- 只新增参与事实、导入批次及审计。原签到和学分不修改，也不将参与事实补录表述为原签到学员ID已关联。
- 执行前要求目标提交完整CI、MySQL导入兼容性测试、正式接口只读预览通过。执行结果另存实际回执，不能将本验证说明视为已经生产补录。
- 异常先按SHA查询实际批次，禁止不确定结果时重放。恢复限定唯一新批次及源ID前缀、日期、数量上限，只撤回该批次新增事实，保留原批次和审计并另记录恢复审计。

## 本地验证

- 管理端类型检查、109项测试及staging构建通过。
- 相关参与历史、日期范围与导入接口测试通过；新增用例验证未关联签到的报告会通过匿名事实补录恢复个人历史，同时原签到状态、学员ID及计分资格保持不变。

- 未执行真实活动删除；小程序真机展示仍需账号本人刷新验收，不使用伪造用户令牌代验收。
