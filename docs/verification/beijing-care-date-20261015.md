# 今日关怀北京时间口径排查

## 根因与规则

用户在北京时间 2026-10-15 点击“今天”，看到 10-14 生日。今日行动采用 `datetime.now(UTC).date()`，使北京时间每日 00:00～07:59 使用前一天；完成记录的 SQL `DATE(timestamp)` 同样按 UTC 截日。

运营自然日统一为北京时间 UTC+08。审计时间继续保存 UTC；生日、入塾日期和明确的日历日期保持原日期。无时区的既有计划时间沿用业务日历语义；MySQL 无时区审计 DATETIME 沿用 UTC 存储语义。未批量修改历史记录、权限或数据库结构。历史无时区计划值保持既有墙上时间口径，不推测其原时区。

## 排查与修复范围

| 范围 | 调整 |
| --- | --- |
| 今日行动与生日七天窗口 | 默认日期、生日当天识别、登记完成窗口按北京自然日 |
| 今日已完成 | 生日、续费沟通、电话/普通关怀、企业走访及已关闭任务按北京时间归日；SQLite/MySQL 查询和 Python 二次判断一致 |
| 管理关爱健康 | 当天、逾期天数、生日未及时完成按同一日期判断 |
| 续费运营 | 默认年月、日历阶段、当月已触达、下次跟进日期判断（新录入带时区计划统一保存北京墙上时间），以及年度可信续费节奏按北京日期 |
| 月度运营汇总 | 续费状态变更按北京时间月份统计；原业务日期字段保持日历语义 |
| 运营日程与移动运营 | 今日、未来七天、逾期及移动接口 as_of/default year 按北京日期 |
| 生日资料与共同记忆 | 同行年数和默认参考日期按北京日期，生日月日与历史日期事实不改写 |
| 管理端 | 明示北京时间与今天日期；完成时间按北京时间显示；月度默认筛选、学习计划操作日期使用北京日期 |
| 页面跨日 | 每 30 秒检查日期变化，前台恢复时检查；跨日自动重载，停用页面停止计时器，组件卸载移除监听 |

保留 UTC 的用途包括审计原始时间、令牌/临时凭据/任务到期瞬间、时间戳生成及既有权限/任职有效性规则。小程序今日行动使用服务端 as_of；其记录上传的 toISOString 是 UTC 瞬间，无需转换成日历日期。独立签到部署未改动。

- 新增午夜前后、月末、年末、闰日、日期字段不偏移测试；数据库实际 SQL 截日验证同时加入 MySQL 专项 CI。
- 今日完成既有集成用例增加 UTC 前一日 16:00 与当日 15:59:59，覆盖四类动作、幂等去重与组织范围。
- 管理端 69 项行为测试通过；包含北京日期、无时区 UTC 审计时间展示、跨午夜/后台恢复只刷新一次。
