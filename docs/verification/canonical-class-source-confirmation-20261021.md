## 班级选项原因与修正

组织管理服务已有同父组织/同名班级规范选择，前端又独立按引用量去重；学习会直接列举所有 CLASS/SPECIAL_COHORT，导出也未排除停用组织。多入口采用不同规则，会让历史重复节点重新显示。新增共用目录，以同父组织 ID、类型、去空白后的名称分组，按当前关系/子组/活动引用及创建时间稳定选择有效节点。服务端先限定授权范围，再选择规范节点。组织管理、学习会筛选、学分导出与来源班级使用同一规则；导出和筛选保留同范围下相关历史节点 ID，不删除组织、学员关系或账本。不同父组织下的同名班级不合并。

已覆盖合成的有效重复、停用重复、跨分中心同名、仅授权重复节点，以及四处班级列表一致性。2026-10-21 15:32 UTC 经现有受保护的 GET /api/v1/checkin-rosters/options 核验 9 个组织范围、40 个有效 CLASS、127 个有效小组：每个父组织内有效班名均唯一；吴江为 3 个有效班级、3 个唯一班名。其他范围有效班级数：姑苏4、昆山4、苏州直属4、无锡指导团一8、指导团二8、新吴3、园区4、张家港2。名单接口读取的是组织元数据和汇总数量，不含学员明细/手机号。此结果与旧筛选未过滤停用节点的代码缺陷一致，不能把有效名册外的历史节点当作第二个在运营班级。核验未查询直接数据库，也未清理生产组织。

## 导入、预览和确认

保存来源原先采用零等待全局学分操作锁；并行操作会立即报错。现在仅来源导入有限等待 10 秒，并在释放锁前提交回执，使等待重试可命中已保存指纹。Excel 异步端点将同步检查/存储放入线程池，客户端允许较大表格处理时间。保留来源变更检测、部分读书行跳过、输入提示与幂等保护。以上为已核实的代码缺陷，不宣称覆盖未取得日志的所有生产偶发原因。

结算默认显示学习日期、人数、每人计分笔数、预计和已入账学分，内部编号不再充当业务主标题。按日期与原表可展开。确认提交携带已展示的完整结算指纹；服务端再验原始来源、范围、入账权限、实时规则和账本。直接确认只适用于合法表格来源绑定的普通批次，不伪造 approved_by/approved_at，审计明确记录 source.confirm。通用批次、历史余额及其他复核流程不改变。重复确认不重复入账；部分失败只能明确继续未完成条目，不能重新生成覆盖结果。无需新增迁移、权限或生产开关。

## 同名签到

平台根据已绑定的准确 ID、编号和有效姓名确认身份，不再要求该姓名在全部学员中唯一。普通导入仍只按姓名和手机号作身份关联。受保护的本人签到匹配可为未关联的同名报名返回 BOUND_NAME_SELF_CONFIRMATION；不同名字和已经关联其他学员的记录不覆盖。独立签到组件同步保留本人确认来源和时间，并以事务保证报名、签到和同步事实一致。

本人持有微信账号与原报名身份不是逻辑等价，产品采用显式本人确认而非标记手机号核验通过。生产验证不代用户签到、不写入真实学分。
