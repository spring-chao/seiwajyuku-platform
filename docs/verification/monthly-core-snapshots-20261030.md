# 核心数据预生成与小组读书率修正

## 行为

- 每月1日北京时间02:00生成所有已授权分中心的上月完整核心数据；03:00、04:00补漏。已就绪文件不重复生成，失败最多自动尝试3次。默认月份为上月，按钮为“导出核心数据”。
- 下载路径只读现成文件，不再当场查询学习数据、生成工作簿。其他月份或首次缺少文件时，立即创建后台任务并显示排队/生成状态，可关闭页面。页面每5秒仅查询状态，不重发生成请求。缓存下载的客户端超时为30秒，实际线上耗时必须单独核验。
- 文件使用现有私有COS存储，独立 `monthly-core/production` 前缀，无数据库迁移。元数据绑定月份、截止日、分中心、有效班级集合、是否可看中心活动和版式版本；下载重新校验账号权限和范围，并校验文件SHA256、记录审计。部分班级权限不能下载全中心文件。
- 状态更新使用COS ETag条件写入，生成文件不可覆盖；并发点击只派发一次。权限或组织范围变化时，旧任务不能发布新文件。任务租约10分钟，过期可重试；云函数单次只处理一个中心，通过固定事件续接。
- 定时器使用现有bootstrap运营账号的实时导出权限，要求具备全分中心范围；没有现有权限则拒绝运行，不授予权限、不修改身份。所有下载仍按实际访问账号核验。
- 周报的小组打卡率只受本组缺失/冲突影响。与本组无关的未匹配来源不再使全表小组均显示“待核对”；来源问题仍保留说明。有效应打卡人天和暂停、停学、免要求的原规则保留。工作簿保留COUNTIF公式及移动端预览缓存。
- 月度生成同时复用样式对象、一次读取中心小组会数据，减少生成期间的重复处理。
- 读书周报和月报不再逐行传输整个来源工作簿快照；每份导入仅在数据库端提取一次未匹配行数量，避免大JSON随打卡行重复返回造成传输放大。SQLite与MySQL使用各自原生JSON数组计数函数。

## 本地验证

- 后端相关55项通过：缓存复用、并发单次派发、权限撤销、分中心/班级隔离、文件校验、月初上月边界、定时重试上限、鉴权及现有导出与存储桥回归。
- 管理端类型检查、行为测试及staging构建通过；实际组件核验默认上月、按钮、生成时间和已生成状态。
- 云函数17项测试通过，包含私有前缀、条件签名、固定函数派发、定时隔离和原签到/学分任务不变。
- 合成500人、六张完整模板表，生成并序列化约5.24秒（不含数据库和网络）。该数字不冒充线上端到端耗时。

## 发布核验

先通过目标main提交9项CI；更新既有云函数代码，保留其环境、权限、资源和其他触发器；经受控发布器更新API；创建monthlyCoreReports定时器；通过受保护内部入口逐个补齐当前上月报表，核验完成数量和缓存下载最大耗时；最后发布管理端并比对前后端构建版本。内部核验只返回数量和耗时，不返回个人数据或工作簿内容。

版本回退使用上个稳定API和管理端入口；新增对象属于独立私有前缀，旧代码不读取它们。关闭新增定时器即可停止后续生成，不删除既有照片、学分任务或业务记录。
