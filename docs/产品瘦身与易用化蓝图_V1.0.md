# 盛和塾运营平台瘦身与易用化蓝图 V1.0

日期：2026-08-28（Asia/Shanghai）
状态：业务方向确认，待分阶段实施
基线：`main@efd1df38bd3586fbb511bddf6c7003ecff60238e`

## 1. 本次决定

平台从“继续增加发布工程层级”转向“围绕日常运营减步骤”。

生产 revision 188 继续保持稳定运行；腾讯云 `IsFreeze=yes` 的外部问题按 [R1.4.2 冻结原因处理方案](./V1.2-R1.4.2-production-database-freeze-root-cause-resolution-20260828.md) 单独处理，不阻塞本地产品整理，也不因为本蓝图执行任何生产变更。

本蓝图不是一次重构任务，不删除已有数据、API、迁移、审计或回滚能力。目标是：

> 运营人员看到的是少量清晰的业务入口；技术复杂度由后台、CI 和运维自动承担。

## 2. 长期原则

1. **业务简单，技术隐藏。** 普通运营人员不需要理解 SHA、revision、BuildId、digest、manifest、scope 或 capability。
2. **一个人一个视角。** 学员、续费、关爱、学习和志工记录围绕 `member_id` 聚合展示；底层事实表继续分离。
3. **一个事实一个来源。** 学员主档、组织关系、续费、活动签到和学习会事实继续使用各自正式数据源，不用页面拼接或估算补齐。
4. **安全不降级。** 权限、审计、备份、回滚、迁移校验和 Feature Flag 保留在后台；隐藏入口不等于取消授权校验。
5. **先改善高频动作。** 优先减少查找、切页、重复填写和技术词，不为 800 多名学长建设大规模互联网基础设施。
6. **不为整洁而破坏兼容。** 旧路由和后端 API 先保留，逐步把日常入口收口到新的业务模块。

## 3. 当前盘点（只读）

当前管理端已经有四个一级菜单，但二级页面仍按建设阶段和技术边界分散：

| 当前一级菜单 | 当前页面 |
| --- | --- |
| 运营驾驶舱 | 运营总览、月度填报、学习计划审核 |
| 学员运营 | 学员管理、新学长入塾申请、关怀跟进、续费运营、小组学习会记录 |
| 活动管理 | 活动与签到 |
| 系统设置 | 账号管理、身份与任职、班级与小组管理、学习计划配置 |

当前小程序已具备统一首页、身份绑定、新学长申请和小组学习会登记页面；绑定正式学员后已隐藏新学长申请，学习会入口由有效志工岗位和服务范围决定。现有页面和 API 是后续收口的复用底座，不需要另造一套业务系统。

## 4. 目标结构

### 4.1 学长端：四个主要入口

普通学长打开小程序只看到与当前身份有关的入口。未绑定时仍保留“绑定正式学员身份”和“新学长入塾申请”；一旦绑定有效正式学员，申请入口永久从首页隐藏。

| 入口 | 首屏内容 | 第一阶段动作 |
| --- | --- | --- |
| **我的学习** | 本月学习安排、最近活动、小组学习会、我的学分 | 查看，不新增复杂个人中心 |
| **扫码** | 扫描当前活动/学习会二维码 | 扫码、确认身份、提交；没有可用场景时给出明确提示 |
| **我的盛和塾** | 姓名、班级、小组、入塾时间、学习记录、志工记录 | 查看成长档案 |
| **我的服务** | 续费、活动报名、信息修改等服务 | 按需逐项接入，不预先堆满菜单 |

组长或辅导员进入“扫码”后，沿用现有学习会流程：自动识别身份和当前小组 → 一键选择本组成员 → 可选同班跨组学长 → 选择课程 → 提交 → 明确成功结果。合影上传作为后续增强，不改变四入口结构。

### 4.2 运营端：四个核心模块

| 目标模块 | 运营人员看到什么 | 现有页面/能力归并 |
| --- | --- | --- |
| **学员** | 一个学员的主档、班级小组、状态、续费、学习、关爱、志工记录 | 学员管理；新学长申请作为“待入塾申请”队列；身份/志工作为学员详情中的受控区块 |
| **今日行动** | 今天谁生日、谁该续费、谁最近缺席、谁需要关爱、谁刚加入、谁的信息缺失 | 运营总览的确定性行动卡；续费“今日行动”；关怀跟进待处理 |
| **活动与学习** | 活动、签到、小组学习会、课程、合影、学分 | 活动与签到；小组学习会记录；课程积分配置；学习计划作为高级配置 |
| **数据** | 在册人数、新增、续费、流失、学习参与率、班级情况 | 运营总览中的统计与趋势；月度填报/年度 MP 作为负责人可见的经营数据区 |

账号、组织主数据、岗位能力、迁移、审计、Feature Flag、构建版本和清理任务不属于日常四模块，统一放在“管理员设置”或运维后台，仅对相应角色可见。

## 6. 四类处理清单

### 6.1 必须保留

- 学员主档、`member_id`、班级/小组正式组织关系和状态。
- 新学长申请 → 审核 → 分中心 → 收款 → 正式入塾闭环。
- 续费周期、关怀记录、活动报名/签到和小组学习会事实。
- 学习会参加人员和课程的运营修正、合影短期私有保存及审计。
- 志工岗位历史、服务范围和 capability 权限判断。
- 数据库迁移记录、备份/PITR、CI、回滚和构建来源证明。
- 生产数据最小权限、敏感字段用途控制和现有写入门禁。

### 6.2 应该简化

- **运营总览**：首屏先显示今日行动，统计数据放到“数据”模块；失败模块局部提示，不阻断整页。
- **续费与关爱**：日常入口统一为“今日行动”，保留原页面处理详情，不复制新的事实表。
- **活动、签到、小组学习会**：统一到“活动与学习”，详情页内显示参加人、课程、合影和修正记录。
- **学员详情**：以学员为中心展示续费、学习、关爱和志工摘要；编辑动作按权限显示。
- **岗位维护**：日常只选“岗位 + 服务范围”，任职依据、审计和历史由系统自动记录。
- **课程积分**：已配置课程自动带出分值，新课程默认 0/待配置；运营只维护积分标准，不审核技术节点。
- **小程序**：保留四入口和身份自适应；普通学员不看到志工或入塾申请操作。
- **发布流程**：SHA、revision、digest、manifest 和迁移校验由 CI/脚本自动保存，业务人员只看“备份、测试、发布、验证、可回退”五项结果。

### 6.3 暂时隐藏（不删除）

- 原始迁移脚本、迁移 manifest、构建 provenance、镜像 digest 和发布执行细节。
- C6 异常复核、学习计划源文件浏览、流程解析诊断和 JSON 调整草稿。
- IAM 的 `role_key`、`scope_type`、`appointment_key`、组织 ID 和 capability 名称。
- 原始导入/回滚、敏感导出、审计日志检索和对象清理操作。
- 运行身份、CloudBase 存储、Cron、Feature Flag 和生产冻结处理页面。

隐藏只针对普通运营的导航和文案；后台接口仍必须进行权限校验，管理员仍可追溯和处理。

### 6.4 暂不建设（保留未来选择）

- 微服务拆分、Kubernetes、消息队列、Redis 和大数据平台。
- 永久图片相册、复杂审批流、公开排行榜和自动评价学长。
- 依赖付费第三方工商查询的企业信息自动补全。
- 第二套小程序、独立身份主键或以微信 `openid` 替代 `member_id`。
- 没有明确数据来源的预测分数、课程参与率或经营排名。

这些项目不是永久删除；只有当真实使用量和明确业务需求证明必要时才重新评估。

## 7. 推荐实施顺序

### P0：蓝图与文案（本文件）

- 固定四入口、四模块和路由映射。
- 确认哪些页面是普通运营入口，哪些属于管理员设置。
- 不改数据库、不改生产 Feature Flag、不改变 API 事实来源。

### P1：管理端入口收口

- 将侧栏标题和首页快捷入口改成“学员 / 今日行动 / 活动与学习 / 数据”。
- 保留旧路由，使用重定向或页面内标签兼容原收藏链接。
- 将“账号、组织、岗位、学习计划配置”放入管理员设置，并按现有权限显示。
- 先以静态导航和既有 API 完成，不新增 migration。

### P2：学员详情与今日行动联动

- 从今日行动卡一键进入学员详情和对应动作。
- 记录动作后刷新行动状态，不新增复制表。
- 续费、关爱和学习历史只读摘要与原页面处理保持同一事实来源。

### P3：小程序四入口收口

- 在现有首页基础上增加“我的学习 / 扫码 / 我的盛和塾 / 我的服务”外壳。
- 绑定状态、志工权限和普通学员状态继续由后端结果决定。
- 复用现有身份绑定、学习会、入塾申请 API；不新增身份主键。

### P4：使用数据驱动的后续调整

- 以实际点击次数、完成时间、错误率和运营反馈决定是否合并或隐藏页面。
- 连续观察后再考虑废弃重复入口；不因一次视觉改版直接删除旧功能。

## 8. 验收指标

### 运营端

- 登录后第一屏能直接看到“今天要做什么”。
- 两次点击内能从行动卡进入目标学员。
- 常规关爱或续费记录不超过 30 秒，且不需要理解技术字段。
- 三次点击内能从“活动与学习”打开一场学习会的参加人员、课程和合影。
- 普通运营侧栏不出现迁移、digest、scope、capability 等技术词。

### 学长端

- 未绑定：可看到“绑定正式学员身份”和“新学长入塾申请”。
- 已绑定正式学员：不再显示新学长申请；无志工权限时不显示学习会登记。
- 有志工权限：从首页到学习会提交沿用现有流程，常规场景目标 30～45 秒，有跨组和课程目标约 60 秒。
- 解绑后恢复未绑定状态；`member_id`、组织关系和历史记录不被改变。

### 安全与兼容

- 原有路由、API、数据表和审计不因导航收口删除。
- 现有权限仍由后端校验，前端隐藏不作为安全边界。
- 本蓝图实施阶段不执行生产 migration、不切换 revision、不打开 V1.2 功能开关、不创建 Cron、不写真实学习会或积分数据。
- 生产发布仍遵循“备份、测试、发布、验证、可回退”五项结果；底层 provenance 继续自动留存。
